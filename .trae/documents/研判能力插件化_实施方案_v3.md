## 1. 背景与目标

### 1.1 业务目标

1. **提高对数据的研判能力**：在现有资金筛查/五间交叉之上，新增关系研判、时间研判、多模态图像研判等手段，并使多手段产出可交叉升格。
2. **便于系统扩展**：新增一种研判手段的边际成本应趋近"一份声明 + 一个只读实现"，融合、升格、可视化、报告由平台自动承接。
3. **数据底座纯粹化**：ontology 作为整体数据底座，不绑定任何一种研判学说（包括五间）。
4. **底座契约可信化（v3 新增）**：主键与端点是所有研判、图、报告共同依赖的底座契约，必须显式声明、装载即对账，消灭"改 pk 静默重铸全库主键""图上静默少边"两类不可见故障。

### 1.2 设计原则（贯穿全文）

- **机制与词汇分离**：底座与研判内核只提供机制（对象/链接、线索契约、多源交叉、状态机），业务词汇（五间、资金视角…）全部在可插拔的研判手段包内。
- **契约先于能力（v3 新增）**：主键策略、端点方向等共享口径显式声明、装载期硬失败；任何上层镜头与表达层都消费同一份契约，不得自造口径。
- **统一事实契约**：所有研判手段产出同构的 `LineageClue`，禁止各自定义返回结构；任何"强制结论"只能写入结果对象的标记字段，不得早退或返回异构对象。
- **表达层零判据**：图与报告只消费线索与证据引用，不产生结论；每条陈述、每条高亮边可回溯到 clue_id / 语义对象 ID。
- **确定性优先、概率性隔离**：规则/图算法可复现，直接进推演；多模态输出不可复现，只能产草案（draft），人验通过才成证据。
- **门控式投资**：不为假想需求提前建平台；每个抽象必须有 ≥2 个真实使用样本后再抽取。

### 1.3 目标架构

```
L4 表达层（投影，零判据）
   GraphView 资金链路图/关系图谱（同图不同过滤） · canvas_report/sunzi-report 结构化报告
        ▲ 消费 evidence_refs（节点/边/时间区间/聚合量/书证）
L3 研判手段包（可插拔，因案而异）
   五间包（现有，降级为平级手段之一） · 关系镜头 · 时间镜头 · 图像镜头(草案通道)
        ▲ 产出统一 LineageClue
L2 研判内核（机制，无业务词汇）
   SkillSpec/skill_invoke（失败隔离/灰度） · 去重合并 · 多源交叉升格机制 · 三维评分机制
        ▲ 消费
L1 语义层  obj_* / lnk_*（编译器产物）
L0 数据底座（纯 ontology，零研判词汇；契约显式）
   objects(含 key 一等声明)/links(含 endpoints)/bindings/policies/views/data_elements/...
   装载期：key↔pk 对账 · endpoints 方向与 build_sql 输出列对账 · 自然键唯一性断言
```

## 3. 目标契约设计

### 3.1 底座契约（L0）：key 一等声明 + endpoints 对账

**（1）Object key 声明**（objects.json 每对象）

```json
"key": {
  "column":   "txn_id",        // 主键列名（= 现有 pk）
  "type":     "string",        // Palantir：主键必须 string
  "strategy": "proxy",         // proxy | natural | composite
  "prefix":   "txn",           // 仅 proxy 需要（5 个不一致前缀按现值固化）
  "properties": ["from_raw", "to_raw", "amount", "date"]
}
```

| strategy | 语义 | 现推断来源 | 键值来源 |
|---|---|---|---|
| proxy | 哈希代理键（实体/事件） | kind==event 或默认分支 | `prefix + sha1(...)[:12]` |
| natural | 自然键直通 | pk==name_property | 源列原值 |
| composite | 多属性拼接不 hash（**本期仅留 schema 位、不实现**） | 现不支持 | `col1\|col2` |

- `pk` 降为**只读别名**：key.column 存在以 key 为准，同时写 pk 且不等 → 硬失败；key 缺失回落 pk 并告警（兼容存量快照）。pk 不参与决策，故非双写源。
- **自然键唯一性装载断言**：clue/decision 源列重复即构建失败。DDL PRIMARY KEY 暂缓（先断言观察一迭代，避免 CTAS/COPY 大批量路径与存量脏数据整包失败）。
- 20 对象迁移分布：18 proxy + 2 natural（clue、decision）；5 个前缀逐对象硬编码固化。

**（2）endpoints 契约**

- 方向：`endpoints.{side}.ref.object` 必须等于 `from_obj`/`to_obj`，装载期硬失败。
- 列：物化期将 endpoints.col/extra 与 build_sql 执行后的 actual 输出列对账，缺列即硬失败（零额外查询）；此校验只能放物化期——无别名 SELECT 列无法静态提取。
- 存在性：非 runtime link 必须声明 endpoints；不入图者显式 `"graph_visible": false`，缺失即硬失败，"忘了写"与"不参与"可区分。
- 联动：`endpoints.*.ref.key` 保留（语义即引用主键列名），装载期断言 `== objects[ref.object].key.column`。
- 前端：订正 OntologyModelerView 的 pk 反向校验（与后端对齐）；ObjectCentricPanel 展示策略徽标（代理键+前缀/自然键）；ontologyObject.ts 契约补 key。

**（3）底座纯粹化**

- objects.json/links.json 删除 `jian`、`jian_source` 字段（P6 批次）；在此之前 P2 先消除双写漂移。
- ontology_loader 装载主链路最终删除 `load_jians → allowed_jian → _parse_jian` 依赖链；底座对研判包零引用，研判包引用底座对象名、引用不存在时由研判包校验报错。

### 3.3 镜头声明与统一线索契约（L2/L3 边界）

`SkillSpec` 扩展（全部带默认值，向后兼容）：

```python
consumes_objects: list[str]   # 消费的语义对象/链接类型（能力声明主口径）
produces_dims: list[str]      # 产出的评分维度标签
mode: str = "deterministic"   # deterministic | draft   ← 图像镜头用 draft
enabled: bool = True          # 单镜头开关（灰度/停用）
# —— 外设化对齐 ——
params_schema: dict = {}      # 任务声明：可接受的指挥参数 {名: {type, enum?, required?}}；空=仅被动上报
external_services: list = []  # draft 镜头依赖的外部服务标识（如 vlm:qwen-vl）；确定性镜头为空
timeout_ms: int = 0           # 外部调用超时；0=不适用（确定性镜头）
result_ttl_s: int = 0         # 产出新鲜期；超过 TTL 的线索标记"陈旧"，禁止静默沿用旧结果
```

- **任务声明**：`params_schema` 把镜头从"只可被看见"补全为"可被指挥"，参数类型/enum 装载期校验，未声明指令不得下发。
- **新鲜度**：draft 镜头必须声明 external_services/timeout_ms/result_ttl_s；断连或超 TTL 时线索标 `stale` + 缺口，不当当前结论。确定性镜头三字段恒空/0。

`LineageClue` 新增**结构化证据引用**（只加字段、不改现有字段）：

```python
evidence_refs: list[dict] = field(default_factory=list)
# 每条 ref：{"kind": "node"|"edge"|"time_window"|"aggregate"|"file",
#           "ref": "obj_org#id" | "lnk_transfers#id",
#           "time_from"/"time_to": 可选, "metric"/"value": 可选,
#           "file_uri"/"verify_status": 可选（书证/图像）}
```

- evidence_refs 引用的对象/边必须存在，且节点引用挂 §3.1 的 key 契约（P3 起校验）。
`jian_types` 字段**保留不改名**（约 20 文件消费的共享契约），填充方式改变：镜头不自报间类，由融合层按 evidence_refs 引用的源对象经五间包映射**反查注入**；五间包未安装时该字段为空，交叉升格降级为缺口展示（复用现有 `_UNMODELED` 诚实缺口范式）。

### 3.4 失败隔离与降级（P3）

- `skill_invoke` 包裹 handler：单镜头异常 → 捕获 → 返回空线索 + RunHealth 记 `skill_failed{skill_id, error}` + 结果带 `degraded` 清单；其余镜头照常。
- deterministic 镜头异常 = 降级空转（零命中诊断，REQ-G-002 复用）；draft 镜头异常 = 静默降级并明示（`fallback=deterministic_only`）。
- 红线：隔离不得吞"装载期硬失败"（声明非法、契约不符必须炸构建），只隔离运行期数据异常。

### 3.5 多模态图像镜头的"草案→人验"闸门（P8，不提前实现）

- 模型输出只生成 draft 线索（`mode=draft`），**永不直接进入生产 finding、不写语义层、不进评分融合**（沿用 shadow 语义）。
- 正兵按 verify_playbook 核验通过后，经 **ActionExecutor 唯一写路径**创建 `obj_image_evidence`（图像 URI、模型名/prompt 版本/模型分、核验人、核验结论），此后为普通语义对象，按确定性体系计分、被任意镜头消费。
- 模型置信度与规则置信度**分字段存储**，禁止混填同一 confidence。

### 3.6 镜头自枚举与镜头级授权

**（1）自枚举：上电即注册，替代手工 register**

- 启动期扫描 `packs/*/pack.json`：枚举（发现包）→注册（SkillSpec 登记、校验引用底座对象/链接存在）→挂载（进入调度目录）→可分配任务。
- 引用对象不存在、params_schema 非法在**注册期硬失败**（仅该包拒绝挂载并报明原因），不连坐；运行期异常按 §3.4 隔离。
- 兼容过渡：现有 5 内置技能由 registry_bootstrap 作为"内置包"引导，注册路径收敛到同一枚举入口。
- 目标：接入第 N 个镜头 = 放一个 pack 目录，零注册代码。

**（2）镜头级授权：接入是授权不是让渡**

- pack.json 声明可读对象/链接类型作用域；调度层查询时套 policies 遮蔽。现有 AccessContext 五出口约束使用方，本项补上能力提供方一侧最小权限。
- 第三方 draft 镜头默认最小作用域、只获脱敏数据，提升需显式申请，fail-closed。
- 凭据可单独吊销（enabled=false 或移除目录）；写操作不在镜头授权内，落证据一律经 ActionExecutor。

| P1 前缀固化错 → 全库主键变 | 高 | 5 前缀硬编码（不自动生成）；迁移前后键值逐行比对脚本进准出 |
| business_key 改名遗漏活跃路径 | 中 | 两处代码（loader `_parse_dedup_key`、etl.py）与 JSON 同批；test_dedup_key/test_m6_govern 同步 |
| P6 交叉口径漂移 | 高 | P2 后结果为基线 Golden Finding 逐线索比对；jian_types 不改名只改注入源；一次切换不留双读 |
| 失败隔离掩盖真实错误 | 中 | 只隔离运行期异常；degraded 必须产物与看板显式暴露 |
| evidence_refs 过度设计 | 中 | P3 只定最小集，P4/P5 两样本后才修订 |
| 图像通道泄漏 PII/绕过密级 | 高 | 政策先于代码；视觉模型独立白名单；默认 isolated；test 固化 |
| 模型分混入评分 | 高 | 分字段分通道；draft 不进融合；升格后只按规则计分 |
| 镜头越权读取 | 高 | pack 作用域声明、缺省最小 fail-closed；查询统一套 policies 遮蔽 |
| 断连后旧结果当当前结论 | 中 | timeout/TTL 强制声明；stale 不参与当期升格；状态进 RunHealth |
| 自枚举引入坏包 | 中 | 只解释声明、注册期校验、单包不连坐；pack 目录纳入评审不接受热写入 |
| 大爆炸重构 | 高 | 禁止跨阶段合并；每阶段独立全绿、可独立回滚 |

### 5.3 明确不做（防止范围蔓延）

- 不建 v1 设想的 `core/lens.py`/`lenses.json` 独立子系统。
- 不实现 composite 复合主键（仅留 schema 位）、不落 DDL PRIMARY KEY（断言先行）。
- 不在本批泛化评分引擎、不做多维 tag 体系（等第三种研判学说出现）。
- 不搬家式调整与解耦无关目录；不在 P6 之外重构 lineage 评分口径。
- 不让任何自动通道置"已立案"（human 专属终态红线不变）。

## 6. 业务价值与衡量指标

| 价值 | 现状基线 | 目标 | 度量方式 |
|---|---|---|---|
| 图上静默缺边 | owns/time_window/osint_mentions 永久隐形（入图边仅 7 条） | 入图边 7→10；缺边 = 0 | P0 入图边数对账；反证用例 |
| 主键契约 | split 反解；改 pk 静默重铸全库主键 | 显式 key/prefix/strategy；pk↔key 冲突硬失败 | P1 键值比对脚本；test_ontology |

| endpoints↔build_sql | 无对账 | 方向/列不一致 = 0；ref.key 与 key.column 联动 | P0/P1 校验；反证用例 |
| 新研判手段接入成本 | 改 detector/loader/前端/报告/标签多处 | 确定性新镜头 = 1 份 functions + 1 实现 + 1 个 pack 目录 | 统计 P4/P5 实际改动文件数；《镜头接入清单》 |
| 镜头挂载速度 | 手工 register | 放 pack 目录重启即枚举；单包损坏不连坐 | test_pack_enum |
| 单镜头故障爆炸半径 | 一个 handler 异常整条链失败（L339 无保护） | 仅该镜头降级，degraded 可见 | test_skill_isolation |
| 镜头越权读取 | 随系统同权 | 越权 = 0；第三方 draft 仅见脱敏数据；吊销即时生效 | 作用域测试 + 吊销演练 |
| 语义配置矛盾 | 已存在 1 处双写矛盾（transaction 生间/反间） | 构建期硬失败，生产矛盾 = 0 | P2 守卫 + P6 单源 |
| 研判覆盖面 | 资金/轨迹/登记 6 规则、五间交叉 | 关系圈层、时间碰撞、图像书证三类手段自动升格 | 同夹具线索数/独立源覆盖率对比 |
| 新手段上图/进报告 | 每手段单独接线 | 零接线自动投影（evidence_refs） | P7 后自动出现比例 100% |
| 多模态可控引入 | 无图像能力 | 草案人验 100%；模型直入生产 = 0；断网零影响 | verify 与 finding 集合对账 |

> 诚实边界：契约加固提升的是**口径可信度**（静默故障转显性），插件化提升的是**能力供给与安全迭代速度**；二者均不直接产生命中率，研判增益在多手段上线后用 Golden Finding 集与真实案件线索采纳率持续度量。

## 7. 具体例子（端到端）

### 例 1：owns 端点加固——账户持有人从隐形到可见（P0）

1. 加固前：`obj_account`（宏业建设名下账户）与持有人"李志强"之间的 owns 边因 endpoints 两端对调，在 graph_view 装配时 `continue` 跳过——正兵在关系图谱里永远看不到"谁持有这个账户"，且装载、物化、接口全程无错。
2. P0 修正 endpoints（from=account_id/ref account；to=owner_person/ref person）并通过物化对账：该边入图。
3. P4 关系镜头上线后，直接在这条可信边上算"账户→持有人→其通话人→投标公司"三跳圈层——**若不修 P0，关系镜头的第一条核心边就是断的**，这是底座加固必须前置的直接理由。

### 例 2：key 声明挡住一次主键重铸事故（P1）

1. 分析师在 OntologyModelerView 把 transaction 的 pk 从 `txn_id` 调整为 `id`（以为只是显示列改名）。
2. 旧逻辑：重建后全库交易键 `txn_3028…` → `id_3028…`，所有线索、图、报告引用全部失配，无任何提示。
3. P1 后：key 是权威声明，pk 别名与 key.column 不一致即装载硬失败；prefix=`txn` 已显式固化，必须走正式迁移并经键值比对才能改——事故在构建期被拦。
4. 同源收益：clue 源表混入重复 clue_id 时，自然键唯一性断言直接报出重复值，而不是让两条同主键线索在看板互相覆盖。

### 例 3：资金研判 → 图 → 报告（P4/P7 后，过桥账户）

1. 筛查：xu_shi R1 命中"A 公司→张某→李某"整数大额单向链。
2. evidence_refs 携带三条 lnk_transfers 边、节点 obj_org/obj_person、aggregate（合计 480 万）。
3. 融合：五间包按边源对象反查注入 jian_types=[反间]；与 call 碰撞线索（生间）合并 → 双源升格。
4. 图：资金链路图 = GraphView 以 edge_kinds=[transfers] 投影同一语义图，命中边高亮、附金额时间轴；切关系图谱看全边类型。
5. 报告：sunzi-report 凭 evidence_refs 自动生成资金链路段，可点击溯源。

### 例 4：五间语义拍板与同源修正（P2）

1. 按建议语义落锤：**流水事件=生间**（主体存活活动的自呈痕迹，与通话/轨迹同构）；**过桥派生边=反间**（利用嫌疑人资金通道反证，客体是关系而非事件）。
2. jians.json 修正：反间 source_object_types=[transfers]；生间增加 transaction。若按旧配置（transaction=反间），等于"只要调到流水就点亮反间"，交叉被数据存在性灌水。
3. P2.5 声明 transaction/transfers 同源（related_pairs）：流水与过桥边不再各计一个独立源，独立源数虚高被修正；该步改变计数结果，须 Golden Finding 比对后启用。

### 例 5：关系镜头零改融合层产生新升格（P4/P6 后）

关系镜头发现 B 公司隐性股东与中标项目分管领导为共同通话人（owns 两跳 + calls_to 共同邻居）。镜头无五间词汇；融合层反查 evidence_refs（org→因间、call→生间）自动获双间类，与资金线索交叉达三源"可立案依据候选"。**新增手段未改融合/评分/图/报告一行。**

### 例 6：时间镜头跨类型碰撞（P5）

开标前 72 小时内，同一对公账户向 3 个个人账户各转出 9.8 万、3 人轨迹点在开标地同一酒店聚集。evidence_refs 带 time_window 与 aggregate；镜头只报候选事实，"串标"定性权属正兵。

### 例 7：图像研判草案闸门与降级（P8）

1. 报销发票照片入卷，vlm 识别"8 张发票销售方同名但专用章编码不一致"，生成 draft（模型分 0.87 独立字段），页面标"AI 草案待核"。
2. 正兵比对原件确认印章伪造 → 核验动作经 ActionExecutor 创建 obj_image_evidence 并链接涉案 org；证据自动入图入报告，后续按确定性规则计分（不用 0.87）。
3. 故障演练：断网/限流 → vlm degraded、草案超 TTL 标 stale 不参与升格，其余镜头照常；镜头作用域仅含脱敏数据，读未遮蔽证件/轨迹字段被拒。

### 例 8：任务指挥与授权回收（P3/P4 后）

1. 围绕新主体"王某"：调度器按 relation 镜头 params_schema 校验后下发 `{target_subject:"王某", depth:3}`，未声明参数被拒；三跳圈层带 evidence_refs 自动上图进报告。
2. 第三方 VLM 合同到期：移除 packs/vlm（或 enabled=false）凭据立即失效，历史草案留存审计、不再调度；底座与其余镜头无变化——接入是可单方面收回的授权。

## 8. 验收与防复发机制

1. **每阶段准出**：138 组全绿（WSL venv）；MCP 改动加跑 mcp_client_test；新测试组同步注册 GROUPS。
2. **P0 前置核查**：只读核查脚本在全量包与全部存量快照上跑出待修清单，无遗漏才允许发布硬失败校验。
3. **P1 键值比对**：迁移前后全对象键值逐行比对脚本固化进测试（建议新增 test_pk_contract 组）；自然键重复注入用例。
4. **口径守卫**：P6 前后两次 Golden Finding 全量比对，交叉等级/评分/溯源行数不一致即阻断。
5. **契约守卫**：镜头返回必须为 `[LineageClue]`；非 draft 不写模型分；evidence_refs 挂 key 契约（存在性 + ref 列名）；params_schema 与下发参数双向核对。
6. **降级可观测**：degraded/skill_failed/stale 进 RunHealth 与"镜头健康度"面板（空转率、异常率、零命中率、陈旧线索数）。
7. **授权守卫**：作用域最小默认、越权测试、吊销演练纳入准出；pack 目只录经评审的包。
8. **红线回归**：已立案 human-only、写操作仅 ActionExecutor、Function 只读、LLM isolated 默认——每阶段全量回归。
9. **复盘门控**：P5 后复盘 evidence_refs、P8 后复盘接入模板与 DDL 落库时机；无第三样本不泛化。
