> 版本 v1.0 ｜ 适用 MVP-0 ~ MVP-5（26 页全量）
> 目标读者：业务测试人员 / 产品验收 / 新手上手
> 本指南采用「手把手教学」结构：每模块含 **你将完成 → 操作步骤 → 验收要点 → 常见坑**。

## 一、测试前准备

### 1.1 环境要求

| 项 | 要求 |
|---|---|
| Node.js | ≥ 20.19 |
| 包管理器 | pnpm（推荐）或 npm |
| 浏览器 | Chrome / Edge 最新版（推荐）；Firefox 可测但 SSE 重连表现略不同 |
| 后端（联调模式） | WSL Ubuntu，Python venv `/root/.venvs/inves` |
| 分辨率 | 最低 1280×720，推荐 1440×900 以上（侧栏 220px + 内容区） |

### 1.2 两种测试模式

系统支持 **MSW 离线 Mock 模式** 和 **真实后端联调模式**，根据测试目的选择：

| 模式 | 适用场景 | 启动方式 | 后端依赖 |
|---|---|---|---|
| **A. MSW 离线 Mock** | 前端独立验收、无后端时走查页面交互、红线演示 | `VITE_USE_MSW=1 pnpm dev` | 无（前端拦截所有 `/api/v1` 请求） |
| **B. 真实联调** | 端到端验证、数据真实流转、审计链落库 | `pnpm dev` + 后端服务 | 需要（API:8000 / Worker） |

#### 模式 A：MSW 离线 Mock 模式（推荐前端自测优先）

```bash
cd frontend
# Windows PowerShell
$env:VITE_USE_MSW="1"; pnpm dev
# 或 Linux/WSL bash
VITE_USE_MSW=1 pnpm dev
```

启动后浏览器打开 `http://localhost:5173`。控制台会出现 `[MSW] Mocking enabled` 字样。
Mock 数据由 `frontend/mocks/handlers.ts` 提供，覆盖登录、案件、线索、处置、审计链等核心接口。

> ⚠️ Mock 模式下**不产生真实落库**，处置/审计等写操作为前端模拟，刷新后可能重置。验证真实留痕请用模式 B。

#### 模式 B：真实后端联调模式

1. **启动后端**（WSL 环境）：
   ```bash
   wsl -u root -- bash -c "cd /mnt/d/dev/inves_duckdb && bash scripts/start_dev.sh"
   ```
   看到 `API 健康探针 OK` 即就绪，默认监听 `http://localhost:8000`。

2. **启动前端**（Windows 原生，走 Vite 代理同源）：
   ```bash
   cd frontend
   pnpm dev
   ```
   打开 `http://localhost:5173`。前端 `/api/v1/*` 经 Vite 代理到 `127.0.0.1:8000`，**无需配置 CORS**。

### 1.4 关键概念速查

- **案件（Case）**：所有业务数据的归属上下文。顶部案件选择器切换后，全页面数据随之刷新。未选案件时，业务页显示「请先选择案件」空态。
- **本体版本（pack）**：当前案件绑定的规则/模型快照，头部右侧 `本体 <pack_id> · <快照日期>` 标签展示。
- **降级态**：元数据层不可用时，页面顶部出现黄色「元数据层降级」横幅，写操作（立案/导出等）被禁用并标注原因。
- **内网涉密徽章**：头部右侧标识，提醒会话不出网。

## 二、全局基础操作

### 2.1 登录与退出

**你将完成**：用 demo 账号登录系统，验证会话有效，退出后回到登录页。

**操作步骤**：
1. 打开 `http://localhost:5173`，未登录自动跳转 `/login`。
2. 输入账号 `demo`、密码 `demo12345`，点击「登录」。
3. 登录成功进入系统，URL 回到 `/c/overview`（治理仪表盘）。
4. 点击右上角头像 → 「退出登录」。

**验收要点**：
- ✅ 登录成功后头部右上角显示用户名 `demo`。
- ✅ 密码错误时提示统一文案（不泄露「账号存在/密码错误」等双因子状态差异）。
- ✅ 退出后回到 `/login`，无法通过浏览器后退访问业务页（会话已清除）。
- ✅ Token 存于 sessionStorage，**localStorage 无 `sunzi.*` 键**（红线：敏感数据不落本地持久化）。

**常见坑**：
- Mock 模式登录失败 → 检查控制台是否有 `[MSW]` 字样，确认 `VITE_USE_MSW=1` 已生效。
- 联调模式登录 500 → 检查后端 `logs/api.log`，确认 Worker 已启动。

### 2.2 案件切换

**你将完成**：在头部案件选择器中切换案件，验证页面数据联动刷新。

**操作步骤**：
1. 登录后点击左上角案件选择器下拉框。
2. 选择一个案件（如 `reqd_case` 或其他已存在案件）。
3. 观察右侧 `本体` 标签更新为该案件的 pack 快照。
4. 切换到「全部案件」（空值），业务页显示空态。

**验收要点**：
- ✅ 切换案件后仪表盘/线索列表等数据自动刷新，无需手动刷新页面。
- ✅ 选择「全部案件」时，线索详情等按案件归属的页面显示「请先选择案件」。
- ✅ 案件选择只写入 sessionStorage，关闭浏览器标签后丢失（不持久化）。

### 2.3 导航与布局

**你将完成**：通过左侧六分组导航切换页面，验证侧栏折叠/展开。

**操作步骤**：

**验收要点**：
- ✅ 所有侧栏菜单项均可点击并跳转对应页面，无 404。
- ✅ 侧栏折叠后菜单项变为图标，悬停显示文字提示。
- ✅ 页面顶部全局条五元素齐全：案件选择器 / 本体版本标签 / 任务图标 / 设置图标 / 用户头像。

### 2.4 全局检索（交互壳）

**你将完成**：在头部中部搜索框输入关键词，验证可输入/清除。

**操作步骤**：
1. 点击头部中部搜索框，输入任意文字（如 `测试`）。
2. 点击搜索框右侧 × 按钮清空。

**验收要点**：
- ✅ 可正常输入和清除。
- ✅ 当前为交互壳，检索结果页随后续迭代落地，输入不触发实际检索（不报错即可）。

### 2.5 降级态识别

**你将完成**：识别降级横幅，理解降级态下的能力限制。

**操作步骤**：
1. 登录后观察页面顶部是否出现黄色「元数据层降级」横幅。
2. （联调模式）可尝试停掉后端 Worker 后刷新，观察降级态。

**验收要点**：
- ✅ 降级横幅出现时，头部本体标签旁显示 `元数据层降级` 黄色标签。
- ✅ 降级态下，立案、导出等写操作按钮**渲染但禁用**，并标注「降级」原因。
- ✅ 降级态不影响只读浏览（线索列表、详情等仍可查看）。

## 三、分模块测试指引

### 3.1 研判中心

#### 3.1.1 治理仪表盘（`/c/overview`）

**你将完成**：查看案件健康度、线索统计、五间雷达、高优先级线索列表。

**操作步骤**：
1. 登录后默认进入此页（需先选择案件）。
2. 查看顶部健康度横幅：根据诊断总数和严重等级显示不同语义。
3. 查看指标卡片区：待办处置按状态分组、诊断按严重等级分组。
4. 查看五间雷达图：按线索的 `dimension` 通道聚合命中数。
5. 查看高优先级线索列表（按 `priority_rank` 取前 8 条），点击线索进入详情。

**验收要点**：
- ✅ 零诊断记录时，健康度横幅为 **warn 语义**，**不显示「一切正常」**（红线：禁止零记录报正常）。
- ✅ 有 warning 诊断 → 显示「降级」；有 critical → 显示「严重」。
- ✅ 五间雷达图正常渲染，各通道数值与线索列表中 `dimension` 字段一致。
- ✅ 点击高优先级线索跳转到 `/c/clue/:clueId`。

**常见坑**：
- 仪表盘空白 → 未选择案件，先在头部选择一个案件。
- 健康度永远正常 → 后端未产出诊断数据，非前端问题。

#### 3.1.2 线索列表（`/c/clues`）

**你将完成**：分页浏览线索列表，使用 `?page=N` 分享 URL。

**操作步骤**：
1. 侧栏点击「线索列表」。
2. 浏览表格，每页 50 条（`page_size=50`）。
3. 点击底部分页器切换页码，或在跳页输入框输入页码跳转。
4. 复制浏览器地址栏 URL（含 `?page=N`），在新标签页打开，验证分页参数生效。
5. 点击某条线索进入详情。

**验收要点**：
- ✅ 分页表格可用，每页显示 50 条。
- ✅ `?page=3` 这类 URL 可分享，新标签页打开直接落在第 3 页。
- ✅ 当数据只有 1 页时，手动输入 `?page=2` 会自动回退到第 1 页（不显示空列表）。
- ✅ 跳页输入框可用，输入非法值（如 0、超大数）自动夹紧到有效范围。

#### 3.1.3 线索详情（`/c/clue/:clueId`）—— MVP-1 闭环核心

**你将完成**：查看三栏证据、打开溯源抽屉、执行处置动作、验证审计留痕。

**操作步骤**：
1. 从仪表盘或线索列表点击一条线索进入详情。
2. 查看三栏证据布局：
   - **事实栏**（青色）：已确认的事实项。
   - **推断栏**（琥珀色）：基于事实的推断。
   - **待核实栏**（灰色虚线）：尚未核实的信息。
3. 点击「溯源 →」按钮，右侧抽屉打开，显示每行数据的 `row_uri`，命中字段琥珀高亮。
4. 在处置状态机区域执行动作（如「查证中 → 已固证」），弹出确认对话框，填写备注/理由后提交。
5. 提交后看到「处置请求已入队」提示，状态刷新。
6. 打开「审计链」页面，验证刚才的操作记录。

**验收要点（核心红线，逐条核对）**：
- ✅ **推断栏配色为琥珀色，绝不出现绿色**（红线：推断禁绿，避免暗示已证实）。
- ✅ **无 `source_rows` 溯源的推断项不渲染**（红线：无溯源推断拒绝展示，前端丢弃并计数）。
- ✅ 三栏严格分隔，推断不混入事实栏。
- ✅ 溯源抽屉中 `row_uri` 可复制，命中字段琥珀色高亮。
- ✅ 处置动作走状态机：`查证中` 可执行「固证/排除/退回」；`已固证` 可执行「立案/排除」。
- ✅ **`已立案` 为终态**，无任何可执行动作按钮。
- ✅ **立案四重门禁**：机器角色（system/ai/agent）→ 按钮不渲染；非「已固证」→ 渲染但禁用（提示需先固证）；法定依据为空 → 禁用（提示需法定依据）；降级态 → 禁用（提示降级）。
- ✅ 越权访问线索（如正兵角色访问内间线索）→ 返回 404，不暴露线索存在性。

**常见坑**：
- 处置后状态没立即变 → DISPOSE 是异步任务（202 已入队），状态在 Worker 完成后更新，可去任务中心查看进度。
- 溯源抽屉为空 → 该线索确实无溯源数据（`source_rows` 为空），属正常。

### 3.2 数据接入

## 五、常见问题排查链路

### 5.1 启动问题

| 现象 | 排查顺序 |
|---|---|
| `pnpm dev` 报端口占用 | 1. 检查 5173 端口是否被占用；2. `vite.config.ts` 改 `server.port`；3. 关闭占用进程后重试 |
| MSW 模式无 Mock 效果 | 1. 确认启动命令含 `VITE_USE_MSW=1`；2. 控制台是否有 `[MSW]` 日志；3. 清除浏览器缓存后重试 |
| 联调模式接口 404 | 1. 后端是否启动（`curl http://localhost:8000/api/v1/health`）；2. Vite 代理是否指向 `127.0.0.1:8000`；3. 检查 `logs/api.log` |
| 联调模式 CORS 报错 | 1. 前端必须经 Vite 代理（`localhost:5173`），不可直连 `localhost:8000`；2. 代理配置见 `vite.config.ts` |

### 5.2 登录问题

| 现象 | 排查顺序 |
|---|---|
| 登录提示统一错误文案 | 正常行为（不泄露双因子状态），确认账号密码是否正确 |
| 登录后白屏 | 1. 控制台是否有 JS 报错；2. `auth/me` 接口是否返回 200；3. 清除 sessionStorage 后重试 |
| 登录后又跳回登录页 | 1. Token 是否存于 sessionStorage；2. 401 钩子是否触发；3. 后端 token 是否过期（12 小时 TTL） |

### 5.3 数据/接口问题

| 现象 | 排查顺序 |
|---|---|
| 业务页显示「请先选择案件」 | 1. 顶部案件选择器是否选中案件；2. 选「全部案件」会触发此空态 |
| 线索列表/仪表盘空数据 | 1. 案件下是否有数据；2. 后端接口是否返回 200 且 `items` 非空；3. Mock 模式下 handlers 是否有该案件数据 |
| 处置后状态不变 | 1. DISPOSE 是异步任务，去任务中心看进度；2. Worker 是否运行；3. `logs/worker.log` 排查 |
| CSV 上传列映射异常 | 1. 确认使用最新代码（已支持分隔符自动嗅探）；2. 检查 CSV 是否带 BOM（已兼容 `utf-8-sig`） |

### 5.4 降级态问题

| 现象 | 排查顺序 |
|---|---|
| 顶部出现「元数据层降级」 | 1. 元数据层（DuckDB）是否可用；2. 健康探针是否返回降级标志；3. 非阻断，只读功能仍可用 |
| 降级态下按钮点不动 | 正常行为：降级态写操作禁用，恢复元数据层后自动解除 |

### 5.5 审计链问题

| 现象 | 排查顺序 |
|---|---|
| 操作后审计链无记录 | 1. 写操作是否成功（任务中心查看）；2. 审计链是否刷新；3. Mock 模式下审计为前端模拟，刷新可能丢失 |
| 审计链显示断链 | 1. 查看断链数量与明细；2. 属数据完整性问题，非前端 bug，反馈后端排查 |
