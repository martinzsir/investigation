### 决策 6：长列表方案改为分页

**推翻原虚拟滚动方案**，理由：

1. **后端本就是分页契约** —— 列表端点 `?page=&page_size=`，虚拟滚动与后端设计错位
2. **09 处置看板不需要** —— 原型是五列卡片队列，每列 ≤24 张卡，不是长表格
3. **Ctrl+F 可用** —— 虚拟滚动未渲染的行，浏览器原生搜索找不到
4. **URL 可分享** —— `?page=3` 能直接发给同事（协查场景实用）
5. **成本低** —— 分页 ≈1 人日 vs 虚拟滚动 ≈5 人日

**唯一例外：05 实体裁决** —— 键盘流 A/R/D 连续裁决，分页会打断操作。改用**无限加载**（滚到底自动加载下一批，键盘流不中断）。

**`page_size` 上限确认为 50**（决策 8；审计端点后端允许到 200，前端统一仍按 50）：

| 场景 | 方案 |
|---|---|
| 05 实体裁决 | **无限加载**（候选常数百条，50/页需翻 10+ 次，键盘流不能断） |
| 06 审计链 / 22 隔离区 / 24 任务历史 | 分页 50/页 + 跳转输入框（累积数据量大） |
| 其余列表 | 分页 50/页 |

### 决策 11：SSE 事件字段（v1.7 按代码订正）

SSE 事件体为任务对象直出（`asdict(TaskRow)`），事件名三类：`progress` / `terminal` / `error`。

```ts
interface TaskEvent {
  status: 'PENDING'|'RUNNING'|'SUCCEEDED'|'FAILED'|'CANCELLED'
  progress_pct: number | null      // 0–100
  progress_stage: string | null    // 阶段标识，如 "实体对齐"
  progress_label: string | null    // 阶段文案，如 "阶段 4/10"
  progress_detail: object | null   // 明细，如 { "已处理": 1203, "待确认": 6 }
  error_code: string | null
  error_message: string | null
}
```

**前端渲染映射**：

| 字段 | 渲染位置 | 组件 |
|---|---|---|
| `progress_pct` | 进度条 | `FE-C-007 TaskProgressCard` |
| `progress_label` | 阶段文案（进度条下方） | 同上 |
| `progress_stage` | 当前阶段名（可展开区标题） | 同上 |
| `progress_detail` | 展开后的明细键值对 | 同上 |

**边界情况约定**：

| 情况 | 前端处理 |
|---|---|
| `progress_pct` 缺失或 >100 | 显示"计算中"，进度条走 indeterminate 态 |
| `progress_label` 为空 | 只显示 `progress_stage` |
| `progress_detail` 为空 | 不渲染展开区 |
| 重连后收到历史事件 | 按 SSE `id:`（Last-Event-ID）去重，**进度只增不减** |
| 收到 `terminal` 且 status=FAILED | 显示 `error_code` + `error_message`，重试受 max_retries=2 约束 |

### 决策 15：双端访问层 —— HttpTransport 抽象 + Electron IPC 桥（v1.8 新增）

吸收 api_access_layer_plan D6/D9。访问层是 UI 与后端之间**唯一出口**，两种运行形态共用同一套接口：

| 形态 | transport 实现 | token 位置 | 说明 |
|---|---|---|---|
| Web（私有化主力） | `fetch.transport.ts`（fetch + ReadableStream SSE） | 内存（Pinia）+ sessionStorage | 同源 `/api/v1`，无 CORS |
| Electron 瘦客户端（后期立壳） | `ipc.transport.ts`（`window.sunzi.*` 薄封装） | **仅 main 进程 safeStorage 加密**；renderer 不持 token、不发 HTTP | CSP 最严（renderer 无 connect-src）；base URL 由设置页配置 |

纪律：
1. **业务代码零 `if (isElectron)`** —— 启动时按 `window.sunzi` 是否存在选择 transport 实现，之后全链路无平台分支；
2. Electron 立壳时 **renderer 代码零改动**，仅替换 transport（因此接口必须在批次 0 就定好，后期补接口等于重构）；
3. Electron 上传走 IPC 传**文件路径**由 main 流式发送（涉密大文件不进 renderer 内存）；下载由 main 流式落盘 + 保存对话框；Web 端上传 FormData、下载 fetch blob → objectURL；
4. CORS 默认关闭，仅 dev server 经 `SUNZI_CORS_ORIGINS` 白名单临时放行，**不进生产构建**；
5. Electron sidecar（本机起 python 服务）为可选后期项，访问层零特判，仅 base URL 变化 + health 探针等待就绪。

### 决策 16：data_version 版本失效闭环（v1.8 新增）

吸收 api_access_layer_plan §6.3 版本闭环 + ui_v1.3 §4.3 任务五阶段版本化行为：

```
读响应信封 {ok, data, data_version}
   → data_version 写入 TanStack Query 缓存标签（query key 组成部分）
SSE terminal（BUILD/RESCAN/IMPORT 成功，响应含新 data_version）
   → 该案件相关 Query 全部 invalidate → 自动重取新版本数据
```

- 任务进行中：版本标签显**旧版本号**，页面数据保持旧快照（不半新半旧）；
- 任务完成：Toast"数据已更新（vN → vN+1）"，点击或自动刷新；失败则旧数据不动；
- 切案件：清空当前案件 Query 缓存；登出：全清；数据元/偏好等跨案件缓存不受案件失效影响（query key 不含 cid 的不失效）。

### 错误码映射表（FE-I-005 明细，决策 13 按代码订正）

| 错误码（envelope.py 实际） | HTTP | 前端处理 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 未认证/会话超时 → 清会话跳 `/login`，保留来源路径；**登录失败同码，统一文案"账号或密码错误"，不区分账号/密码/双因子，不提示账号是否存在**（红线八） |
| `FORBIDDEN` | 403 | 角色/密级/租户/membership 拒绝（fail-closed）：按权限渲染，本就不该看到入口；跨案件部分授权时按响应 detail 显示 N/M 有权案件数 + 锁执行按钮；operator 不一致同码 |
| `NOT_FOUND` | 404 | 统一「不存在或无权访问」（跨租户探测同样 404，不返回 403，防存在性泄漏） |
| `VALIDATION` | 400 | 参数/表单错误，定位到字段；声明类校验失败（422 语义）展示后端返回的定位信息 |
| `CONFLICT` | 409 | 幂等键命中 → 跳转既有 task，不重复提交；状态机非法迁移/降级写拒绝按下条细分 |
| `DEGRADED_WRITE_REJECTED` | 409 | 提示降级原因，禁用导出/立案（FE-T-010） |
| `INTERNAL` | 500 | 异常态（StateSwitch Error）+ 重试出口；元数据层不可用（503 语义）明示"系统暂不可用"，不静默降级 |
