## 一、排序方法

### 1.1 两层排序规则

1. **第一层：拓扑依赖** —— 分 T0–T10 共 11 层，上层不完成，下层无法开工
2. **第二层：层内难度升序** —— 同层内先做简单的（快速见效），再做复杂的

### 1.2 难度与工时定义

| 级别 | 含义 | 工时 | 典型特征 |
|---|---|---|---|
| **XS** | 极简 | 0.5 人日 | 纯配置、无逻辑 |
| **S** | 简单 | 1 人日 | 单文件、无外部依赖 |
| **M** | 中等 | 2–3 人日 | 多状态、需联调 |
| **L** | 复杂 | 4–5 人日 | 状态机、图表、跨域交互 |
| **XL** | 极复杂 | 6–8 人日 | 多端点协同、复杂状态同步 |

### 1.3 关键路径

```
FE-I-001 镜像 → FE-I-004 request → FE-D-001 Token → FE-D-002 主题
   → FE-C-001 StatusBadge → FE-C-014 状态机★ → FE-C-024 AppShell
   → FE-P-001 仪表盘 → FE-P-004 线索详情
```

**关键路径 ≈ 23 人日**（不含并行压缩）。这是最短可能工期。
