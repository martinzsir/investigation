### 1.2 明确不借鉴（红线与不匹配项）

- **不照搬配色**：截图为蓝紫扁平风；本系统沿用 [tokens.ts](file:///d:/dev/inves_duckdb/frontend/src/design/tokens.ts) 深色青金体系（`#030A14/#051522` 底、青 `#6EDEE9`、金 `#F2B54D`、语义三档色），新组件**只消费 CSS 变量**，不引入硬编码色值（FE-D-011）。
- **不引入立方动态对象（kind:"cube"）**：司法侦查消费形态是线索/报告而非 OLAP 立方；左栏分组**预留分组位但本期不建类型**，避免牵动 objects schema 与编译器。
- **不做 AI 直写画布/批量入库**：所有 AI 产出先进变更清单，逐项勾选后走 `POST /ontology/proposals` 既有人审提案流；LLM 默认 isolated 关闭，离线 503 降级（与规则工坊同口径）。
- **不做"生成工作流/发布智能体/流式数据接入/业务-画布双模式"**：与单机离线内核定位不符。
- **不动 AppShell 侧栏导航、不动八段声明语义、不动保存三级 diff 红线**。

## 二、不可改 / 可改清单

### 不可改（经验：布局改造先锁边界）

1. `AppShell.vue` / `SideNav.vue` / 全局 tokens 与 CSS 变量定义（只允许新增组件内消费，不改既有变量值）。
2. S2 保存流：`buildDiff()` 三级分类（structural/relational/semantic）、`SaveConfirmModal`、CONFLICT 恢复、R1 名称置灰、R2 未知字段透传、R3 事实文案——**只在其外加入口，不改其判定**。
3. `ModelDesignerView.vue` JSON 编辑入口保留并存（顶部 hint-bar 保留）。
4. 后端八段装载纪律：新端点只读声明、只读 DuckDB；不新写 SQL 模板 Function；写操作仍只经 ActionExecutor / 提案 publish。
5. 权限：建模器写操作维持 `canWriteConfig(auth.clearance)`（偏将及以上 + ontology_admin）；新端点复用 `get_principal` + `_get_owned_case`。

### 可改/可新增

- S2 页面内部布局：topbar 扩展、左栏分组搜索、中栏加 chip 栏、右栏加 tab、AI 抽屉（页面级，不影响外壳）。
- 新增前端组件目录 `frontend/src/components/om/` 下的新文件。
- 新增 3 个只读聚合端点（facets / checks / versions）+ 1 个血缘装配端点；均为只读，不改声明文件。

### A2. 对象要素 chip 栏（核心）

**位置**：中栏 `.pane-title` 与元信息折叠区之间，新增 `ObjectFacetChips.vue`。

**chip 集合**（对照截图1，命名按本系统术语）：

| chip | 计数口径（后端 facets 返回，前端不自行扫文件） | 点击行为 v1 |
|---|---|---|
| 关系 | links 中 from_obj/to_obj = 本对象的活动 link 数 | 右栏切「关系图」并聚焦本对象（已有 select） |
| 数据源 | bindings.object_bindings 中 object 匹配数（source/source_sql 均计 1，optional 标 ◇） | 打开 ETL 页并定位（路由 `/c/etl?object=x`，批次 A 可仅跳页；高亮归 A 尾部 0.3 人日） |
| 属性 | properties 键数（含新增未提交） | 锚点滚到 ptable |
| 指标函数 | functions.json 中 inputs/params 引用 `obj_<name>` 的函数 | 右栏抽屉列出函数名+用途（只读，跳函数页） |
| 派生 | derived_properties 中 name 前缀 `<name>.` | 抽屉列派生属性（跳通用配置页） |
| 行动 | actions.json 中引用本对象的动作（引用扫描，**宁多报**口径同 S5 impact） | 跳行动页并过滤 |
| 权限 | policies.json 对象级策略命中数（含 fail-closed 未声明警告态：无策略时 chip 显示 ⚠） | 跳权限与遮蔽页 |
| 视图 | views.json 声明引用本对象的视图数 | 抽屉列视图 |
| 规则 | rules.json 中 function 链路上引用本对象的规则（经 functions 反查） | 跳规则工坊并过滤 |

未提交改动时 chip 计数随工作副本实时重算（关系/属性走本地；其余要素提示「以已保存声明计」——chip 组末尾统一小字标注，不做假实时）。

**视觉**：复用 NTag `size="tiny" :bordered="false"`，0 值 chip 降透明度置灰；⚠ 态用 warn 色；沿用 `.mono` 显示英文键名。不引入截图的紫色。

**文件**：新增 [components/om/ObjectFacetChips.vue](file:///d:/dev/inves_duckdb/frontend/src/components/om/ObjectFacetChips.vue)（约 180 行）；改 OntologyModelerView 挂载；新增前端 API `ontologyFacetsApi`。**1 人日**（含联调）。

## 六、批次 C：AI 变更清单抽屉（P3，约 2.5 人日，受 LLM 开关门控）

### C1. 交互（严格对齐截图1「改动先入清单、逐项勾选写入」）

- 留痕：提案摘要标注「来源：AI 辅助」；审计链现有机制自动覆盖。

### C2. 范围限制（v1）

## 七、新增 API 契约汇总

| 方法 | 路径 | 批次 | 说明 | 复用 |
|---|---|---|---|---|
| GET | `/cases/{cid}/ontology/facets` | A | 返回每对象的要素计数（一次请求全对象，前端按选中取）：`{pack, objects:{name:{links,binds,props,functions,derived,actions,policies,views,rules, bind_optional, policy_declared:bool}}}` | load_pack + 声明引用扫描（impact 同口径） |
| GET | `/cases/{cid}/ontology/checks` | A | `{summary:{error,warn,pass}, checks:[{id,level,title,detail,target?}]}` | load_pack/文件扫描/DataMap/`_materialized_tables`/proposal store |
| GET | `/cases/{cid}/ontology/versions` | B | `[{version,current,created_at,summary,operator,stats:{objects,links}}]` | artifacts/build_stats_vN + meta 指针 + 审计链 |
| GET | `/cases/{cid}/ontology/fabric-lineage?object=<name>` | B | `{nodes,edges}` 五层子图 | 八段声明只读装配（新 `ontology_fabric.py`） |
| POST | `/cases/{cid}/ontology/ai-suggest` | C | 入参 object + intent；出结构化建议项；守卫生效时 503 | LLM guard + llm_policy |

## 九、排期与风险

| 批次 | 人日 | 价值 | 依赖 |
|---|---|---|---|
| A 要素整合 | 3.5 | 直接消除「19 文件分散感」，80% 体验收益 | 无新基础设施 |
| B 版本+血缘 | 4 | 设计缺口可视、版本可回溯 | A 的 facets/抽屉骨架 |
| C AI 清单 | 2.5 | 截图最吸睛但本系统收益最低、门控最多 | A + 案件包开 LLM |

风险与对策：
1. **facets 引用扫描误报**（functions/actions 对对象的引用是文本级）→ 沿用 S5「宁多报」并在 chip tooltip 标注「按声明引用计」；后续若函数声明显式化 endpoint 再收紧。
2. **血缘全图过大** → v1 强制单对象子图；超出阈值（节点 >200）只显示前三层并提示。
3. **G6 双图维护成本** → FabricLineagePanel 与 RelationGraphPanel 抽公共 `useG6Canvas` 小 composable（批次 B 内顺手，约 0.3 人日），不提前抽象。
4. **版本语义混淆**（保存 ≠ BUILD 版本）→ 顶栏胶囊与抽屉文案明确区分「声明版本（快照）/分析版本（BUILD vN）」，两处时间线不混用。
5. Windows/WSL 差异：本方案不触 DuckDB 扩展与新依赖（G6 已装、naive-ui 已装），无 Ladybug 类环境风险。
