## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 五间与本体能解耦吗？ | **能**，且对象级**已经是声明驱动的** |

## 1. 决定性发现：五维已经走通了这条路

`dimensions.json` 的注释（REQ-G-011）写得非常明确：

> "DIMENSIONS **不再硬编码于 core/hypotheses.py**，改由本文件声明；
> rules.json 规则的 dimension 必须是此处已声明的 name（**装载期交叉校验，未声明硬失败**）。
> **新增维度不改 Python 即可被规则引用并参与覆盖度。**"

且 `ontology_loader.py` 有完整校验（缺 name / 重复 / 为空全部 `raise ValueError`）。

### 1.1 这就是五间改造的现成模板

**不是"能不能做"，而是"照着再做一遍"。**

### 1.2 ⚠️ 但有个教训：五维迁移没做干净

```python
# core/hypotheses.py:67 —— 残留硬编码
DIMENSIONS = ["资金", "通讯", "行为", "关系", "时间"]
```

声明已外置，代码里仍留一份。**改造五间时必须避免同样的错误**——迁移要彻底，不留双源。

## 2. 现状：耦合是分层的

| 层 | 状态 | 证据 |
|---|---|---|
| **对象 → 间类归属** | ✅ **已是声明** | `objects.json` 的 `jian` 字段（transaction=生间、tipoff=内间、org=死间…） |
| **间类集合本身** | ❌ **硬编码 ×3，顺序还不一致** | 见 §2.1 |
| **交叉等级规则** | ❌ 硬编码 | `functions.py:291`，注释明写"红线：等级规则硬编码，不读配置" |
| **间类校验枚举** | ❌ 硬编码 | `ontology_loader.py:47` `ALLOWED_JIAN` |
| **权限过滤** | ❌ 职责越界 | `hypotheses_view.py:29` `_NEIJIAN = "内间"` |

### 2.1 三处硬编码（顺序不一致，是隐患）

```python
core/functions.py:246       _JIAN_ORDER = ["因间","内间","反间","死间","生间"]
core/hypotheses.py:69       JIAN_ALL    = ["生间","反间","因间","死间","内间"]
server/app/hypotheses_view.py:30  _JIANS  = ["因","内","反","死","生"]   # 单字版本
```

**三份定义、三种顺序、两种粒度**——这是典型的隐式耦合，改一处必漏两处。

### 2.2 交叉规则现状

```python
# core/functions.py:291
level = "可立案依据候选" if n >= 3 else ("线索" if n == 2 else "观察")
```

注释明确写着 `# 红线：等级规则硬编码，不读配置`——**这是刻意的**，见 §5.2。

### 2.3 权限耦合（职责越界）

```python
# server/app/hypotheses_view.py:29
_NEIJIAN = "内间"   # 内间线索按密级过滤
```

**把"权限"绑死在"间类"上**。而系统本就有 `policies.json` 做这件事——明显的职责越界。

---

## 3. 关键洞察：五间承担了三个不该混在一起的职责

**这是本次评估最重要的发现**：

| 职责 | 现在由"间"承担 | 应该归谁 |
|---|---|---|
| **数据来源分类** | 五间（工商/举报/通讯/公开/资金） | 可配置的标签体系 |
| **证据独立性判定** | 五间（交叉=独立） | **独立的相关性声明** |
| **权限过滤** | `_NEIJIAN = "内间"` | 已有 `policies.json` |

**拆开之后，五间就变成一个"默认配置"，而非架构约束**——平台自然适用于别的场景。

---

## 4. 动态组合：能做，但边界要清楚

### 4.1 可配置 vs 不可配置

| ✅ 可配置 | ❌ 不可配置（红线） |
|---|---|
| 间类名称、数量（不同领域叫法不同） | **单源不得升格到"可立案"级别** |
| 哪些对象/源归属哪个间 | 独立性判定必须存在 |
| 等级名称（观察/线索/候选 → 可改名） | 交叉必须基于**独立源** |
| 组合表达式（A+B 意味着什么） | 底线阈值**只许往严配** |

### 4.2 为什么红线不能配

`functions.py:245` 注释："红线：等级规则硬编码，不读配置"。

理由：**等级规则本身就是防误报的底线，可配置就等于可绕过。**

> 所以正确做法是：**结构与名称可配，独立性判定与底线阈值不配**（或只允许往严配）。

---

## 5. 真正的解耦红利：源相关性 ⭐

### 5.1 当前模型的盲区

讨论选股时提过的关键问题：研报互抄、新闻同源转载、舆情互相引用——
**"两个源"其实是"一个源"，硬套五间会系统性高估置信度。**

**现在的五间模型无法表达"这两个源相关"。**

### 5.2 解耦后自然解决

一旦把独立性从间类里剥离，变成独立的**源相关性声明**：

```jsonc
{
  "source_independence": {
    "default": "independent",
    "_note": "未声明视为独立；显式声明相关的源对在交叉计数时合并计为 1",
    "related_pairs": [
      { "a": "公开OSINT", "b": "舆情监测",
        "relation": "同源转载", "count_as": 1 },
      { "a": "研报A", "b": "研报B",
        "relation": "同一机构发布", "count_as": 1 }
    ]
  }
}
```

**这比"换个领域能用"更有实际价值**——它直接提升当前场景的准确性。

## 6. 实施方案：四阶段

### 阶段 A：声明化（照搬五维，约 1–2 人日）

#### A-1 新增 `jians.json`

**结构完全对齐 `dimensions.json`**：

```jsonc
{
  "schema_version": 2,
  "_note": "REQ-G-0XX 用间维度声明。JIAN 不再硬编码于 core/functions.py，"
           "改由本文件声明；rules.json 的 jian_types 必须是此处已声明的 name"
           "（装载期交叉校验，未声明硬失败）。新增间类不改 Python 即可被规则引用。",
  "jians": [
    { "name": "因间", "note": "工商/社会关系（敌国或关系人渠道）",
      "source_object_types": ["org", "bid_project"],
      "default_clearance": 1 },
    { "name": "内间", "note": "举报/内部线索",
      "source_object_types": ["tipoff"],
      "default_clearance": 3 },
    { "name": "反间", "note": "资金对手/逆向信息",
      "source_object_types": ["transaction"],
      "default_clearance": 1 },
    { "name": "死间", "note": "公开信息/工商公示",
      "source_object_types": ["osint_article", "org"],
      "default_clearance": 0 },
    { "name": "生间", "note": "通讯/轨迹等直接观察",
      "source_object_types": ["call", "trackpoint"],
      "default_clearance": 1 }
  ]
}
```

#### A-2 loader 改造

```python
# core/ontology_loader.py
# 删除：ALLOWED_JIAN = {"因间","内间","反间","死间","生间"}（第 47 行）
# 改为：从 jians.json 动态加载，与 load_dimensions 同构
def load_jians(pack="default", base_dir=None) -> list[str]:
    p = (base_dir or PACK_ROOT) / pack / "jians.json"
    if not p.exists():
        return list(DEFAULT_JIANS)      # 兜底内置默认
    data = _read_json(p)
    names, seen = [], set()
    for i, d in enumerate(data.get("jians", [])):
        name = d.get("name") if isinstance(d, dict) else None
        if not name:
            raise ValueError(f"jians.json jians[{i}] 缺 name 字段")
        if name in seen:
            raise ValueError(f"jians.json 间类名重复：{name}")
        seen.add(name); names.append(name)
    if not names:
        raise ValueError("jians.json 声明为空：至少需要一个间类")
    return names
```

#### A-3 清理三处硬编码

| 位置 | 动作 |
|---|---|
| `core/functions.py:246` `_JIAN_ORDER` | 改为从 pack 读取 |
| `core/hypotheses.py:69` `JIAN_ALL` | 改为从 pack 读取 |
| `server/app/hypotheses_view.py:30` `_JIANS` | 改为从 pack 读取（注意单字版本，需处理取首字） |

**⚠️ 迁移纪律**：三处全部改完，不留残留（吸取五维的教训）。

#### A-4 校验强化

`rules.json` 的 `jian_types` 必须在此声明，**未声明硬失败**（对齐 dimensions 的做法）。

---

### 阶段 B：职责拆分（约 2 人日）

#### B-1 权限从间类剥离 ⭐ 优先

**现状问题**：`_NEIJIAN = "内间"` 把权限绑死在间类上。

**改法**：把 `default_clearance` 作为 `jians.json` 的**可选元数据**（已在 A-1 schema 中预留），
实际过滤仍由 `policies.json` 执行。

```python
# 现在
_NEIJIAN = "内间"          # 硬编码：内间=高密级

# 改为
restricted = jian_meta.get(jian, {}).get("default_clearance", 0)
```

**收益**：换领域后，间类变了权限规则跟着变，不用改代码。

#### B-2 交叉等级名称可配

```jsonc
// jians.json 增加
"cross_levels": [
  { "min_independent_sources": 1, "name": "观察" },
  { "min_independent_sources": 2, "name": "线索" },
  { "min_independent_sources": 3, "name": "可立案依据候选" }
]
```

**⚠️ 注意**：名称可配，**映射关系（1/2/3）不可配**——见 §4.1 红线。

---

### 阶段 C：源独立性声明（约 2–3 人日）⭐ 最大价值

#### C-1 新增声明

```jsonc
// jians.json 或独立 source_independence.json
"source_independence": {
  "default": "independent",
  "related_pairs": [
    { "a": "公开OSINT", "b": "舆情监测",
      "relation": "同源转载", "count_as": 1 },
    { "a": "研报A", "b": "研报B",
      "relation": "同一机构", "count_as": 1 }
  ]
}
```

#### C-2 交叉计数改造

```python
# 现在：简单计数命中的间类数
n = len(hits)

# 改为：合并相关源后计数
n = count_independent(hits, related_pairs)
```

#### C-3 装载期校验

- `related_pairs` 的 `a`/`b` 必须是已声明的源
- `count_as` 必须是正整数且 **≤ 1**（不能放大）
- 自反（a==b）报错

**收益**：解决"同源转载被当成两个独立源"的系统性高估问题。

---

### 阶段 D：动态组合表达式（约 3 人日，可延后）

```jsonc
"combinations": [
  {
    "name": "人证物证俱在",
    "expr": "AND(生间, 反间, 因间)",
    "level": "可立案依据候选"
  },
  {
    "name": "孤证",
    "expr": "AND(内间, NOT(ANY_OTHER))",
    "level": "观察"
  }
]
```

**注意**：可复用 `core/rule_dsl.py`（已实现 AND/OR/NOT/WITHIN + `explain()` + MAX_DEPTH=5，
见《已实现未暴露模块全局盘点》）。

> ⚠️ 这是**增强项**，不是解耦必需。建议 C 完成后再评估。

## 7. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **过度抽象** 🔴 | 五间是孙子兵法方法论结晶，拆太散会丢掉智慧 | 保留"独立源交叉验证"内核，**只拆形式不拆精神** |
| 迁移不彻底 | 五维教训：`hypotheses.py:67` 仍残留 | 阶段 A 强制三处全改，加测试断言 |
| 配置爆炸 | 间类 + 相关性 + 等级，配置量可能大 | 提供合理默认，按需覆盖 |
| 红线被绕过 | 可配置 = 可能被配坏 | 装载期校验 + 映射关系不可配 |
| 顺序不一致引发 UI 错位 | 三处顺序不同 | 阶段 A 统一由 `jians.json` 的声明顺序决定 |

## 10. 一句话总结

> **五间解耦不是"能不能"，而是"照搬五维再做一遍"——`dimensions.json` 已经证明了这条路走得通。**
>
> 真正的价值不止于"换个领域能用"，而是解耦后能表达**「源相关性」**——
> 解决当前模型"把同源转载当成两个独立源"的系统性高估问题。
>
> **但要分层推进：先声明化，再职责拆分，最后动态组合。
> 跳步做会同时丢掉五间的方法论价值，又拿不到解耦红利。**
>
> 记住一条：**结构与名称可配，独立性判定与底线阈值不可配。**
