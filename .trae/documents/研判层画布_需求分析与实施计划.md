# 研判层画布（案件级）需求分析与实施计划

> 目标：一张**案件级**的研判作战地图。正兵在上面摆人、地、事、假设，随手调用研判工具，
> 发现的东西直接长在图上，一层层往下查，随时钻回源数据回答"凭什么"。
>
> 本文所有"现状"均取自实际代码，标注了文件与行号出处，不是记忆。

---

## 0. 决策记录（本轮已定）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | 画布形态 | **独立页面** `c/canvas`，案件级域 | 与 `c/graph`、`c/geo`、`c/convergence` 一致的案件级路由体系；页面独立 ≠ 数据模型独立，领域层共用即不会分叉 |
| D2 | 多维呈现方式 | **窗口式**，不做"四投影切换" | 投影切换是全局视角，窗口式是节点视角；用户要的是"节点上数据的呈现" |
| D3 | 常态呈现 | **C 打底**：186×50 卡内画迷你符号 | 复用现成的 `dimDotColor` 卡内色点机制，零改动成本 |
| D4 | 交互呈现 | **B 承载**：点击节点 → 贴附浮窗 | 卡片是 G6 canvas 节点，塞不进 HTML；浮窗不改节点渲染 |
| D5 | 触发方式 | **点击**触发（默认，可切悬浮） | 悬浮在密集画布会持续误触闪烁 |
| D6 | 窗口形态 | **贴附浮窗**（贴着节点，默认） | 抽屉脱离节点位置，与"节点上的窗口"意象有距离 |
| D7 | 全局视图 | **保留**，但降为窗口内「放大」入口 | 窗口擅长看单点，不擅长看跨节点模式；不做成默认视角 |

D5/D6/D7 为默认取值，均为配置开关，可切换。

| 靶心自动带入 | pack.json 每个镜头声明 `auto_from` | `packs/{geo,relation,timeline}/pack.json` |

### 1.2 缺口（四处结构性差距）

**G1 域不对——画布是线索级，不是案件级**

```python
# server/app/canvas_seed.py:86
def fact_ref(clue_id: str, idx: int) -> str:
    return sha1(f"{clue_id}|fact|{idx}")[:12]
```

`seed_canvas(*, clue_id=...)` 全程以 `clue_id` 为域。每次从某条线索进，长不成案件总图。

**G2 方向不对——只能往回溯源**

`canvas_expand.py` 四层是 `fact → object → source_row → source_file`，回答"凭什么"，不回答"下一步查什么"。

**G3 能力不对——研判镜头进不了画布（最硬的一处）**

- 画布 `function_result` 节点机制存在（RC-204），但白名单只有 6 个 Function，全是资金/通讯类
- 包里 14 个研判镜头（geo 7、timeline 3、relation 3、vlm 1），**进白名单的是 0 个**
- `canvas_enabled: true` 只有 geo 的 5 个（`packs/geo/pack.json` 5 处，relation/timeline/vlm 各 0 处）

→ 这正是"不能在画布上不断增加研判节点"的技术根因。

**G4 语义不对——节点全是证据溯源语义**

```typescript
// frontend/src/domain/canvas.ts:7
export const NODE_KINDS = ['rule','fact','object','source_row','source_file',
                           'verify_item','evidence','hypothesis','note','function_result']
```

10 类全是"证据/溯源"语义，**没有 subject（人）/ place（地）/ event（事）**。
人工可加的只有 `MANUAL_NODE_KINDS = ['hypothesis','note']`。

## 2. 需求设计

### 2.1 域升级：线索级 → 案件级（解 G1）

**域键**

```
案件级：eid("case", case_id)          节点键加 case# 前缀
线索级：sha1("{clue_id}|fact|{idx}")  保留，作为溯源子域
```

新增 `server/app/canvas_case.py`：**不改动** `canvas_seed.py`。
理由：线索画布（嵌在 `ClueDetailView`）仍承担溯源用途，两套并存、两套用途，比硬塞一张图清晰。
领域层（画布服务、id 体系、PATCH 校验）共用，避免分叉。

**兼容**

- 节点键加 `case#` 前缀 → 旧线索快照全部失效
- 处理：旧快照按 `clue#` 前缀识别，只读不迁；新画布只认 `case#`

### 2.2 节点语义扩展（解 G4）

新增 4 类，与既有 10 类并列：

| 新 kind | 业务名 | 承载数据 | 判定来源 |
|---|---|---|---|
| `subject` | 人（主体） | `person_pk`、`person_name`、`person_ambiguous` | `core/entity_ref.py` |
| `place` | 地点 | `location_id`、`lng/lat`、`coord_precision` | 交汇侧已补坐标挂载 |
| `event` | 事件/时间窗 | `time_start/end`、`time_precision` | `core/time_semantics.py` |
| `analysis_result` | 研判结果 | `lens_id`、`dimensions`、`weight`、`precision` | 统一来源 |

`analysis_result` **取代** `function_result`：
现有 `_lens_intervals` 把 Lens 产出也叫 `function_result`（同一名字两种来源），
统一为 `analysis_result`，来源写在 props 里。

对应改动：
- `domain/canvas.ts`：`NODE_KINDS` +4、`KIND_LABELS`、`KIND_ORDER`
- `server/app/canvas_edit.py`：`can_connect` 的 kind×kind×rel 矩阵扩展

### 2.3 边语义扩展

既有 `SYSTEM_RELS` 7 类 + `MANUAL_RELS` 4 类（推断为/证实/查否/补充说明）不变，新增研判边：

| 关系 | 语义 | 连接 |
|---|---|---|
| 位于 | subject/analysis → place | 人去过某地 |
| 发生于 | subject/analysis → event | 人在某时 |
| 支撑 | analysis_result → hypothesis | 证据支撑假设 |
| 反驳 | analysis_result → hypothesis | 证据反驳假设（**必须有**，否则假设只有单向证据） |
| 同现 | subject ↔ subject | 三维交汇产出的同现主体 |

### 2.4 窗口式呈现（核心，解 D2）

#### 2.4.1 为什么不能内联

```
// frontend/src/components/research/g6-card-node.ts:35
const CARD_WIDTH = 186
const CARD_HEIGHT = 50
class ResearchCardNode extends Rect   // G6 canvas 图形节点，不是 DOM
```

186×50 的 canvas 矩形，卡内布局全部写死坐标。**塞不进地图/时间轴/关系图，连内嵌 `<div>` 都做不到**。
所以窗口只能是 **DOM 浮层**，按节点屏幕坐标定位（复用 `domain/canvas-viewport.ts`）。

#### 2.4.2 C 打底：卡内迷你符号

节点仍是 186×50 紧凑卡片，用 G6 图形画极简标记（复用 `dimDotColor` 同位置机制）：

| 标记 | 含义 |
|---|---|
| 底部细色条 | 时间跨度（条长=跨度，位置=时点） |
| 右上色点（已有） | 主维度 |
| 左下空心/实心点 | 精度档：实心=时刻级，空心=日期级 |
| 虚线边框 | 重名待裁决 |

**作用**：一眼看出"这个节点有内容、是什么精度"，不承载完整可视化。

#### 2.4.3 B 承载：节点窗口

点击节点 → 贴附该节点弹出窗口。**窗口内容按节点类型分化**——这是"节点上数据的窗口式呈现"的实质：

| 节点类型 | 窗口 | 内容 | 数据来源 |
|---|---|---|---|
| `subject` | **关系窗口** | 他的关联网络（一跳邻居、共同邻居、圈子） | `graphApi` 按 `person_pk` 过滤 |
| `place` | **地图窗口** | 位置与周边锚点、同址事件 | 坐标挂载 + 交汇锚点 |
| `event` | **时间窗口** | 时序轨道带、前后事件、节奏 | `canvas-layout-time` / timeline 镜头 |
| `analysis_result` | **证据窗口** | 三维支撑矩阵（条数+精度档+权重）、证伪条件 | `convergenceApi`、`observationsApi` |
| `hypothesis` | **假设窗口** | 支撑/反驳清单、覆盖缺口 | 假设存储 |
| `fact`/`source_row` | **溯源窗口** | 沿用现有 `FactDetailPopover` | 既有 |

#### 2.4.4 窗口协议（关键约束）

| 项 | 规则 | 原因 |
|---|---|---|
| 同时打开数 | **默认 1 个**（可钉住多开，上限 3） | 多窗口互相遮挡，且每个都可能拉数据 |
| 定位 | 贴附节点右侧，越界翻转到左侧；视口跟随 | 节点滚动后窗口不能飘 |
| 地图实例 | **全页面唯一**，复用 | Leaflet/Amap 实例开销大，多开会爆 |
| 底图 | 默认离线 SVG；用户明确要看才创建在线实例 | 涉密环境默认不外联 |
| 关闭 | Esc / 点空白 / 再点节点 | — |
| 加载态 | 骨架屏 + 可取消 | 镜头调度是 202 异步 |

#### 2.4.5 放大路径（D7）

窗口内提供「放大」入口 → 进入该维度全局视图（`/c/graph`、`/c/geo`、`/c/convergence`），
并**带入当前主体/地点作为预设筛选**。
保留理由是窗口不擅长看跨节点模式（例：三个地点在时间上串成轨迹，三个独立窗口看不出来）。

### 2.5 生长机制（解 G3）

**靶心自动带入**是"不断增加研判节点"能成立的前提——否则每调一次工具都要重新选人，图长不起来。

```
选中 subject 节点 → subject_id 自动填 person_pk
选中 place 节点   → location_id 自动填 location_id
选中 case 节点    → project_id 自动填
```

实现：读 `pack.json` 已声明的 `auto_from`，前端按选中节点 kind 匹配参数名。

**生长链路**

```
选中靶心 → 工具箱（14 镜头 + 8 包装镜头）→ POST lens run → 202 入队
        → 产出观察 → 回写画布：新建 analysis_result 节点 + 挂到靶心 + 按 assumption 挂假设
```

**`canvas_enabled` 开启时机**：P1 定下节点挂哪一层之后，把 relation 3 / timeline 3 / vlm 1 与 geo 剩余 2 个一并置 true。
（当前只有 geo 5 个开着）

### 2.6 溯源层保留

画布保留双层：
- **溯源层**（现有 10 类节点、四层展开）→ 回答"凭什么"
- **研判层**（新增 4 类）→ 回答"查到什么、下一步查什么"

同页面双图层切换，不做两套画布。

## 3. 两条红线（写进测试）

**R1 精度档必须贯穿卡内符号与窗口**

```
实线粗边 / 实心点 = 时刻级（可判时间窗真重叠）
虚线细边 / 空心点 = 日期级（仅同地异时，非同时）
```

符号口径提到 `domain/canvas-window.ts` 单一来源，卡内渲染与四个窗口共用。
否则「12 条 date 档」和「4 条 minute 档」在图上长得一样——前面所有精度加权被一张漂亮图抹平。
（这是交汇侧已踩过的坑，画布上会原样重演）

**R2 重名绝不自裁**

张卫国真实存在两个身份证号（`obj_person_identity` 4 行）。
subject 节点带 `?` 标记 + 虚线边框，窗口顶部显式提示"待裁决"，
**不在两个候选里挑一个**。当前 42 条交汇里 21 条待裁决——消歧落地前这部分结果不能用。

## 5. 风险与开放项

| # | 事项 | 处理 |
|---|---|---|
| 1 | 旧线索快照因 `case#` 前缀失效 | 旧快照只读不迁；需确认是否接受"旧画布只读" |
