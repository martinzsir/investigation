## 1. 案例概况

### 1.1 案件一句话

招投标分管领导**张卫国**，其辖下 7 个市政项目连续由**宏业建设**（法人**李志强**）中标；每次中标公示后数日内张卫国账户出现 10 万元整数现金存入；另有宏业→李志强妻弟名下 **A建材**→张卫国配偶的两跳大额资金转移。疑似"分管领导—中标企业—亲属代持—资金回流"闭环。

### 1.2 入卷数据（8 源，真实规模）

| 数据源 | 行数 | 关键内容（聚合） |
|---|---|---|
| 招投标档案 | 7 | 宏业建设连中 7 项目，分管领导均为张卫国 |
| 银行流水 | 29 | 财政局季度工资 20 笔（约 1.85 万/笔）；**整数现金存入 7 笔×10 万**；对公转移 2 笔（460 万、170 万） |
| Q1_time_window | 7 | 7 个项目中标公示日→现金存入日，间隔 **5–18 天** |
| 通话记录 | 114 | 张卫国↔李志强长期高频通话（约每月 1 次，贯穿 2020–2023） |
| 轨迹出行 | 7 | 张卫国每次中标**次日**出现在对应项目现场 |
| 工商信息 | 3 | 宏业法人李志强；A 建材法人**李志强妻弟**；张卫国配偶关联 |
| 举报材料 | 3 | 现金约 120 万、安置房围标、A 建材大额转账 |
| 公开 OSINT | 4 | 招投标公示一致、分管职责、法人身份等公开信息 |

### 1.3 涉及主体（L0 对象实例）

```
obj_person:  张卫国 · 李志强 · 李志强妻弟 · 张卫国配偶
obj_org:     宏业建设 · A建材
obj_bid_project: 滨江路改造 · 城东管网 · 安置房一期 · 桥梁加固 · 市政绿化 · 智慧交通 · 安置房二期
obj_transaction / obj_call / obj_trackpoint / obj_tipoff / obj_osint_article: 见上表
```

## 2. 实施前基线：系统能发现什么、漏掉什么

> 基线 = 当前代码（v3 方案**未实施**）在同一数据上的真实表现。

### 2.1 能发现（现有能力）

| 能力 | 产出 |
|---|---|
| R1 整数大额筛查 | 7 笔 10 万元整数现金存入命中 |
| R6 公示日±20 天时间窗 | 中标日与现金存入 5–18 天间隔命中（Q1 表支撑） |
| R2 链式聚合 / 两跳过桥 | 宏业→A建材→张卫国配偶（460 万→170 万）两跳链 |
| R4 异人同地 | 轨迹与项目现场碰撞 |
| 五间交叉 | 已有线索按间类做 1/2/3 升格 |
| 报告 | canvas/sunzi-report 带溯源出报告 |

### 2.2 漏掉或失真（v3 要解决的缺口）

| # | 缺口 | 在本案的具体后果 |
|---|---|---|
| G1 | **owns 边 endpoints 两端对调** | "A建材由李志强妻弟持有""宏业由李志强持有"这类**账户/企业持有关系在图上永久隐形**——关系网络的第一条边就是断的 |
| G2 | time_window/osint_mentions 无端点 | 时间窗边、舆情提及边不入图，图上节点孤立 |
| G3 | 主键靠 `pk.split("_")[0]` 反解 | 分析师在编辑器改 txn_id 等 pk，会**静默重铸全库交易键**，线索/图/报告引用全部失配 |
| G4 | 自然键无唯一性断言 | clue 重复主键无人发现，看板上同线索互相覆盖 |
| G5 | 五间映射双写矛盾 | transaction 一处算生间、一处算反间，独立源计数口径不统一 |
| G6 | 无关系/时间统一镜头 | 亲属代持网络（妻弟+配偶+法人）靠人工串联；时间节奏（中标→存入→现场）散落在 R4/R6 不成体系 |
| G7 | 新手段无法自动上图进报告 | 每加一类手段要重写一遍可视化接线 |
| G8 | 无图像研判通道 | 发票/现场照片等书证只能人工查看，无结构化产出 |

**基线结论**：实施前系统能"点状命中"，但**核心关系边隐形、映射口径矛盾、跨手段不成链**，调查员需要大量人工拼图，且一次 pk 编辑就可能造成全库静默事故。

## 3. 实施后推导（按 P0→P8 能力逐批上线）

> 以下推演严格遵循 v3 批次顺序。每批标注"本案新增的可观测能力"。

### P0 endpoints/build_sql 一致性加固 —— 隐形边上图

**校验生效**：装载期 ref 方向硬失败 + 物化期端点列与 build_sql 输出对账 + 未声明端点显式 `graph_visible`。

**本案变化**：

1. owns 端点按真实方向修正：
   - `宏业建设 —[owns]→ 李志强`（企业与法人）
   - `A建材 —[owns]→ 李志强妻弟`（企业与代持人）
   - 账户层：`obj_account —[owns]→ obj_person` 不再两端对调。
2. time_window、osint_mentions 补齐端点；decision_for 显式 `graph_visible:false` 豁免。
3. **default 包入图边数 7 → 10**。调查员第一次在图上看到"谁持有哪家企业"。

> 若不修 P0：后续 P4 关系镜头的核心边（持有/亲属）全部建立在断点上。

### P1 key 一等声明 —— 主键契约可信

**本案变化**：

1. 20 个对象补 key 声明，5 个不一致前缀按现值固化：

| 对象 | key.column | strategy | prefix |
|---|---|---|---|
| transaction | txn_id | proxy（event） | **txn**（≠对象名） |
| trackpoint | track_id | proxy（event） | **track** |
| bid_project | project_id | proxy（entity） | **project** |
| osint_article | article_id | proxy（entity） | **article** |
| person_identity | identity_id | proxy | **identity** |
| clue / decision | clue_id / decision_id | **natural** | — |

2. `pk` 降为只读别名，与 key.column 冲突即硬失败；自然键唯一性断言生效。
3. 推演防事故：调查员若把 transaction 的 pk 从 `txn_id` 改为 `id`，旧逻辑会让全库键 `txn_3028…→id_3028…`；P1 后在装载期即被拦截。

### P2 五间映射止血 —— 口径单源

**业务拍板**（按 v3 建议语义）：

- **流水事件（transaction）= 生间**：主体存活活动的客观痕迹，与通话、轨迹同构。
- **过桥派生边（transfers）= 反间**：利用嫌疑人资金通道反证，客体是关系。
- related_pairs 声明 **transaction/transfers 同源**：不重复计独立源。

**本案变化**：jians.json 成为唯一权威源；"只要调到流水就点亮反间"的灌水被消除；反间只有在过桥边物化（宏业→A建材→配偶）时才成立。

### P3 镜头契约、失败隔离与自枚举 —— 插件管道就绪

**本案变化**：

1. `skill_invoke` 加 try：任一镜头异常不再炸全链，返回空线索 + degraded。
2. SkillSpec 支持 enabled/mode/params_schema/external_services/timeout/TTL。
3. `packs/*/pack.json` 自枚举：后续镜头放目录即注册，零注册代码。
4. evidence_refs 契约生效，引用挂 P1 key 契约（对象/边必须存在）。

### P4 关系研判镜头 —— 亲属代持网络显形

**镜头**：`packs/relation/`，consumes=[org, person, owns, calls_to, transfers]，params_schema={target_subject, depth}。

**本案产出（确定性图算法）**：

1. **亲属代持圈层**：以张卫国为中心 N 跳——
   ```
   张卫国 ──配偶── 张卫国配偶
            ▲ A建材→配偶 170 万（transfers）
   A建材 ─owns→ 李志强妻弟 ──亲属── 李志强 ─owns→ 宏业建设
   张卫国 ─calls_to（114 次）─ 李志强
   ```
2. 共同邻居：张卫国与 7 个中标项目，经"分管领导+通话+现场轨迹"多路径收敛到李志强。
3. 每条线索带 evidence_refs（节点/边/聚合量，如"两跳合计 170 万"）。

### P5 时间研判镜头 —— 中标后资金节奏成链

**镜头**：`packs/timeline/`，统一时间轴。

**本案产出**：

1. **中标→存入节奏**：7 个项目中标公示日后 5–18 天内各出现 1 笔 10 万整数现金存入（Q1 表精确对账）。
2. **中标→现场**：中标次日张卫国轨迹出现在项目现场（7 次）。
3. **跨类型碰撞**：把投标节点、现金存入、通话、轨迹对齐同一时间轴，呈现"中标—通话—现金—视察"重复 7 轮的稳定节奏。
4. 镜头只报候选事实，不出"串标/受贿"定性。

> P4+P5 两个样本后，evidence_refs 契约定稿（"两次再抽象"门控）。

### P6 五间最小解耦 —— 底座与五间脱钩

**本案变化**：

1. 五间搬出为 packs/wujian/，jian_types 改由融合层按 evidence_refs→源对象→映射**反查注入**。
2. 不装五间包，底座仍可装载并跑关系/时间镜头。
3. **装包后交叉升格结果与 P2 基线逐线索 Golden Finding 比对一致**。

### P7 表达层平台化 —— 自动出两图一报告

**本案变化**：关系/时间/资金线索凭 evidence_refs 零接线自动投影：

- **资金链路图**：edge_kinds=[transfers]，命中边高亮 + 金额时间轴。
- **关系图谱**：全边类型，亲属代持圈层可见。
- **报告**：自动生成资金链路/关联关系段落，每条陈述挂可点击溯源。

### P8 多模态图像研判 —— 书证草案经人验入卷

> 本节为**假设性补充数据**：将 7 笔现金存入对应的"报销/工程发票照片、现场签证单照片"纳入图像研判。

1. vlm 镜头（mode=draft）识别发票：发现"8 张发票销售方同名但发票专用章编码不一致""签证单金额与中标台账不符"，产 draft（模型名/prompt 版本/模型分独立字段，页面标"AI 草案待核"）。
2. 正兵按图像核验 playbook 比对原件确认 → ActionExecutor 创建 obj_image_evidence，链接宏业建设/对应项目。
3. 证据自动入图入报告，按确定性体系计分（**不使用模型分**）。
4. 断网/超时：vlm degraded，草案超 TTL 标 stale，其余镜头照常。

## 4. 五间覆盖与交叉等级的逐步演变

> 独立性按 related_pairs 处理（transaction/transfers 同源只计一次）。等级 = 独立间类数对应的 1/2/3 升格。

### 4.1 五间点亮路径

| 间类 | 对应证据（本案） | 镜头来源 |
|---|---|---|
| 因间 | 工商登记：宏业/李志强、A建材/妻弟、配偶关联 | 关系镜头 + obj_org |
| 内间 | 举报 3 条（含内部职工实名反映安置房围标） | obj_tipoff |
| 反间 | 过桥边：宏业→A建材 460 万→张卫国配偶 170 万 | obj_lnk_transfers |
| 死间 | 公开 OSINT 4 条 | obj_osint_article |
| 生间 | 现金存入 7 笔、通话 114 次、轨迹 7 次 | obj_transaction/call/trackpoint |

### 4.2 升格时间线（同一核心线索"中标后现金回流"）

```
第1步  R1/R6 单源命中（7 笔整数现金，时间窗吻合）
       间类：生间（1 类）                          → 等级1「观察」

第2步  P5 时间镜头并入：中标次日轨迹现场 + 通话节奏（仍属生间同源）
       P? 举报（内部职工）加入
       间类：生间 + 内间（2 独立类）               → 等级2「线索」

第3步  P4 关系镜头 + 过桥边：宏业→A建材→配偶 170 万
       间类：+ 反间                                → 等级3「可立案依据候选」

第4步  工商亲属代持（因间）+ 公开信息（死间）并入
       间类：五间全覆盖（5 类）                    → 维持等级3，置信度/覆盖度增强
```

### 4.3 三维评分（确定性，非模型分）

| 维度 | 本案贡献 | 数据来源 |
|---|---|---|
| 置信度 | 规则命中稳定重复 7 轮、多源一致 | scoring 声明权重 |
| 覆盖度 | 五间 5/5 覆盖 | jian_coverage |
| 数据强度 | 460 万/170 万大额、114 次通话、整数 7 笔 | 聚合量 |

> 图像模型分（如 0.87）**不进入**此表；只有人验通过、落为 obj_image_evidence 后才按规则体系计分。

## 7. 结论与边界

### 7.1 实施后效果（本案）

系统把同一批数据从"**点状命中、核心边隐形、口径矛盾**"推进到"**底座契约可信 → 四类镜头成链 → 五间交叉升格 → 两图一报告自动产出**"。调查员从人工拼图转为在可溯源图上做决策，新手段（关系/时间/图像）以 pack 目录接入、自动获得融合与表达能力。

### 7.2 诚实边界

1. 系统输出始终是**候选线索与交叉等级**，"受贿/串标"定性与立案决定权属于正兵，系统不替代。
2. 插件化与契约加固提升的是**口径可信度、能力供给速度与安全迭代速度**，不直接产生命中率；实际增益需以 Golden Finding 集和真实案件线索采纳率持续度量。
3. §P8 图像情节依赖假设性补充数据；现有夹具无图片，真实效果以图像数据接入后实跑为准。
4. 等级 3 = "可立案依据**候选**"，是证据成熟度标记，不是立案结论。
