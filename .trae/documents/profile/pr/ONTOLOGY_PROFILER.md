## 三、第七批缺、本次补的能力

**值类型识别**（画像指南 §三 坑 3）。第七批只按 `objects.json` 的
`string` 类型筛属性，**完全不看内容**，无法发现混装。

实测补上后：

| 属性 | 值类型分布 | 判定 |
|---|---|---|
| `account.raw_name` | 账号 100% | 纯净 → `account` |
| `org.legal_rep` | 人名 100% | 纯净 → `person` |
| **`transaction.from_raw`** | 账号 50% 人名 50% | **⚠ 混装** |
| **`org.raw_name`** | 机构名 67% 人名 33% | **⚠ 混装** |

混装属性的真正危害不是信号稀释（我上一版这个论断已收回），
而是**归一落点不明确**：归一到 `account` 还是 `person`？
探测会同时报两个方向，人工二选一，**选错就是链断裂**。

## 四、实施中修掉的四个缺陷

### 缺陷 1：画像原「金额串」正则过宽（画像指南的坑）

```
原正则：^[¥￥$]?[\d,]+(\.\d+)?(万|万元|亿|亿元)?$
```

可选部分全空时等价于 `^[\d,]+$`——**会把 `6222000111110001` 判成金额串**。

修法：要求「货币符号 / 千分位 / 小数 / 单位」至少出现其一。

```
¥1,200,000   → 金额串    1,200,000.00 → 金额串
15万元       → 金额串    6222000111110001 → 账号
```

### 缺陷 2：否定式顺序错误

`账号` 的 `^[\d*\-]{6,}$` 是超集，排在前面会吞掉手机号与身份证。
改为**特异性强的排前面**：手机号 → 身份证 → 日期串 → 金额串 → 账号 → 纯数字。

### 缺陷 3：第七批 `materialized_props()` 语义混淆（本次发现的最重要一处）

```python
def materialized_props(props=None):
    props = props or self.connectable_props()   # ← 只收录 string
```

它混了两个问题：

1. 这个**对象**物化了吗（`obj_*` 表存在吗）
2. 这个**属性**可连接吗（string 且非元数据）

后果：`transaction.amount`（decimal）、`transaction.date`（date）
被判为**"未物化"**——因为 `connectable_props()` 只收录 string。

修法：拆成两个方法。

| 方法 | 回答 |
|---|---|
| `materialized_objects()` | 哪些**对象**已物化 |
| `materialized_props()` | 哪些**属性**已物化且可连接（语义不变） |

### 缺陷 4：部分物化会崩溃

对象已物化但表缺列时，`COUNT("amount")` 抛 BinderException。
真实场景（分批建表、schema 演进）下会发生。

修法：画像加**列存在性检查**，缺列标注"对象已物化，但表中无此列"而非崩溃。

## 五、六层实现要点

### L0 文件层 → 不适用（物化后无文件）

### L1+L2 列层 / 值层

复用 `value_profile`，补：空值率、值类型分布、混装判定、落点建议。

### L3 语义层（画像指南 §四，四项指标）

| 指标 | 实现 | 适用 |
|---|---|---|
| 万元整数率 | `MOD(CAST(amount AS BIGINT), 10000) = 0` | decimal |
| 时间窗覆盖 | `ABS(date_diff(...)) <= window_days` | date + 关键日期 |
| 关注主体命中 | `IN (focus_entities)` | string |
| 与已有重合数 | `COUNT(DISTINCT ... IN known_entities)` | string |

**变体双轨**：规则检出同语言异写 + 别名表检出跨语言。
沿用画像铁律 2——**变体数 0 不代表干净**（有 AC 专门固化这点）。

⚠ **时间窗不硬编码**：从 `CaseContext.window_days` 读，
生产应接参数治理（`thresholds.json` / REQ-032）。有 AC 验证可配置。

### L4 间类层

直接复用画像指南的映射表：**正向**查"这批数据属于哪一间"，
**反向**查"缺哪一间 → 该补什么数据"。

实测当前：**缺内间、生间、因间**（`因间` 无任何对象声明，是设计缺口）。

### L5 决策层

质量分语义转换：一次性接入 → **持续健康度**。

| 类型 | 项 |
|---|---|
| 阻断 | 混装 -25、空值率≥50% -20、0 行 -30 |
| 告警 | 未物化 -12、基数≤2 -8、含肯定式识别 -5、无万元整数 -5、有变体 -5 |

**只对可连接属性报警**。元数据属性（`status`/`title`/`note`…）
不参与实体连接，其值类型分布无意义。
实测若不区分，`org.status`（值"存续"被误判为"人名"）会刷屏。
