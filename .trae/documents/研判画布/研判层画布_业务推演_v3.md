# 研判层画布 · 业务推演（完工态）

> 面向：办案人员（正兵）
> 场景：一起涉及公职人员的职务犯罪案件
> 前提：**本文假设前述所有功能均已实施完毕**——案件级独立画布、窗口式节点呈现、假设自动连线、证据节点提升、组织上画布、物品对象入本体。
> 数据说明：人物、地点、通话、三维交汇取自本案实测结果；**物品部分为推演示意**（本体中尚无真实物品数据），用于说明能力形态而非既成事实。

---

## 零、一句话定位

**研判层画布是这个案子唯一的总图。**

你在上面摆**人、组织、物品、地点、事件、假设**，随手调用研判工具，发现的东西直接长在图上，一层一层往下查，随时钻回源数据回答"凭什么"。

它不是从某条线索钻进去的小窗口，而是**整个案件的作战地图**——案件一立起来就存在，结案时这张图就是完整的研判过程记录。

---

## 一、起点：图上只有一个人

打开 **「研判画布」**（`c/canvas`），一个属于整个案件的独立页面。

图上放着举报材料里提到的那个名字：

> **张卫国**

孤零零一个节点。

这个节点不是你手打出来的文字——它是从证据卡**提升**上来的。

### 怎么提升

你在线索的证据链里看到"张卫国"这张灰色的证据卡，点它 → **「提升为研判主体」** → 弹出确认框，显示：

```
姓名   张卫国
主键   person_ecb52c3719fc
类型   人
```

确认之后，图上出现一张**主体卡**（不再是灰色），并且自动连回原来那张证据卡。

**原卡不消失。** 只是多了一条「提升为」的边。这样任何时候你都能顺着它钻回"这个人是从哪条线索、哪份材料里来的"。

而且提升是**幂等**的——同一个人在不同线索里被提升十次，图上仍然只有一个张卫国节点，不会变成十个。

---

## 二、第一次研判：他平时在哪

点中"张卫国"，右侧工具箱亮起所有能用的研判手段。

**关键体验：你只点了一下人，不用再选第二遍。**

系统已经知道靶心是谁。过去每调一个工具都要重新选一次人——查关系选一遍、查轨迹选一遍、查通话再选一遍；现在**选一次，所有工具都认**。

你点 **「落脚点分析」**。

图上"张卫国"周围自动挂出三个地点：

| 地点 | 到访次数 |
|---|---|
| 西湖区文三路 | 20 次 |
| 拱墅区莫干山路 | 3 次 |
| 滨江区江陵路 | 若干次 |

**图开始长了**——从一个人，长到一个人加三个地点。

注意边上还标着精度：文三路那 20 次多数是**日期级**（只知道哪天来过），莫干山路那 3 次是**时刻级**（精确到几点几分）。图上日期级画虚线细边、时刻级画实线粗边——这个区别后面会要命。

---

## 三、窗口：点开才知道节点里有什么

你想看看"莫干山路"到底是什么地方。

点这个地点节点——**不跳页**，节点旁边弹出一个窗口，窗口里嵌着一张地图：

- 位置落在杭州拱墅区
- 周边有什么、同址还发生过什么
- 坐标精度

**精度这一栏必须看：**

- **实心点** = 门牌级坐标，这是真实位置
- **空心点** = 区划质心，只代表"大概在这个区"

两者在地图上看上去一模一样，含义却差得很远。把质心当门牌用，就会把"他大概在这一带"读成"他就在这一户"。所以窗口里必须写清楚。

关掉窗口，图上还是那个节点。**地图是节点身上的一扇窗，不是另一张图。**

| 点什么节点 | 弹出什么窗口 | 里面是什么 |
|---|---|---|
| 人（subject） | **关系窗口** | 他和谁往来 |
| 组织（subject·org） | **关系窗口** | 哪些人挂在这个单位下 |
| 物品（subject·item） | **持有链窗口** | 谁在什么时候持有过它 |
| 地点（place） | **地图窗口** | 位置、周边、同址事件 |
| 事（event） | **时间窗口** | 什么时候发生、前后有什么 |
| 研判结论 | **证据窗口** | 支撑它的证据是哪几维、各什么精度 |
| 假设 | **假设窗口** | 支撑清单、反驳清单、还缺哪一维 |
| 证据卡 | **溯源窗口** | 沿用现有详情浮层 |

**每种节点打开的是它自己那一维的东西。** 这就是"节点上数据的窗口式呈现"——节点不再是干巴巴的一张卡片，而是带一扇窗。

卡片本身也有讲究：186×50 的紧凑卡片上，底部有一条细色条表示时间跨度，右上是维度色点，左下是**实心/空心点**标精度档，重名的画**虚线边框**。不打开窗口也能一眼看出"这个节点有内容、是什么精度"。

---

## 四、第二次研判：哪里不对劲

还是选中"莫干山路"，点 **「异常轨迹检测」**。

图上挂出一个新的研判结论节点：

> 张卫国在 **3 月 10 日、17 日、24 日** 下午 **14:35–16:40** 三次出现在莫干山路，均属脱离日常路线。

这条结论连着一根 **实线粗边**——时刻级，能判定"时间窗真的重叠"。

系统同时告诉你：那几天同在现场的还有 **李志强**。

"李志强"作为新节点自动出现在图上，也连到了莫干山路。**你没动手加他，是他自己长出来的。**

### 为什么线型比条数重要

看一个真实对照：

```
时间维  12 条  日期级  权重 0.6
空间维   4 条  分钟级  权重 1.6
```

12 看着比 4 多三倍。但日期级的每一次都是独立巧合——"他前一天来过、她后一天来过"而已，**根本不能叫见面**。如果图上 12 条和 4 条画得一样粗，你就会被条数骗了。

所以实线虚线、粗边细边，在卡内符号、连线、窗口里**必须一致**。这不是美术偏好，是防误判的硬要求。

---

## 五、规律自己跳出来

选中"李志强"，点 **「通话关系分析」**。

图上出现张卫国 ↔ 李志强一条连线，标注 20 次通话。

再打开李志强的**时间窗口**，你看到一个节奏：

```
3/7  通话 → 3/10 见面 → 3/11 通话
3/15 通话 → 3/17 见面 → 3/19 通话
3/23 通话 → 3/24 见面 → 3/27 通话
```

**每次见面前后都有通话。**

这个规律在过去根本看不出来——关系报告只说"通话 20 次"，空间报告只说"同框 3 次"，时间报告只说"有聚集簇"。三份报告分开放着，靠人脑拼。

现在它们在**同一个人的窗口里、同一条时间轴上、同一个地点旁边**，规律是自己跳出来的。

## 六、假设自己长出来：不用手工连线

这时候，图上**自己长出一个节点**：

> **H6 私下接触**

同时，莫干山路交汇点、异常轨迹、通话关系这三条研判结论，**自动连到它下面**，边上标 **「推断为」**。

**这三条边是灰色的细线**——表示"这是机器推的，还没经你认可"。

你审一遍，认同其中两条，点一下改成 **「证实」**，边立刻变成**实线粗边**。第三条你觉得证据不足，直接删掉。删了之后系统不会下次又给你连回来。

### 三条规矩

**一、系统只出「推断为」，不出「查否」。**

系统只知道"这条证据归属哪条假设"，不知道"这条证据**反驳**了哪条假设"——那是判断，不是数据。所以反驳方向留给你。

比如你后来查到两人同属一个项目组（公务往来而非私下接触），这条由你连上去、标 **「反驳」**。

**二、一条证据命中多条假设，就出多条边。**

比如某条证据同时涉 H1（特定关系）和 H6（私下接触），图上就画两条边，**不替你挑一条**。

**三、线型跟着精度走。**

支撑边的粗细虚实，跟着那条证据本身的精度档。时刻级实线、日期级虚线。所以你在假设节点上一眼能看出：**这个假设是靠什么精度的证据撑起来的。**

### 假设节点成了中枢

打开 H6 的**假设窗口**，你会看到：

```
支撑  3 条   空间·时刻级 / 关系·时刻级 / 时间·日期级
反驳  1 条   同属项目组
覆盖缺口  通信维无数据
```

**证据终于归集了。** 过去是三堆互不相干的观察，现在同一个假设下有几条、几维命中、什么精度、还缺哪一维，全在这一个窗口里。

## 七、组织登场：两个人之间隔着一个单位

你觉得"通话 20 次"只是表象，想看看两人有没有更深的利益关联。

选中李志强，点 **「单位利益关联」**。

图上长出一个**组织节点**：

> **某某建设集团**

并自动连出两条边：张卫国 → 该集团、李志强 → 该集团。

**这就是过去画不出来的那条间接路径。**

直接关系（张↔李通话）只是表象；真正要紧的是「张卫国 → 某单位 ← 李志强」这条**通过组织串联**的路径——而间接路径恰恰是利益输送最常见的形态。

组织节点的窗口里，你能看到哪些人挂在这个单位下、它和哪些项目有关、涉及哪些间类关系（单位利益关系、任职关系、管理服务关系）。

打开 H6 的假设窗口，这条单位关联也自动挂了上去（灰色细边待你确认）。

## 八、物品登场：那辆车

现在图上有了人、组织、地点、事件。还差一样东西——**物**。

你在核查中发现李志强名下有一辆车。在图上加一个**物品节点**，类型选"车辆"，录入车牌号。

这个节点一出现，工具箱里多了一组物品相关的研判手段。你点 **「物品轨迹分段」**。

图上挂出这辆车的行驶轨迹——**和人的轨迹走的是同一套对象、同一套空间镜头**，因为轨迹模型从来没规定"必须是人在走"。

结果：

> 该车在 **3 月 10 日、17 日、24 日** 下午均出现在莫干山路一带，时段与张卫国、李志强的停留时段重合。

车内没有人，但车在那儿。这条证据自动挂到 H6 下。

## 九、物品和人的根本不同：时态 + 重号

打开这辆车的**持有链窗口**，你看到的是一条**带时间区间的链**：

```
2020-03 前   王五持有
2020-03-05   王五 → 李志强（过户）
2020-03 至今 李志强持有
```

**这条时间轴是必须的，不是装饰。**

如果只画静态边"王五 → 车、李志强 → 车"，你会读成"两人共用一辆车"。而实际是"王五卖给了李志强"——**性质完全相反的两种事实**。

所以持有边一律带起止时间，未闭合的表示"当前仍持有"。

### 重号是信号，不是噪声

再跑一次 **「同号多点冲突」**，系统报出一条：

> 该车同一车牌在 **3 月 17 日 14:40** 同时出现在莫干山路与相距约 200 公里的另一地点，两地在此时段内物理上不可达。

注意措辞——系统**只说事实**："同一标识、同一时刻、出现在物理不可达的两地"。

它**不说"套牌"**，也不说"涉嫌""可疑"。定性是你的事。

这就是物品和人的根本区别：

| | 人的重名 | 物品的重号 |
|---|---|---|
| 性质 | **噪声**，要消除 | **信号**，要报出来 |
| 处理 | 消歧、分列、不猜 | 输出待核线索 |
| 例子 | 两个张卫国 | 套牌、改 IMEI、假发票 |

人的身份证号不会故意伪造，物品会——套牌、改号、假发票都是典型的对抗行为。所以物品的"重号"不能套用人那套消歧逻辑，它本身就是线索。

## 十、物品家族：房产、发票、药品批号

车只是第一类。同样的玩法，还有：

**房产**——不动产权证号是可靠凭证。查涉案人名下房产，看购置时点与资金异动的耦合。

**发票**——代码加号码，可靠凭证。发票流转属资金维，能串出"甲单位开票 → 乙单位入账"的链条，是税务与职务犯罪交叉场景的主力。

**药品批号**（医疗行业）——一批耗材从出厂到入院，流经哪些经销商，谁签的字。高值耗材是医疗腐败的重灾区。

**行业可扩展**——金融行业可以加证券代码、理财产品；海关可以加集装箱、报关单；食药可以加食品批次。**研判逻辑是通用的**（流转链、共现、时空轨迹），与具体是什么物品无关，所以行业包只需要声明自己行业的物品子类型，不用改代码。

### 一条必须守住的规矩：不新增"物品"维度

车的轨迹属**空间维**，发票流转属**资金维**，手机通话属**通信维**。物品散落在既有六个维度里。

**不单开"物品维"。** 否则会破坏维度覆盖度模型，也会让人误以为"物品"和"资金""通信"是并列关系——它不是，它是一种**实体**，不是一种**证据维度**。

---

## 十一、没有编号的物品：赃物怎么办

现场扣押的无编号物品——账本、U 盘、现金、管制物品——**没有唯一凭证**。

这类物品在图上照样能建节点，但：

- **不进自动消歧**（没有凭证无从判定"是不是同一个"）
- **不进交汇打分**（否则会给出伪精确）
- 只按特征描述建**描述性对象**

节点上会明确标注"描述性对象，无唯一凭证"。这不是功能缺失，是**防伪精确**——给不出确定答案的时候，宁可说"不知道"，也不能编一个"是"。

---

## 十二、一条不能越的线：重名不能猜

回到图上的"张卫国"——他带着一个 **`?` 标记，边框是虚线**。

因为库里**有两个张卫国**：身份证号不同、手机号也不同。系统判定为同名异人，但**分列还没落库**。

系统**不会替你挑一个**。它把主键留空、列出候选、写明理由（身份证号互斥），等你裁决。

### 这不是洁癖

当前 42 条三维交汇里，**21 条是这样的重名待裁决，整整一半**。

如果不标清楚，空间、时间、关系三个维度的证据可能配到另一个人身上——**图长得越漂亮，错得越彻底**。

你点开节点、接受分列、系统重建，`?` 消失，这一半的结论才真正可用。

**组织也有同样的问题，而且更麻烦**——组织连统一社会信用代码都没有，只能靠"单位名 + 法定代表人"组合判定，而组织名的重复率比人名高得多。所以组织节点的 `?` 标记，你更要当心。

---

## 十三、溯源：随时回答"凭什么"

图上任何一条结论，双击它，往下钻：

```
研判结论 → 原始观察 → 具体数据行 → 源文件
```

点"3 月 10 日 14:35 出现在莫干山路"，能看到具体是哪条轨迹记录、来自哪个数据文件。

点那辆车的过户记录，能看到过户登记的原始行。

**图长得再多，也不丢证据链。** 这是双图层设计的目的——研判层负责生长，溯源层负责保真。

## 十四、产出：直接转核查任务

看完图，你认定莫干山路这个交汇点值得查。在节点上直接点 **「生成核查任务」**：

1. 核实莫干山路 111 号的场所性质（办公？餐饮？住宅？）
2. 核实两人是否同属一个项目组
3. 核实那辆车的实际使用人与过户真实性

任务落到核查工作台，走访回来回写结论——**证实或证伪，直接标回假设节点**，H6 的边由灰转实、或者被标成查否。

研判过程第一次被完整记录和呈现：**从一个人，到一张图，到一条假设，到实地核查，到结论回写。**

## 十五、这个形态解决了什么

| 过去 | 现在 |
|---|---|
| 三份报告分开看，规律靠人脑拼 | 同一张图，规律自己跳出来 |
| 每个工具要各自选一遍人 | 选中即靶心，自动带入 |
| 查到新线索要重跑全流程 | 图上直接加节点继续查 |
| 结论堆在报告里，不知在证明什么 | 自动挂假设，标明支撑 / 反驳 |
| 间接路径（甲→单位←乙）画不出来 | 组织节点登场 |
| 涉案车辆、房产、发票无处安放 | 物品对象，带时态持有链 |
| 人的重名和物品的重号混为一谈 | 前者消歧不自裁，后者直接出线索 |
| 看到结论不知凭什么 | 双击下钻到源数据 |
| 看细节要跳到别的页面 | 原地开窗，图不丢 |

## 十六、一句话总结

**过去是"跑工具 → 看报告 → 手工拼规律"；现在是"在图上摆对象 → 随手调工具 → 发现的东西自己长在图上 → 假设自己连起来 → 顺着往下查"。**

研判不再是一次次跑批，而是**一张会长大的图**——人、组织、物品、地点、事件、假设，六种对象在同一张图上互相印证；每一次研判都留痕，每一条结论都可溯源，每一个假设都知道自己被什么支撑、被什么反驳。

## 附一：四条红线（业务上必须知道）

1. **系统不定性。** 物品冲突只说"同一标识同一时刻出现在物理不可达两地"，不说"套牌""涉嫌"。定性是正兵的事。
2. **精度档贯穿始终。** 卡内符号、连线线型、窗口矩阵三处一致。时刻级实线粗边、日期级虚线细边——否则会被条数骗。
3. **重名绝不自裁。** 人的重名标 `?` 等裁决；物品的重号报线索不消歧；无凭证物品不进打分。
4. **系统边可删不可改。** 灰色细边是机器推的，你可以删、可以改成"证实"，但系统不会因为你删了就下次又连上。

## 附二：仍需拍板的三件事

1. **物品持有链的图布局**——持有链是时序结构，蛇形／时序流一类布局比力导向更贴合；是否按此选型待确认（不阻塞后端实施）。
2. **组织无唯一凭证**——`org` 仅有单位名、法定代表人、状态、关联，无统一社会信用代码。是否引入信用代码属性，属独立小需求。
3. **手机号未标敏感**——`DE_PHONE` 当前无去标识化标记，而手机号属个人信息。物品引入手机号／IMEI 后是否顺带补标，会影响既有通话链路的遮蔽行为，需单独确认。
