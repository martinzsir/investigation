## 〇、本轮核查发现的三处必须先纠正的事实

这三条若按错误信息实施，会系统性返工。

### C1 · 假设编号的实际含义与我此前推演不符

`ontology/default/hypothesis_patterns.json` 实际定义：

| 编号 | 实际含义 | dimension | jian_types |
|---|---|---|---|
| H1 | 收受财物（异常整数现金存入） | fund, time | 生间 |
| **H2** | **关联公司因行贿获中标优势（利益关联）** | relation | 因间 |
| **H3** | **二人密切私下关系（通讯频次突增）** | comm, behavior, space | 生间 |
| H4 | 财物通过第三方过桥 | fund, time | 反间 |
| H5 | 系列事件空间聚集（掠夺者型空间行为模式） | behavior, space | 死间 |
| H6 | 私下接触（异主体时空反复同框） | space, time | 生间 |

**后果**：此前给 8 个裸 Function 补 Lens 包装时，把 `lens_comm_call_frequency`
（通话高频）挂到了 H2 —— **挂错，应挂 H3**。`overpass_two_hop`（跨主体二跳资金）
挂了 H1 —— **应挂 H4**。

已列为准入项 **CAN-18**，在所有画布接线开工前必须先修正。

### C2 · 物体卡片尺寸是硬约束，窗口不能内联

```typescript
// frontend/src/components/research/g6-card-node.ts
const CARD_WIDTH = 186
const CARD_HEIGHT = 50
class ResearchCardNode extends Rect   // G6 canvas 图形节点，非 DOM
```

186×50 的 canvas 矩形、卡内布局全为写死坐标，**连内嵌一个 `<div>` 都做不到**。
所以"节点上的窗口"只能是 DOM 浮层，按节点屏幕坐标定位。

### C3 · 组织类型名与属性与预期不符

- 类型名是 **`org`**，不是 `organization`
- 属性仅 `raw_name / legal_rep / status / relation`，**没有 `org_code`**
- 故组织身份键只能取 `raw_name + legal_rep`；唯一凭证需新增（见 ITM-21）

## 二、现状与差距（实测）

### 2.1 画布的四处结构性差距

| # | 差距 | 代码出处 |
|---|---|---|
| G1 | **域是线索级**，长不成案件总图 | `canvas_seed.py:86` `fact_ref(clue_id, idx) = sha1("{clue_id}\|fact\|{idx}")` |
| G2 | **方向是回溯源**，非往外研判 | `canvas_expand.py` 四层：`fact→object→source_row→source_file` |
| G3 | **镜头进不了画布** | 白名单 6 个 Function 全是资金/通讯类；14 个镜头进白名单 **0 个** |
| G4 | **节点是证据语义**，无研判对象语义 | 7 类：`hypothesis/fact/object/source_row/source_file/function_result/note` |

### 2.2 镜头画布开关实况（比预估更差）

```
packs/geo/pack.json      canvas_enabled: true × 5
packs/relation/pack.json    —— 0 个开启
packs/timeline/pack.json    —— 0 个开启
packs/vlm/pack.json         —— 0 个开启
```

不是"镜头进不了画布"，是**压根没开**。

### 2.3 假设连线：线索层已自动，画布层三处断链

线索产物实测 **7 条线索全部自动挂了假设**（H6/H1/H2/H4/H3…），来源是
`hypothesis_patterns.json` 的 `match_finding_pattern`，**rule_id 精确命中优先于关键词**。

画布层断在三处：

1. **不生成假设节点** —— `MANUAL_NODE_KINDS = ['hypothesis','note']`
   （`frontend/src/domain/canvas.ts:66` 与 `server/app/canvas_edit.py:28` 前后端各一份），
   hypothesis 属于"只能手工加"的那类
2. **节点不带假设 ID** —— `canvas_seed.py` 中无 `assumption_chain` 消费，
   而 `core/registry.py:247` 的 `Lineage.assumption_chain` 是现成的
3. **无系统推断边** —— 现有边只有系统溯源边（`SYSTEM_RELS` 7 类）与人工边
   （`MANUAL_RELS` 4 类），**没有第三种**

### 2.4 边语义矩阵已完备（可直接复用）

`RC-203` 前后端各一份、单测全量对拍：

```
fact / object          → hypothesis ：推断为
verify_item / evidence → hypothesis ：证实 / 查否
note                   → 任意       ：补充说明（方向固定）
```

**语义齐备，缺的只是让系统去用它。**

## 三、对现有项目的影响分析

### 3.1 破坏性影响（必须重跑/迁移）

| 影响项 | 原因 | 处置 |
|---|---|---|
| **节点键全量变化** | 域升级加 `case#` 前缀 | 旧线索画布**只读不迁**（按 `clue#` 前缀识别），新画布只认 `case#` |
| **`track_id` / 主键全量变化** | `timestamp` 列 + `identity_key` 复合键 | 重跑管线；画布快照、已提升线索的 `event_pks` 全部失效 |
| **既有通话链路遮蔽行为改变** | `DE_PHONE` 补标 sensitive 后明文不可用于关联 | I22 提到 I16/I17 之前，**先回归通话关系分析再继续** |
| **组织主键变化** | 引入统一社会信用代码作身份键 | 涉及组织的所有既有 `lnk_*` 需重建 |

### 3.2 兼容性影响

| 影响项 | 处置 |
|---|---|
| `function_result` 名称已错位（`_lens_intervals` 把 Lens 产出也叫此名） | 统一为 `analysis_result`，来源写进 props；保留旧 kind 只读兼容一版 |
| `MANUAL_NODE_KINDS` 扩展 | 前后端各一份，需同步；现有单测全量对拍，新增须同步补 |
| `RC-203` 矩阵新增行 | `object → subject : 提升为` 为**系统边**，与人工四类互斥，不进人工矩阵 |
| `label_of()` 引入 | 现有 3 处猜测（`lens_basis.py:38`、`observation.py:138/143`）保留兜底，**禁止新增猜测点** |

### 3.3 性能影响

| 风险 | 约束 |
|---|---|
| 地图窗口实例爆炸 | **每个节点一个 Leaflet 实例会爆**。窗口内默认离线 SVG，仅用户明确要看真实底图时创建**单个复用**实例 |
| HTML 节点性能 | 数百节点下 G6 HTML 节点显著劣化 → 卡片**保持 canvas 图形节点**，窗口用 DOM 浮层 |
| 画布规模 | 沿用现有 `NEW_NODE_CAP=200` / `NEIGHBOR_CAP_PER_LINK=50` / `OBJECT_SCAN_PER_TYPE=2000` 限流 |
| 装载期 | 物品/组织新声明进 `ontology_loader` fail-closed 校验，失败即硬失败（不静默） |

### 3.4 合规影响

- 手机号、IMEI、车牌、权证号中，**手机号属个人信息、IMEI 可定位到设备**
- 复用 `DE_IDCARD sensitive=true mask=partial` + `policies.json` 既有机制，不新造
- **join 键改用 `digest`**：若用部分遮蔽明文串（如 `138****0001`）匹配，
  不同人号码会撞成同一串，产生错配
