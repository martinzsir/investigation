## 1. 背景与目标

### 1.1 业务目标

1. **提高对数据的研判能力**：在现有资金筛查/五间交叉之上，新增关系研判、时间研判、多模态图像研判等手段，并使多手段产出可交叉升格。
2. **便于系统扩展**：新增一种研判手段的边际成本应趋近"一份声明 + 一个只读实现"，融合、升格、可视化、报告由平台自动承接。
3. **数据底座纯粹化**：ontology 作为整体数据底座，不绑定任何一种研判学说（包括五间）。

### 1.2 设计原则（贯穿全文）

- **机制与词汇分离**：底座与研判内核只提供机制（对象/链接、线索契约、多源交叉、状态机），业务词汇（五间、资金视角…）全部在可插拔的研判手段包内。
- **统一事实契约**：所有研判手段产出同构的 `LineageClue`，禁止各自定义返回结构；任何"强制结论"只能写入结果对象的标记字段，不得早退或返回异构对象。
- **表达层零判据**：图与报告只消费线索与证据引用，不产生结论；每条陈述、每条高亮边可回溯到 clue_id / 语义对象 ID。
- **确定性优先、概率性隔离**：规则/图算法可复现，直接进推演；多模态输出不可复现，只能产草案（draft），人验通过才成证据。
- **门控式投资**：不为假想需求提前建平台；每个抽象必须有 ≥2 个真实使用样本后再抽取。

### 1.3 目标架构

```
L4 表达层（投影，零判据）
   GraphView 资金链路图/关系图谱（同图不同过滤） · canvas_report/sunzi-report 结构化报告
        ▲ 消费 evidence_refs（节点/边/时间区间/聚合量/书证）
L3 研判手段包（可插拔，因案而异）
   五间包（现有，降级为平级手段之一） · 关系镜头 · 时间镜头 · 图像镜头(草案通道)
        ▲ 产出统一 LineageClue
L2 研判内核（机制，无业务词汇）
   SkillSpec/skill_invoke（失败隔离/灰度） · 去重合并 · 多源交叉升格机制 · 三维评分机制
        ▲ 消费
L1 语义层  obj_* / lnk_*（编译器产物）
L0 数据底座（纯 ontology，零研判词汇）
   objects/links/bindings/policies/views/data_elements/...
```

## 3. 目标契约设计

### 3.1 纯底座（L0）

- objects.json/links.json 删除 `jian`、`jian_source` 字段；`ObjectType/LinkType` 去字段。
- ontology_loader 装载主链路删除 `load_jians → allowed_jian → _parse_jian` 依赖链；loader 不认识任何研判词汇（也不做"不透明注解"的长期保留——注解化只是迁移中间态，见 P4）。
- 底座装载对研判包零引用；研判包引用底座对象名，引用不存在时由**研判包自己的装载校验**报错。

### 3.2 研判包（L3）物理形态（P4 定稿，此处先定形状）

```
packs/wujian/                 # 五间研判包（从 ontology/default 搬出的研判部分）
  pack.json                   # 包声明：id/版本/依赖的 ontology 对象与链接名
  jians.json                  # 间类定义 + 对象类型→间类映射（唯一权威，单向）
  cross_levels.json           # 1/2/3 升格绑定（映射数字仍硬编码校验，名称可配）
  scoring.partial.json        # jian_coverage 维度与间类权重
  validators.py               # 自己的白名单/一致性校验（不再寄生 ontology loader）
```

- 映射唯一源：**jians.json 的 `source_object_types`（间类→对象/链接列表，天然支持一对多，如 org 同时属因间/死间）**；`jian_source` 展示名并入映射条目。
- 未来 packs/relation/、packs/timeline/、packs/vlm/ 与之平级。

### 3.3 镜头声明与统一线索契约（L2/L3 边界）

`SkillSpec` 扩展（全部带默认值，向后兼容）：

```python
consumes_objects: list[str]   # 消费的语义对象/链接类型（能力声明主口径）
produces_dims: list[str]      # 产出的评分维度标签
mode: str = "deterministic"   # deterministic | draft   ← 图像镜头用 draft
enabled: bool = True          # 单镜头开关（灰度/停用）
# —— 外设化对齐（v2.1 修订）——
params_schema: dict = {}      # 任务声明：可接受的指挥参数 {名: {type, enum?, required?}}；空=仅被动上报
external_services: list = []  # draft 镜头依赖的外部服务标识（如 vlm:qwen-vl）；确定性镜头为空
timeout_ms: int = 0           # 外部调用超时；0=不适用（确定性镜头）
result_ttl_s: int = 0         # 产出新鲜期；超过 TTL 的线索标记"陈旧"，禁止静默沿用旧结果
```

- **任务声明（外设化三问之"你能执行什么动作"）**：`params_schema` 把镜头从"只可被看见"补全为"可被指挥"。参数类型与 enum 白名单在装载期校验，复用对象属性 enum 机制；未声明的指令调度层不得下发。
- **新鲜度（对接"断连重连/超期标记"）**：draft 镜头必须声明 `external_services/timeout_ms/result_ttl_s`；服务断连或超时时，调度层将其既有线索标 `stale` + 缺口提示，而不是把旧结果当当前结论。确定性镜头无外部依赖，三个字段恒为空/0。

`LineageClue` 新增**结构化证据引用**（只加字段、不改现有字段）：

```python
evidence_refs: list[dict] = field(default_factory=list)
# 每条 ref：{"kind": "node"|"edge"|"time_window"|"aggregate"|"file",
#           "ref": "obj_org#id" | "lnk_transfers#id",
#           "time_from"/"time_to": 可选, "metric"/"value": 可选,
#           "file_uri"/"verify_status": 可选（书证/图像）}
```

`jian_types` 字段**保留不改名**（约 20 文件消费的共享契约），但填充方式改变：镜头不自报间类，由融合层按线索 evidence_refs 引用的源对象经五间包映射**反查注入**；五间包未安装时该字段自然为空，交叉升格降级为缺口展示（复用现有 `_UNMODELED` 诚实缺口范式）。

### 3.4 失败隔离与降级（P1）

- `skill_invoke` 包裹 handler：单镜头异常 → 捕获 → 返回空线索 + 在 RunHealth 记 `skill_failed{skill_id, error}` + 推演结果带 `degraded` 清单；其余镜头与总流程照常。
- deterministic 镜头异常 = 降级空转（零命中诊断已有规则，REQ-G-002 复用）；draft 镜头异常 = 静默降级并明示（`fallback=deterministic_only` 现有政策）。
- 红线：隔离不得吞掉"装载期硬失败"（声明非法、契约不符必须炸构建），只隔离运行期数据异常。

### 3.5 多模态图像镜头的"草案→人验"闸门（P6，不提前实现）

- 模型输出只生成 draft 线索（`mode=draft`），**永不直接进入生产 finding、不写语义层、不进评分融合**（沿用 shadow 语义）。
- 正兵按 verify_playbook 逐项核验通过后，经 **ActionExecutor 唯一写路径**创建 `obj_image_evidence`（含图像文件 URI、模型名/prompt 版本/模型分、核验人、核验结论），此后它是普通语义对象，按确定性体系计分、被任意镜头消费。
- 模型置信度与规则置信度**分字段存储**，禁止混填同一 confidence 参与三维加权。

### 3.6 镜头自枚举与镜头级授权（外设化对齐，v2.1 新增）

**（1）自枚举：上电即注册，替代手工 register**

- 启动期扫描 `packs/*/pack.json`：读取包声明（id/版本/镜头清单/consumes/params_schema/依赖对象名），执行与 USB 一致的四步——**枚举**（发现包）→**注册**（SkillSpec 登记、校验引用的底座对象/链接存在）→**挂载**（能力出现在调度目录）→**可分配任务**。
- 引用的底座对象不存在、params_schema 非法等问题在**注册期硬失败**（仅该包拒绝挂载并报明确原因），不影响其他包；运行期异常仍按 §3.4 隔离。
- 兼容过渡：现有 5 个内置技能由 registry_bootstrap 作为"内置包"统一引导，注册路径收敛到同一个枚举入口；P4 后五间也成为被扫描的普通包，bootstrap 只负责内置确定性技能。
- 目标：接入第 N 个镜头的工作量 = 放一个 pack 目录，无需改注册代码（兑现"接第 100 个和第 1 个一样"）。

**（2）镜头级授权：每个镜头持作用域凭据，接入是授权不是让渡**

- 镜头在 pack.json 声明**可读对象类型/链接类型作用域**；调度层在其查询时套用 policies 遮蔽（敏感列脱敏、无权对象不可见）。现有 AccessContext 五出口鉴权约束的是**使用方**，本修订补上**能力提供方**一侧的最小权限。
- 第三方 draft 镜头（如外部 VLM 服务）默认作用域最小：只获脱敏后数据，禁止读取未遮蔽 PII；提升作用域需在包声明显式申请并经装载校验，fail-closed。
- 镜头凭据可单独吊销（包 enabled=false 或移除目录）即收回全部权限；写操作不在镜头授权内——任何镜头（含 draft）落证据一律经 ActionExecutor 人验闸门。

## 6. 业务价值与衡量指标

| 价值 | 现状基线 | 目标 | 度量方式 |
|---|---|---|---|
| 新研判手段接入成本 | 需同时改 detector/loader/前端/报告/标签多处 | 确定性新镜头 = 1 份 functions 声明 + 1 个实现 + 1 个 pack 目录（零注册代码） | 统计 P2/P3 实际改动文件数；形成《镜头接入清单》模板 |

| 单镜头故障爆炸半径 | 一个 handler 抛异常，整条 skill 链失败（registry.py L339 无保护） | 仅该镜头降级，其余正常，degraded 可见 | test_skill_isolation 固化 |

| 研判覆盖面 | 资金/轨迹/登记 6 条规则、五间交叉 | 增加关系圈层、时间碰撞、图像书证三类手段，且自动参与多源升格 | 同一夹具下线索数/独立源覆盖率前后对比 |
| 新手段上图/进报告 | 每个手段单独接线 | 零接线自动投影（凭 evidence_refs） | P5 后新镜头清单中"自动出现于两图一报告"比例 100% |

## 7. 具体例子（端到端）

### 例 1：资金研判 → 图 → 报告（P2/P5 后，过桥账户）

1. 筛查：xu_shi R1 命中"A 公司→张某→李某"整数大额单向链。
2. 证据引用：线索 evidence_refs 携带三条 `lnk_transfers` 边、节点 obj_org/obj_person、aggregate（合计 480 万）。
3. 融合：五间包按边源对象反查注入 jian_types=[反间]；与既有 call 碰撞线索（生间）合并 → 双源升格"线索"。
4. 图：正兵打开资金链路图 = GraphView 以 edge_kinds=[transfers] 投影同一张语义图，命中边按 clue_id 高亮、附金额时间轴；切到关系图谱即看全边类型。
5. 报告：sunzi-report 凭 evidence_refs 自动生成"资金链路"段落，边与节点可点击溯源，无需为新规则写报告代码。

### 例 2：关系镜头零改融合层产生新升格（P2/P4 后）

关系镜头发现：投标对象 B 公司的隐性股东，与中标项目分管领导为共同通话人（owns 两跳 + calls_to 共同邻居）。镜头本身不含任何五间词汇；融合层反查其 evidence_refs 命中对象（org→因间、call→生间），该线索自动获得双间类 → 与资金线索交叉后达到三源"可立案依据候选"。**新增一种研判手段，没有改融合/评分/图/报告任何一行。**

### 例 3：时间镜头的跨类型碰撞（P3）

时间轴 Function 发现：开标前 72 小时内，同一对公账户向 3 个个人账户各转出 9.8 万、且 3 人的轨迹点在开标地同一酒店聚集。线索 evidence_refs 带 time_window 与 aggregate；时间镜头只报告候选事实，不产出"串标"定性——定性权属正兵，规则与状态机红线不变。

### 例 4：图像研判的草案闸门与降级（P6）

1. 一批报销发票照片入卷，vlm 镜头识别出"8 张发票销售方名称相同但发票专用章编码不一致"，生成 draft 线索（模型名、prompt 版本、模型分 0.87 独立字段），页面标"AI 草案待核"。
2. 正兵按图像核验 playbook 比对原件，确认印章伪造 → 通过核验动作，ActionExecutor 创建 obj_image_evidence 并链接到涉案 org。
3. 该证据成为普通语义对象：自动出现在关系图谱该 org 节点下，自动进入研判报告"书证"段；后续按确定性规则计分（不使用 0.87 模型分）。
4. 演练：拔掉网络/API 限流 → vlm 镜头 degraded 留痕、草案线索超过 TTL 标 stale（不参与当期升格），资金/关系/时间/五间全部照常出结果（fallback=deterministic_only）；镜头作用域仅含脱敏数据，尝试读取未遮蔽证件/轨迹字段被拒绝。

### 例 5：底座纯粹化的直接收益（P4→P6）

P6 新增 obj_image_evidence 时，objects.json 只声明 pk/kind/属性与 binding，**不被要求填写任何 jian 标签、不因间类白名单硬失败**；五间包是否给它映射（如归"死间"）是五间包自己的配置选择。底座对"五间""图像"均无感知，两套研判学说可同案并存、互不污染。

### 例 6：任务指挥与镜头授权回收（P1/P2 后）

1. 正兵围绕新主体"王某"展开调查：调度器按 relation 镜头 params_schema 校验后下发 `{target_subject: "王某", depth: 3}`——未在 schema 声明的参数被拒，镜头据此返回王某三跳圈层，evidence_refs 自动上图进报告。
2. 第三方 VLM 服务合同到期：移除 packs/vlm 目录（或 enabled=false），其访问凭据立即失效，历史草案作为审计记录保留但不再调度；系统其余镜头与底座无任何变化——接入是可单方面收回的授权。

## 8. 验收与防复发机制

1. **每阶段准出**：138 组测试全绿（WSL venv）；MCP 改动加跑 `python -m scripts.mcp_client_test`；新测试组同步注册 GROUPS。
2. **口径守卫**：P4 前后做两次 Golden Finding 全量比对（test_golden），交叉等级/评分/溯源行数不一致即阻断发布。
3. **契约守卫**：新增静态检查——所有镜头返回必须为 `[LineageClue]`；非 draft 镜头不得写模型分；evidence_refs 引用的对象/边必须存在（装载期校验，复用引用完整性测试模式）；params_schema 与下发参数双向核对，越权/缺参硬失败。
4. **降级可观测**：degraded/skill_failed/stale 必须出现在 RunHealth 产物与看板；新增"镜头健康度"面板（空转率、异常率、零命中率、陈旧线索数），复用 REQ-G-002/010。
5. **授权守卫**：镜头作用域最小化默认值、越权读取测试、凭据吊销演练纳入每阶段准出；pack 目录只接受经评审入库的包。
6. **红线回归**：已立案 human-only、写操作仅 ActionExecutor、Function 只读、LLM isolated 默认——每阶段全量回归，不随重构松动。
7. **复盘门控**：P3 后复盘 evidence_refs 契约、P6 后复盘镜头接入模板，再决定是否需要更高层抽象（无第三样本不泛化）。
