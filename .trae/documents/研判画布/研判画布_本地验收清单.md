## 五、已知失败（实测，需修复）

### 5.1 `test_canvas_api.py` — 5 项

根因两类：

**a) 物品节点 label 取错**

```
AssertionError: '待核实' != '核查微信图片来源'
tests/test_canvas_api.py:212
```

未锚定物品应显示「待核实」，实际显示的是任务名。
→ 影响：正兵看不到"这件东西身份没核实"，会当成已核实继续研判。

**b) 测试数据缺 `v1.duckdb`**

```
FileNotFoundError: 案件版本文件不存在：.../cases/c1/v1.duckdb
```

→ 影响：4 项用例拿不到版本数据。

### 5.2 `test_canvas_case_http.py` — 4 项

根因：端点要求 `ctx` query 参数，测试没传。

```
AssertionError: 404 != 422  {"detail":[{"type":"missing","loc":["query","ctx"]...}]}
AssertionError: 409 != 200  ...（第二次保存撞版本冲突）
```

**其中 409 那条要特别看**：上次修过"版本冲突返回 409 而非 500"，这条失败说明
**要么修复没生效，要么测试与实现对 ctx 的约定不一致**——需要二选一确认，不能都留着。

### 5.3 与本次改动无关的失败

`pyarrow` 缺失导致读 parquet 的用例失败（演示数据用 DuckDB 写 Parquet）。
装 pyarrow 有触发沙盒重置的先例，**建议在本地装**。

## 七、优先级建议

**第一优先：3.1 前端 vitest。** 前端从未真实运行一次，这是唯一未闭合的整块验证债；
其余后端项都有实测数字兜底。

**第二优先：§5.2 的 409 那条。** 它牵涉上次"版本冲突返回 409 而非 500"的修复是否真的生效——
如果没生效，正兵会看到"请求失败"而不是"已按最新版合并你的调整"，且会反复触发。

**第三优先：§5.1 物品 label。** 不显示"待核实"会让未核实物品被当已核实继续用，
属于会误导结论的那一类缺陷。

**E19/E20 不在本清单内**——它们还没写。要补的话是独立一轮。
