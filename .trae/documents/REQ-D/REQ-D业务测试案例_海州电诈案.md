# 业务测试案例：海州"11·03"刷单返利电诈团伙案

**定位**：REQ-D 全特性综合验收案（电诈域，对位贪腐域的华创文教案）。覆盖批 D0–D5 的验收标准；批 D6 相关项标 N-A。

**关联文档**：[REQ-D实施方案.md](./REQ-D实施方案.md)、[REQ-D.md](./REQ-D.md)

---

## 1. 案情背景

2025 年 1 月起，海州市反诈中心接报"刷单返利"电诈警情 23 起。嫌疑人以"某淘科技"为幌子引流，受害人资金经三级卡过桥归集。侦查员拿到三份原始数据：银行流水（导出系统带千分位/货币符）、通话记录（运营商原始格式）、外卖平台实名信息（复合字段），另有同案卷移交的身份材料。

**侦查假设**：过桥卡在资金归集期与固定收款账户存在高频毗邻；嫌疑人与引流窝点存在同址活动。

## 2. 数据集设计（`data/reqd_case/`，声明包 `ontology/reqd_case/`）

### 2.1 银行流水_电诈.parquet（120 行）

列：流水号 / 主体 / 对方 / 金额 / 日期 / 卡号 / 摘要

| 脏数据 | 行数 | 验收指向 |
|---|---|---|
| 金额 `￥1,280.50` / `48,000.00`（货币符+千分位） | 15 | 009 AC-1/3：transform 后可 CAST |
| 金额 `1.28e3`（科学计数法） | 3 | 009 已知边界：null + 诊断，不中断 |
| 金额负数 `-500` | 5 | 016 AC-3 |
| 金额 `9,999,999.99` 孤峰 | 1 | 020 AC-2 提示（N-A，批 D6） |
| 卡号 `6222-0212-3456-7890`（连字符） | 8 | 006 AC-2 |
| 卡号 `6222********7890`（星号遮蔽） | 6 | 006 AC-5 reject_if → quarantine |
| 卡号校验位错 | 4 | 016 AC-1 |
| 日期 `2025年1月6日` / `2025/1/6` / `2025.01.06` / `2025-1-6` | 10 | 009 AC-2 / 011 AC-1/3 |
| 日期 `2026-12-31`（未来） | 2 | 016 AC-4 |
| 日期 `2025-02-30` | 2 | B2-08 回归（TRY_CAST 降级 + 计数） |
| 流水号重复（内容略异）3 对 | 6 | 015（N-A，批 D6） |
| 摘要/对方含"商贸/科技/工作室"等组织词 | 40 | 008 AC-1/4（40/120=33% > 30% 阈值告警） |

### 2.2 通话记录_电诈.parquet（80 行）

列：主体 / 对端 / 日期 / 次数 / 对端号码_原始

| 脏数据 | 验收指向 |
|---|---|
| 电话 `138 0013 8000`、`+86 138-0013-8000`、`00861380013800` | 006 AC-1（有序多规则：先剥国家码再去非数字） |
| 非法号段 `12345678901`（12 位） | 016 AC-2 |
| 旧版变体表 `通话记录_旧版.parquet` 缺"对端"列 | B5-01 回归 + optional_columns 降级 |

### 2.3 人员身份_电诈.parquet（26 行）

| 设计 | 验收指向 |
|---|---|
| 身份证校验位错 6 行、17 位 3 行 | 016 AC-1 |
| 合法小写 `x` 结尾 2 行 | 016 AC-8 误报陷阱 |
| **两个"李强"**：电话/身份证/住址全异 | R-1 红线回归：禁止合并、强制 needs_review |
| "李  强"（含空格）与"李强"同一人 | 005 改值 + strip 后同代理键 |
| 人名 **"王银行"** | 005 AC-5 误报陷阱（org 关键词误剔护栏） |

### 2.4 案件台账_电诈.parquet

案件类别列含代码表外值 **"杀猪盘"** → 003 AC-3 / 016 AC-5。

### 2.5 银行流水_复合列.parquet（15 行）

`对方信息` = `张三|330108199001011234`（复合列）→ 013：**source_sql 上游拆分路径**与 **composite 整列降级路径**各验一次。

### 2.6 声明包 `ontology/reqd_case/`

| 文件 | 设计 | 探针 |
|---|---|---|
| `data_elements.json` | 注册 DE_IDCARD（含 checksum）/ DE_PHONE / DE_BANKCARD / DE_AMOUNT / DE_CASE_TYPE | 001 |
| `objects.json` | id_card 引用 DE_IDCARD（002）；amount 声明 `on_cast_error: quarantine`（010） | 002/010 |
| `policies.json` | **故意漏声明 id_card 遮蔽** → 预期 loader 硬失败并提示补声明；随后补上再验正常装载 | AD-5/002 AC-4 |
| `enum_space.json` | 从 DE_CASE_TYPE 派生，不手写人名 | 003 AC-2 |
| `bindings.json` | `exclude_org_tokens` 案件级词表切换为电诈词表（商贸/科技/工作室/引流） | 007 AC-5 |

## 4. 判定基线与 N-A 清单

| 判定 | 数量 | 说明 |
|---|---|---|
| PASS | 21 | 批 D0–D5 完成后应全过 |
| N-A | 3 | D-04（quarantine 未声明时降级为计数核对）、D-19/20（若复合列按整列降级路径则拆分探针转 N-A） |
| FAIL 触发 | 0 | 陷阱列（D-11/D-18）误报即判 FAIL |

**红线复验**（随案例一并核对）：

- 画像/健康度全部结论保留"待核实候选"定性（017 AC-4）
- 推荐只进 draft 提案，永不自动生效（021 AC-3）
- 扫描器零直读 Parquet、零业务写路径

## 5. 执行方式

```bash
# WSL，数据集就位后
wsl -u root -- bash -c "cd /mnt/d/dev/inves_duckdb && /root/.venvs/inves/bin/python -m scripts.init_duckdb"
# init_duckdb.py 新 parquet 必须相对路径挂载（data/reqd_case/xxx.parquet），确保 Windows/WSL 双侧可读

wsl -u root -- bash -c "cd /mnt/d/dev/inves_duckdb && /root/.venvs/inves/bin/python -m scripts.build_ontology --pack reqd_case"

wsl -u root -- bash -c "cd /mnt/d/dev/inves_duckdb && /root/.venvs/inves/bin/python run_tests.py --only reqd_case"
```

**产物固化**：案例固化为 `tests/fixtures/reqd_case.json` + `tests/test_reqd_case.py`（对位华创案 test_golden 模式，测试组注册进 run_tests.py GROUPS）。数据文件本身（parquet/xlsx）不入 git。
