# S0 结构地基实施计划（F1 三层 / F2 能力位 / F3 版本机制 / F4.2 分级提示）

## 背景

`docs/OM/ext/S0_结构地基_PRD.md` 是 S1–S5 的地基。四项中 F4.1（假承诺文案）已完成；本计划实施剩余三项半。核心问题：行业层无目录、无本体管理员能力位、快照版本建案后永不更新且审计记错版本（`record_config_audit` 把 data_version 计数器当 ontology_version 记进审计链）。

PRD 既定决策（D1–D10）与红线（R1–R6）全部照办：合并优先级固定 案件>行业>全域；历史只追加+存完整快照引用；能力位不改 rank；不迁移旧案件；meta.db 只追加式 ALTER。

## 实施步骤

### 批 1 — F1 loader：override 分支 + 行业包内容

1. [core/ontology_loader.py](file:///d:/dev/inves_duckdb/core/ontology_loader.py#L893-L906)：合并循环加 override 分支——后层元素声明 `override: true` 时覆盖前层同名 ID 并记录覆盖关系，否则维持硬失败；内部新 detailed 变体 `_load_data_elements_detailed() -> (merged, overrides)`，公开 `load_data_elements()` 签名不变（包一层）。核对 `_validate_element_spec` 对额外键 `override` 的容忍度，必要时放行该键（仅 boolean）。
2. 新建 `ontology/_industry/金融/{pack_meta.json, data_elements.json}` 与 `ontology/_industry/医疗/{...}`：pack_meta 至少含 `industry` 字段；数据元各 1 条最小集（`DE_FIN_*` / `DE_MED_*` 前缀防与 `_shared` 撞 ID；字段按 `_validate_element_spec` 要求），`reqd_case` 声明 `industry=金融`，其装载面会并入行业层——保持最小集以免污染既有断言。

### 批 2 — F2 能力位（照抄 is_admin 五件套）

1. [repo_sqlite.py](file:///d:/dev/inves_duckdb/server/app/meta/repo_sqlite.py)：`_SCHEMA` meta_users 加 `is_ontology_admin INTEGER NOT NULL DEFAULT 0`；`_migrate` 加 ALTER 追加块（老库只加列不重建，R6）；`_user` 行映射、`create_user` insert 列清单、`set_user_ontology_admin()` setter。
2. [models.py](file:///d:/dev/inves_duckdb/server/app/meta/models.py#L51-L61) User 加字段；[repo.py](file:///d:/dev/inves_duckdb/server/app/meta/repo.py) ABC 加 setter 抽象；security.py Principal + `ontology_admin_flag()`（is_ontology_admin=1 且非 system 场景判定辅助）；deps.py Principal 构造传字段；auth.py 登录响应带 `is_ontology_admin`。
3. [snapshot_config.py](file:///d:/dev/inves_duckdb/server/app/snapshot_config.py#L38-L42) 加 `require_ontology_admin(p)`：`system` 旁路；其余须 `is_ontology_admin=1 且 ROLE_RANK[role]>=ROLE_RANK["偏将"]`，403 文案按 PRD §8.5。本阶段无标准域写路由，门禁由单测覆盖（UC-S0-4/5/6）。
4. auth.py 加授权端点（`POST /users/{operator}/ontology-admin`，platform_admin_flag 门禁；set_user_admin 现无任何路由调用，一并补在同一个 users 管理小节或新建 routers/users.py——实现时选侵入最小者）。

### 批 3 — F1 server 侧：建案拷贝 + 校验副本补拷

1. [cases.py](file:///d:/dev/inves_duckdb/server/app/cases.py#L89-L96) `create_case`：按模板包 `pack_meta.industry`（复用 `_load_pack_industry`）拷 `ontology/_industry/{industry}` → `cases/<cid>/ontology/_industry/{industry}`；行业目录缺失降级两层不报错（E1-3/UC-S0-3）。
2. 各 temp 校验副本补拷 `_industry`：`snapshot_config.validate_snapshot`、model_designer `_validate_in_temp`、rule_workshop、views、etl、knowledge、access_config（同一模式：与 `_shared` 并列 copytree，存在才拷）。建议在 snapshot_config.py 提一个 `_copy_overlay_layers(base_dir, tmp_root)` 共享，逐路由替换，消重复。

### 批 4 — F3 版本机制

1. [cases.py](file:///d:/dev/inves_duckdb/server/app/cases.py#L31-L74)：`_FINGERPRINT_FILES` 加 `data_elements.json`；指纹范围扩为 包内文件 + 快照 `_shared/` 全部文件 + 快照 `_industry/{industry}/` 全部文件（industry 从快照包 pack_meta 解析，缺失跳过）。
2. meta 层：`pack_snapshot_history` 表（`_SCHEMA` CREATE TABLE IF NOT EXISTS，老库自动建）字段 case_id/version/prev_version/operator/reason/changed_files(JSON)/snapshot_ref/created_at；models.py 加 dataclass；repo.py ABC + sqlite 实现 `append_pack_snapshot_history` / `list_pack_snapshot_history`；`refresh_pack_snapshot(case_id, version, locked_at)` UPDATE case_pack_snapshots。
3. [snapshot_config.py](file:///d:/dev/inves_duckdb/server/app/snapshot_config.py) 新增 `commit_ontology_write()`：调用方在 atomic_write_json 前捕获写前字节；写后 重算指纹 → 归档（包声明+_shared+_industry 拷到 `cases/<cid>/ontology_history/<version>/`）→ 插历史行（prev_version=旧指纹）→ refresh PackSnapshot → `record_config_audit`（显式传新指纹；data_version 计入 summary 双记，UC-S0-11）。**任一步失败：恢复写前字节 + 清理归档目录 + 抛 5xx**（E3-2 原子性）。no-op 保存（新指纹==旧指纹）跳过归档/历史/refresh，仍记审计（防 (case_id,version) 唯一键冲突）。
4. `record_config_audit` 加显式 `ontology_version` 参数；7 个调用点全部改接 `commit_ontology_write`（rule_workshop 保留其 RESCAN 入队逻辑不动）。
5. `create_case` 写首条历史（version=建案指纹，prev_version=null，reason="建案快照"，PRD 待确认#4 采纳）；建案三写无跨表事务，**历史写失败降级 ops 留痕不阻断建案**（E3-2 回滚只约束编辑写）。
