# 孙武侦查官 ontology_v2 详细实施方案

> 基于《对照 Palantir 优化方案》《Palantir 闭环机制对照》两份报告，拆解为 **46 个可独立测试的需求（REQ-001 ~ REQ-046）**。
> 每个需求含：现状 / 目标 / 设计 / 验收标准（AC，可自动化）/ 测试命令 / 依赖 / 风险。
> 编号规则：`REQ-0xx` P0 止血、`REQ-1xx` 未用（统一连续编号）、P1 = REQ-022~040、P2 = REQ-041~046。

## 0. 总纲

### 0.1 三条不可交易的红线（写进代码，不写进 prompt）

| 红线 | 强制点 | 兜底机制 |
|---|---|---|
| R-1 确定性执行只认只读 Function | 执行层分为 `ReadOnlyFunction` / `DerivedProperty` / `ActionEffect`，LLM 工具表只暴露前者 | capability token，无权限工具不存在于调用表 |
| R-2 每条推断挂可解析 `source_rows` | `Finding/Clue/Hypothesis/Explanation` 共享 `evidence` 结构 | 写入前 validator 校验，空即硬失败 |
| R-3 AI 不出定性结论 | `level` 字段只能由规则或人生成，默认 `待核实`；`已立案` 需 `set_filed(legal_basis)` | schema 层禁止模型写 `level` / `status` |

### 0.2 阶段目标

| 阶段 | 目标 | 需求数 | 工作量 | 完成判据 |
|---|---|---|---|---|
| P0 | LLM 尚未接入时也无法破坏正确性 | 21 | 46 人日 | §0.3 全绿 |
| P1 | 规则可维护 + LLM 草案层上线 | 19 | 57 人日 | §0.4 全绿 |
| P2 | 类型、检索、真实回写、多案件 | 6 | 26 人日 | §0.5 全绿 |

### 0.3 P0 出口判据（全部必须自动化）

1. 更新源数据后不重建语义层 → 相关查询被拒绝或自动失效，**不返回旧快照**
2. 所有 `finding` / `decision` 的 `source_rows` 非空，且可按 `case_id + version` 精确重取
3. 越权操作者无法经 API / MCP / 导出读取受限对象或属性（CI 含正负例）
4. Action 或外部回写失败 → 保留 outbox 与审计，**不静默丢事件**
5. 篡改 / 重放审计事件 → 哈希链校验发现
6. 现有 8 组测试迁移 CI；至少一个 case fixture 的 finding 结果与版本绑定

### 0.4 P1 出口判据

1. R5 在**零硬编码人名**下仍能命中受控 fixture
2. 阈值变化可由数据版本和参数集精确解释
3. 注入测试无法使模型直写 SQL、改状态或跳过 review
4. LLM 不可用时，系统功能与原版等价
5. 每条 LLM 解释都有 evidence coverage 报告
6. CI 在固定 seed 下可重放，产出 finding drift report

### 0.5 P2 出口判据

1. 每个新原生类型都有 source / transform / 权限 / 血缘测试
2. embedding 检索不得成为确定规则的唯一证据
3. 业务回写 dry-run 与生产执行结果一致
4. 案件间默认隔离
5. 性能瓶颈有量化基准

### REQ-001 语义层版本时钟与依赖图

| 项 | 值 |
|---|---|
| 优先级 | P0（**最先做**） |
| 工作量 | 3 人日 |
| 依赖 | 无 |
| 涉及文件 | `core/ontology_version.py`（新建）、`ontology/default/manifest.json`（新建） |

**现状**
`build_ontology()` 一次性全量物化 `obj_*` / `lnk_*`，无 watermark、无失效机制。`agg_subject_month` 被 `incremental.py` 更新而 `obj_*` 不变时，系统**不报错**，只是事实悄悄过期。

**目标**
建立"源权威"与"语义权威"的双 watermark，并让 stale 状态可被查询。

**设计**

```python
@dataclass(frozen=True)
class OntologyVersion:
    pack: str
    schema_version: int          # 来自 objects.json
    ontology_version: str        # 语义声明的 semver，如 "2.1.0"
    build_id: str                # uuid4
    built_at: str
    source_watermark: str        # 源端已读取并校验的最大事件时间
    ontology_watermark: str      # 语义层已物化的最大事件时间
    input_hashes: dict[str,str]  # {object_name: sha256(物化结果)}
    params_hash: str

def dependency_graph(pack) -> dict[str, list[str]]:
    # object -> [source tables]; link -> [objects]
```

落地 `data/ontology_state.json`（或 DuckDB 表 `meta_ontology_state`），每次 `build_ontology()` 写入一条。

**验收标准**
- [ ] AC1：`build_ontology()` 成功后，state 文件存在且 `source_watermark == ontology_watermark`
- [ ] AC2：手工把 `银行流水` 表插入一行后再次比对，`freshness()` 返回 `STALE`，且返回差异清单（受影响 object 名）
- [ ] AC3：`freshness()` 在 `STALE` 时返回非空 `affected_objects`；`FRESH` 时为空列表
- [ ] AC4：未构建过语义层时 `freshness()` 返回 `UNBUILT` 而非异常
- [ ] AC5：`input_hashes` 对同一输入两次构建结果一致（确定性）

**测试命令**
```bash
python -m pytest tests/test_ontology_version.py -v
```

**风险**：watermark 取"最大事件时间"时，若源数据含未来日期或回填历史，会误判。需 REQ-005 分区校验配合。

### REQ-002 OntologyReadGateway 单一读入口

| 项 | 值 |
|---|---|
| 优先级 | P0 |
| 工作量 | 4 人日 |
| 依赖 | REQ-001 |
| 涉及文件 | `core/gateway.py`（新建）、`core/store.py`（改） |

**现状**
`bindings.json` 的 object source 指向中文业务表（`"table": "银行流水"`），检测器理论上可绕过语义层直接查中文表——"不要自己写业务 SQL"只是纪律，不是架构约束。

**目标**
所有读路径经网关，网关返回 `{plan, data_version, materialization_state, applied_policies}`。

**设计**

```python
class OntologyReadGateway:
    def __init__(self, store, access: AccessContext, pack="default"): ...
    def objects(self, name: str) -> ObjectSet:      # 仅接受 objects.json 中已声明的 name
    def links(self, name: str) -> ObjectSet
    def materialization_state(self) -> str          # FRESH|STALE|UNBUILT
    def explain(self) -> dict                        # plan + versions + policies
```

- 对象名不在 `objects.json` → `UnknownObjectError`（硬失败）
- `materialization_state == STALE` → `StaleOntologyError`，**禁止悄悄返回旧值**
- 稳定聚合可命中物化表；权限敏感 / 动态查询下推至 view

**验收标准**
- [ ] AC1：`gateway.objects("person")` 返回行；`gateway.objects("银行流水")` 抛 `UnknownObjectError`
- [ ] AC2：标记 STALE 后再查，抛 `StaleOntologyError`，**不返回数据**
- [ ] AC3：`explain()` 输出含 `ontology_version`、`source_watermark`、`applied_policies` 三个键
- [ ] AC4：走网关与直查 `obj_person` 的结果集完全一致（等价性测试）
- [ ] AC5：网关不接受任意 SQL 参数（无 `query(sql)` 方法，dir() 断言）

**测试命令**
```bash
python -m pytest tests/test_gateway.py -v
```

### REQ-003 直查拦截与 unsafe_debug 通道

| 项 | 值 |
|---|---|
| 优先级 | P0 |
| 工作量 | 2 人日 |
| 依赖 | REQ-002 |
| 涉及文件 | `core/store.py`（改）、`scripts/audit_straight_sql.py`（新建） |

**现状**
`store.query(sql)` 是无限制的公共方法。

**目标**
默认路径禁止直查业务表；保留显式 `unsafe_debug` 通道，但强制记录操作者、理由、行数上限。

**设计**

```python
_FORBIDDEN_TABLES = {"银行流水","通话记录","招投标档案","工商信息","轨迹出行","公开OSINT","举报材料"}

class Store:
    def query(self, sql, params=(), *, unsafe=False, reason=None, operator=None, max_rows=1000):
        if not unsafe and _touches(sql, _FORBIDDEN_TABLES):
            raise DirectSourceAccessError(...)
        if unsafe:
            if not (reason and operator): raise ValueError("unsafe 需 reason + operator")
            _audit_unsafe_write(operator, reason, sql, max_rows)   # 写审计表
            sql = _wrap_limit(sql, max_rows)
```

**验收标准**
- [ ] AC1：默认 `store.query("SELECT * FROM 银行流水")` 抛 `DirectSourceAccessError`
- [ ] AC2：`unsafe=True` 但缺 `reason` → 抛 `ValueError`
- [ ] AC3：`unsafe=True` 且齐全 → 正常返回，且 `meta_unsafe_query` 表新增一条记录
- [ ] AC4：`max_rows` 生效：查 10 万行只返回 ≤1000 行
- [ ] AC5：静态扫描全仓库，`core/` 与 `skills/` 下无绕过调用（CI 用 AST 检查）

**测试命令**
```bash
python -m pytest tests/test_store_guard.py -v
python scripts/audit_straight_sql.py --fail-on-violation
```

### REQ-006 事件总线与持久化事件日志

| 项 | 值 |
|---|---|
| 优先级 | P0 |
| 工作量 | 4 人日 |
| 依赖 | 无 |
| 涉及文件 | `core/event_bus.py`（新建）、`core/unit_of_work.py`（新建） |

**现状**
`run_all.py` 十步顺序执行，跑完即结束，无事件、无订阅、无重算入口。

**目标**
轻量事件总线（SQLite WAL 或 DuckDB 表），支持发布 / 订阅 / 重放 / 幂等消费。**不引入 Kafka。**

**设计**

```python
@dataclass(frozen=True)
class Event:
    event_id: str; type: str; occurred_at: str
    causation_id: str | None; actor: str
    payload: dict; payload_hash: str; schema_version: int

class EventBus:
    def publish(self, type, payload, *, actor, causation_id=None) -> str: ...
    def subscribe(self, type, handler, *, idempotency_key_fn) -> None: ...
    def replay(self, from_event_id=None) -> int: ...
```

事件类型清单（REQ-0032 详述）：`source.partition.arrived`、`partition.quarantined`、`ontology.stale`、`objects.materialized`、`finding.created`、`clue.status_changed`、`review.decided`、`proposal.created`、`action.approved`、`action.executed`、`writeback.failed`、`external.status_changed`。

**验收标准**
- [ ] AC1：发布事件可落盘，进程重启后仍可读取
- [ ] AC2：同一 `idempotency_key` 重复投递，handler 只执行一次
- [ ] AC3：`replay()` 重放后，系统状态与首次执行一致（确定性）
- [ ] AC4：`causation_id` 形成链，`A→B→A` 的循环可被检测到（深度 > N 告警）
- [ ] AC5：handler 抛异常不丢失事件，进入 `dead_letter`

**测试命令**
```bash
python -m pytest tests/test_event_bus.py -v
```

class AuditEvent:

- [ ] AC4：重放事件（重复插入）→ 检测为 False（`event_id` 唯一约束）

新增任何 handler（事件消费者 / LLM 草案器 / writeback adapter）时，必须覆盖：

| 场景 | 期望 |
|---|---|
| 重复事件 | 只处理一次（幂等） |
| 乱序事件 | 按 `causation_id` 排序或拒绝 |
| 空证据 | 不产生 finding |
| 权限不足 | 拒绝并记录审计 |
| 外部超时 | 进重试队列，不丢 |
| 外部 409 | 不重试，转人工 |
| 人工改判 | 触发受影响范围重算 |
| 回滚 | 状态可复原 |
| schema 变更 | 装载期失败，不静默 |

## 4.2 闭环风险 checklist

| 风险 | 控制手段 | 关联需求 |
|---|---|---|
| A↔B 死循环 | `causation_id` + score delta 阈值，重建不自动创建新 finding | REQ-006 / REQ-016 |
| 级联放大 | 影响集上限 + 批处理 + 熔断 | REQ-018 |
| 反馈污染 | feedback 分 `tentative` / `confirmed`，双人复核 | REQ-031 / REQ-032 |
| 自动化漂移 | 批准策略版本化，定期回退抽样人工复核 | REQ-032 |
| 写回不一致 | outbox + 幂等键 + receipt + 对账，禁止静默覆盖 | REQ-013 / REQ-014 |
| 审计链失效 | `prev_hash` + 周期根哈希 | REQ-007 |
| 数据出网 | 本地优先、最小字段、PII 映射、输出扫描 | REQ-038 |

## 4.3 明确劝退清单（不要做）

| 劝退项 | 理由 |
|---|---|
| 完整 CBAC / Markings 体系 | 配置、分类学复杂；Palantir 官方亦说明分类标记非默认启用 |
| Global Branching 全套 | 单人单机无协作规模，Git PR + CI 足够 |
| 分布式实时物化 | DuckDB + Parquet 无规模证据 |
| 多租户组织 RBAC | 案件包与用户数都小 |
| 任意 webhook 自动回写 | 侦查业务系统接口与审计要求各异 |
| 把所有计算改派生属性 | Palantir 官方亦指出中小规模有运行时开销 |
| 全量非结构化语义检索 | 当前主要是模拟数据与结构化线索 |
