## 1. 修订记录

| 项 | 原版方案 | 本版优化 |
|---|---|---|
| 地址归并 | 坐标网格 ~50m + 路名主干文本轨 | 双段归并键：`admin_path`（省/地/县/乡）+ `路名主干` |
| 编码通路 | 高德在线单轨（缺省降级） | **三轨**：①区划离线匹配（零网络、县/乡级质心）→ ②高德在线（门牌级）→ ③人工标注 |
| 覆盖率兜底 | 无编码即 NULL | 含行政区划的文本可离线定位到县级精度，覆盖率提升 |
| 同名误并 | 50m 网格兜住 | `admin_path` 前缀约束更早拦截（区县不同即不并） |
| 区划数据 | 无 | 民政部五级区划库入 `data/ref/`，location 实体新增五级属性 |
| 实现策略 | 无外部依赖 | **取数据 + 重写实现**（区划匹配器按 `core/geo.py` 纯函数风格自写，不复制 AGPL 源码） |

```

                              │
                              ▼  未命中行政区划或 confidence 低于阈值
┌─────────────────────────────────────────────────────────────┐

│  ─────────────────────────────────                           │

│                                                             │

                              │
```

#### 区划离线匹配器（重写实现）

**设计约束**：不复制 `admin_standardizer.py` 源码，参考其算法思想（多级后缀剥离、上下文约束、核心名提取），按 `core/geo.py` 纯函数风格重写。

核心函数（全部纯函数、只读、无网络）：

| 函数 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `parse_admin_path(text)` | "安徽省黟县宏村镇宏村" | `{province:"安徽省", county:"黟县", township:"宏村镇", remaining:"宏村"}` | 基于 suffix 集合从长到短匹配剥离；直辖市特殊处理 |
| `match_admin_level(name, level, context)` | name + 上级 context | `MatchResult` | exact → alias → core → prefix → fuzzy 五级链；context 约束过滤同名 |
| `admin_centroid(admin_code)` | 区划码 | `(lat, lng)` | 查预置县/乡镇质心表（离线 CSV） |
| `geo_encode_address(text)` | raw_address | `{lat, lng, admin_path, admin_code, source, confidence}` | 编排以上函数；三轨调度入口 |

**数据依赖**：
- `data/ref/province.csv`（31 条）
- `data/ref/prefecture.csv`（333 条）
- `data/ref/county.csv`（2800+ 条）
- `data/ref/township.csv`（4 万+ 条）
- `data/ref/village.csv`（70 万+ 条，可选——村级命中低、体积大，P1 可只到乡镇级）
- `data/ref/admin_centroid.csv`（县/乡镇级质心，从标准库坐标均值生成）

**性能**：
- 区划库懒加载 + 索引（exact_index / alias_index / core_index），同 `ReferenceTable` 思想；
- 结果缓存：`(name, context_key)` → result，避免重复匹配；
- 地址先唯一化再匹配，调用量从 N 行降到 K 个唯一值。

#### `scripts/geocode_locations.py` CLI 设计

```bash
python scripts/geocode_locations.py \
  --operator 张卫国 \
  --purpose "空间研判-轨迹地点编码" \
  --yes \
  --source trackpoint        # 从 obj_trackpoint.location 取待编码地址
```

流程：
1. 读 `obj_location` 中 `lat IS NULL` 的行；
2. 轨道 1：区划离线匹配（所有行，零网络）；
3. 轨道 2：未命中行调高德 API（需授权 `--yes`）；
4. 写 `data/geocode_cache.parquet`（列：raw_address/std_address/lat/lng/admin_path/admin_code/coord_sys/source/confidence/geocoded_at）；
5. 审计日志：operator/purpose/耗时/命中分布（轨道 1/2/未命中）。

### 3.5 归并双轨（升级版）

| 优先级 | 归并键 | 条件 | 示例 |
|---|---|---|---|
| 1 | `admin_path + std_address` | 区划离线命中 | 同区县同路名 → 同一 location_id |
| 2 | `grid_key(lat, lng, 50m)` | 有坐标（高德/质心） | 坐标近邻 → 同一 location_id |
| 3 | `std_address`（路名主干） | 无区划无坐标 | 纯路名匹配 |

**同名拦截**：「滨江路」在 A 区与 B 区，因 `admin_path` 不同，自然分为两个 location，无需坐标即可区分——这是原版方案风险 3 的根本修复。

### 3.6 验收标准

- `python -m scripts.build_ontology` 后 `obj_location` 物化成功，`admin_path` 非空率 ≥ 区划离线匹配覆盖率；
- 无 geocode_cache 时 build 不报错、坐标可为 NULL 但 `admin_path` 应已填充；
- 同名地点跨区县不并（`count(location_id WHERE std_address='滨江路') = 区县数`）；
- policies.json 漏声明时访问被拒；
- 新测试组 `geo`：归并幂等、grid_key 边界、三轨降级、区划上下文约束。

### 4.3 Function 清单

| name | impl | 说明 |
|---|---|---|
| `geo_subject_sites` | py | 主体落脚点集：target_subject → trackpoint JOIN obj_location，输出 `{std_address, lat, lng, 到访次数, 首末日期, admin_path}`；无坐标行用 admin_path 降级标注 |
| `geo_co_located_radius` | py | 距离阈值同框：补强 `lnk_co_located` 的文本硬 join（bindings.json L225 脆弱点），坐标对 ≤radius_m 判同框，无坐标回落 `admin_path` 文本轨（同区县判近邻） |
| `geo_buffer_scan` | py | 缓冲区分析：中心点 + 半径环带（内环/外环），列出环带内事件与主体——缓冲区理论「住所紧邻区反而低发」的排查工具 |
| `geo_profile_cgt` | py | Rossmo CGT 概率面：输入系列事件点集，网格化输出概率面 + 优先排查区清单。**确定性分段函数**，事件数 < min_events（缺省 5）直接降级 |

### 4.4 CGT 实现要点

- **坐标来源优先级**：高德 lat/lng > 区离线质心 > 县级质心 > 无坐标排除；
- **网格键**：复用 `grid_key(lat, lng, grid_meters)`；
- **缓冲区项**：以已知 anchor（如住所/工作单位）为中心，内环低发带（f < 1）正常，外环高发带（f > 1）异常；
- **距离衰减项**：事件点到网格中心距离按 Rossmo 公式加权；
- **输出**：GeoJSON FeatureCollection + 优先区清单（按概率分降序，截断上限 60）。

### 4.5 rules.json 新规则

```json
{
  "id": "R-GEO-1",
  "stage": "xu_shi",
  "title": "系列事件空间聚集画像",
  "dimension": "behavior",
  "jian_types": ["死间"],
  "rule_text": "同一主体关联的 5 起及以上事件在空间上呈聚集分布，且聚集区外缘存在缓冲区特征（紧邻常驻点的环带内反而无事件）时，符合掠夺者型空间行为模式，可用地理画像产出优先排查区域。产出是排查优先级区域而非定址结论；事件不足 5 起或坐标覆盖率过低时本规则降级不命中，不得以缺口充数。定性权归正兵。",
```

### 6.3 授权闸口设计

- **默认隔离**：未授权时不注入任何 `<script src>` / 瓦片请求，页面显示「离线模式」+ 坐标清单表格；
- **显式授权**：视图顶部横幅「加载在线地图将连接高德服务器」→ 用户点击确认后动态注入 JS API，授权状态存 localStorage（可撤销）；
- **与内核权限面解耦**：内核 `SUNZI_NETWORK=isolated` 约束的是服务端/LLM/编码脚本；浏览器渲染瓦片是用户本人的浏览行为，授权闸口独立；
- 高德 Key 存 `frontend/.env.local`（gitignore），不进库。

### 6.4 图层

1. 概率面热力层（CGT GeoJSON → 高德 Heatmap/多边形渐变）；
2. 缓冲区圆环（内环低概率带 + 外环排查带）；
3. 事件点/落脚点标记（点击弹溯源卡 → 跳线索详情/观察档案，复用 evidence_refs）；
4. 坐标覆盖率提示（「12/20 个地点已编码」+ 引导跑编码脚本）。

### 6.5 验收

## 8. 风险与开放问题

| 编号 | 风险 | 缓解措施 |
|---|---|---|
| R1 | CGT 适用场景错配（面向系列侵财/人身案，非招投标职务案） | rule_text 写明适用条件 + min_events 降级 + 输出措辞只给「优先排查区域」 |
| R2 | 区划离线匹配覆盖率不及预期（非标地址、历史地名） | 三轨兜底：区划离线 → 高德在线 → 人工标注；`degraded_reason` 透传 |
| R3 | 区划库体积大（村级 70 万+）导致加载慢 | P1 可先只加载到乡镇级（4 万+），村级按需扩展；懒加载 + 索引 |
| R4 | 乡镇级质心坐标精度不足（影响 CGT 概率面） | 标注 `geocode_confidence` 较低，CGT 函数内加权；优先用高德坐标 |
| R5 | AGPL 合规边界（区划库 CSV 来自 AGPL 项目，但数据本身是民政部公开数据） | CSV 数据本身无版权限制；代码全部重写，不复制 AGPL 源码 |

### 8.1 开放问题

1. **location 实体是否要挂到 person 的「常住地」语义（lnk_person_resides）？**  
   本期不做——等 P1 数据跑出来看清分布再定。
2. **村级区划库是否必须 P1 就加载？**  
   建议 P1 只到乡镇级（4 万条，内存友好），村级命中率低（79.7% 规则基线）且体积大（70 万条），可延后到 P2 按需扩展。
3. **区划离线匹配是否提供 SQL Function（走 functions.json）还是纯 py Function？**  
   纯 py Function——区划库不在语义层，编译期 SQL 无法 JOIN 离线 CSV；`core/geo.py` 中 `AdminMatcher` 直接读 `data/ref/` CSV。
