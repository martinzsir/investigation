

# 鲁棒性测试案例：冒充公检法诈骗团伙

**定位**：本案例不验证系统"能否破案"，而是验证系统在脏数据、边界值、数据缺失、权限约束面前，是否会崩溃、误报、静默失败或越权。

**设计原则**：每个陷阱对应一处已识别的架构薄弱点，期望行为明确可判定。

**判据口径**：失败标准不是"没查出线索"，而是"系统在不该出错的地方出错了"。

---

## 一、案由

2024 年 3 月起，滨江省连续发生冒充公检法电信诈骗案。受害人接到冒充"公安局"的电话后转账。侦查发现存在专门取款的车队，驾车在多地 ATM 取现后流窜。

- 已立案 3 起（进案件表）
- 另有 12 条 110 报警记录（进警情表），大部分尚未串并
- 核心人物：组织者陈立（绰号"立哥"）、车手赵鹏（绰号"阿鹏"）、孙浩（绰号"胖子"）
- 取款用车两辆，均存在登记人与实际使用人分离

**分组设计**

| 组 | 条数 | 内容 | 意图 |
|---|---|---|---|

**陷阱**

- T2.1 G1 与案件表重复入口
- T2.2 G2 无立案、无人工关联
- T2.3 G3/G4 为误报
- T2.4 地址含"万达那个超市旁边""XX路口往东大概两百米""就那个建行"
- T2.5 时间格式三种混用：`2024/3/15`、`2024年3月15日`、`2024-03-15 14:30`

**期望断言**

| 编号 | 断言 |
|---|---|
| AC2.1 | G1 的 3 条与对应案件去重，不得报出重复线索 |
| AC2.2 | G2 的 7 条至少进入枚举候补池，产出"手法相同"串并假设 |
| AC2.3 | G3、G4 不产生线索；若产生，须标注为待核实且可溯源到误报判据 |
| AC2.4 | 无法解析的地址（T2.4）标记为降级，进健康度小节，**不得静默丢弃** |
| AC2.5 | 三种时间格式归一后能参与时间窗计算；解析失败的记录单独降级标注 |

## 三、两项结构性考验

### 3.1 S1：可选属性缺列

**构造**：轨迹表**故意不设**"数据来源系统"列，但在 `bindings.json` 中声明该属性。

**观测**：系统硬失败，还是降级标注后继续运行。

| 编号 | 断言 | 关联需求 |
|---|---|---|
| ACS1.1 | 可选属性缺列应降级标注（`source_column_missing`，warning）而非硬失败 | REQ-G-025 |
| ACS1.2 | 缺列诊断进入健康度小节并可检索 | |
| ACS1.3 | 必填属性缺列仍保持硬失败（边界验证，不得一并放宽） | |

### 3.2 S2：规则互斥留痕

**构造**：设计两条规则同时命中同一批 ATM 取款记录——"整数取款"与"跨省取款"。

**观测**：抑制是否生效，被抑制方是否留痕。

| 编号 | 断言 |
|---|---|
| ACS2.1 | 同组规则互斥生效，主列表仅保留 primary |
| ACS2.2 | 被抑制规则保留 `suppressed_log`，写清：谁抑制的、依据哪条 `overlap_resolution`、被抑制的候选与溯源行 |
| ACS2.3 | 下次查询可回答"为什么没看到跨省取款线索" |

## 四、五维观测表

跑完后按此表逐项检查，**而非看"查出几条线索"**。

| 维度 | 检查项 | 失败判据 |
|---|---|---|
| **不崩溃** | 脏数据（无效日期、缺列、类型错乱、超长字段）不导致管线中断 | 任一单一数据源异常阻断了其余分析 |
| **不误报** | 重名不合并；边界外不算入窗口；样本不足不虚报强度；误报警情不产线索 | 出现任一误报 |
| **不静默** | 零命中区分四类；所有跳过进健康度汇总；健康度在结论之前 | 存在无痕迹的失败 |
| **不越权** | 未声明权限拒绝访问；不同角色遮蔽程度不同；异常线索不参与交叉等级 | 出现默认放行或异常升格 |
| **可追溯** | 每条处置落持久链（含操作人、法定依据、本体版本）；空链不返回"正常" | 链为空却 `chain_ok=true` |

## 五、通过判据

本案例通过，不看查出什么，而看系统有没有在不该出错的地方出错：

1. 遇脏数据能跑完并说清哪里降级了
2. 遇重名能拒绝自动合并、推给人裁决
3. 遇边界值能明确标注口径
4. 遇样本不足宁可降级，不虚报强度
5. 遇闲置数据源能主动指出"这份数据没被用上"
6. 遇无法解析的地址，宁可标注"我没看懂"，也不假装"查过了没问题"

**最重要的一条**：跑完后，健康度报告中出现的每一条降级、跳过、缺口，都必须能对应到本文档某个具体陷阱。**若某个明明存在的陷阱在系统里毫无痕迹——那才是真正失败的测试。**
