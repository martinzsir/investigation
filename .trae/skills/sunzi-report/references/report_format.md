# 研判报告 · 十段格式契约

> 本文件是**格式契约**：段名、内容要求、可写主体（Agent / 脚本 / 人）三列固定。
> 违反「可写主体」列即为错误用法。

## 段落总表

| # | 段名 | key | 可写主体 | 内容要求 |
|---|---|---|---|---|
| 一 | 线索概况 | `overview` | Agent | 案件/线索标识、时间范围、核心问题一句话 |
| 二 | 证据充分性 | `sufficiency` | **脚本（确定性）** | 五间覆盖、交叉等级、覆盖缺口 |
| 三 | 命中规则与判据 | `rules` | Agent | 命中的规则、判据原文、阈值 |
| 四 | 事实与依据 | `facts` | Agent | 逐句陈述，每句带 `[cite:ref]` |
| 五 | 关联核验 | `correlation` | **脚本（确定性）** | 过桥路径、规则手册、Function 复核 |
| 六 | 研判推断 | `inferences` | Agent | 分「有据推断」与「推测」两组 |
| 七 | 待核实事项 | `pending` | Agent | 无据句自动转入 + 人工补充 |
| 八 | 书证清单 | `evidence` | Agent | 已固证书证，含来源与固证时间 |
| 九 | 数据源清单 | `sources` | **脚本（确定性）** | 数据文件、上传批次、目标数据集、登记行数、案件库/本体包版本、本线索画布引用源与溯源行数 |
| 附录 | 引用索引 | `citations` | 渲染生成 | 编号 / 引用 / 摘要 |

## 关键约束

### 1. 确定性段不得改写

第二段、第五段、第九段由 `gather_evidence.py` 产出。即便 `sections.json` 提供同名段也**被忽略**。

> 理由：让 LLM 复述交叉等级会引入幻觉，且与内核结果不一致；数据源清单
> （文件/批次/行数/版本）若由 LLM 凭行标签拼凑，会出现漏写、错配批次
> 等不可复现问题。三者统一走登记口径确定性采集。
> 项目原则：LLM 只负责编排与表达，不碰计算、不登记数据来源。

### 2. 无据句自动转入待核实

事实段每句必须带引用。无引用句由 `validate_citations` 转入第七段，
并标注「以下表述因缺乏引用已转入待核实」。

**禁止给无据句补引用**——宁可转入待核实。

### 3. 推断必须分两组

```
**有据推断**（有引用支撑）
- …[cite:ref]

**推测**（未经核实，仅供参考）
- …
```

推测组强制标注，不得与有据组混排。

### 4. 降级必须声明

`evidence.json` 的 `降级` 数组非空时，报告头部生成「降级声明」块。

**特别地**：覆盖缺口为 `null`（未知）时，不得呈现为「无缺口」。
文案固定为「未知（内核未就绪，未能计算）」并附说明。

## 三类受众的段落取舍

| 段 | A 研判 | B 汇报 | C 移送 |
|---|---|---|---|
| 一 线索概况 | ✅ | ✅ | ✅ |
| 二 证据充分性 | ✅ | ✅ | ✅ |
| 三 命中规则 | ✅ | ✅ | ✅ |
| 四 事实与依据 | ✅ | ✅ | ✅ |
| 五 关联核验 | ✅ | ❌ | ❌ |
| 六 研判推断 | ✅ | 仅有据部分 | ❌ |
| 七 待核实 | ✅ | ✅ | ❌ |
| 八 书证清单 | ✅ | ✅ | ✅ |
| 九 数据源清单 | ✅ | ✅ | ✅ |
| 附录 引用索引 | ✅ | ✅ | ✅ |

**C 类**由 AI 整理已固证素材，不含定性结论。定性权属于办案人。

## sections.json 字段

```jsonc
{
  "overview": "…",
  "rules": "…",
  "facts": "…[cite:R1]",
  "inferences": "**有据推断**\n- …\n\n**推测**（未经核实）\n- …",
  "pending": "…",
  "evidence": "…",
  "citations": [{"cite_id": 1, "ref": "R1", "summary": "…"}]
}
```

`sufficiency`、`correlation`、`sources` 键**不需要填**（填了也会被忽略）：
第二/五/九段分别由 evidence 的「证据充分性」「关联核验」「数据源清单」块确定性渲染。
