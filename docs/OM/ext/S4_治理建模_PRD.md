## 二、背景与问题定义

### 2.1 现状实测（写本 PRD 前核查的结论）

| 文件 | 现状 | 页面 |
|---|---|---|
| `policies.json` | 可写 | `PolicyMaskingView.vue`（373 行）—— **纯 textarea** |
| `actions.json` | 🔒 **只读** | 无页面 |
| `states.json` | 🔒 **只读** | 无页面 |
| `llm_policy.json` | 🔒 只读 | 无（**永不开放**） |

**`actions.json` 实测内容 —— 已是完整 Palantir Action Type 形态**：

```jsonc
{"name":"file","title":"立案","target_status":"已立案",
 "only_from":["查证中"],"requires_role":"human","terminal":true,
 "side_effects":["set_clue_status","create_decision"],
 "parameters":[{"name":"legal_basis","required":true}]}
```

有终态、有前置态、有角色门禁、有必填参数、有副作用。

> **这是本项目「已实现未暴露」的又一例：声明能力完全到位，却只能改文件。**

### 2.2 用户痛点

| # | 痛点 | 本 PRD 对应功能 |
|---|---|---|
| P1 | 遮蔽策略写在 JSON 里，改错一个 key 可能导致**该遮蔽的没遮蔽** | F1 策略编辑器 |
| P2 | Action Type 完全不可见，改一次要动文件 | F2 Action Type 编辑器 |
| P3 | 状态机转移规则隐性，终态可能被改出可出口 | F3 状态机编辑器 |

### 2.3 为什么治理类最危险

| 文件 | 改错的后果 |
|---|---|
| `policies.json` | 敏感数据泄露（fail-closed 语义退化） |
| `actions.json` | **不具备资格的角色拿到终态权限**（如非 human 角色能「立案」） |
| `states.json` | 已结案状态可被转出，审计链断裂 |

> **S4 的每条红线都对应一个"改错了会出事"的真实场景，不是流程洁癖。**

## 四、术语

| 术语 | 定义 |
|---|---|
| **策略（policies）** | 对象级 / 属性级 / 角色级的可见性与遮蔽规则 |
| **fail-closed** | 未声明即拒绝 —— 项目默认语义，与 Palantir 的「打了 Marking 才受保护」相反 |
| **Action Type** | 可执行的业务动作（如立案/固证），含 `only_from` / `target_status` / `terminal` / `requires_role` |
| **终态（terminal）** | 一旦进入不可再转出的状态（如「已立案」） |
| **密级（clearance）** | 角色可见性上限（见习 0 / 正兵 1 / 偏将 3 / human 3） |

## 六、功能详情

### F1 策略编辑器（1.0 人日）

**F1.1 三级切换**

| 级别 | 说明 |
|---|---|
| 对象级 | 整个对象的可见性 |
| 属性级 | 单个属性的可见性与遮蔽 |
| 角色级 | 角色 → 密级映射 |

**F1.2 属性级表格字段**

| 列 | 控件 |
|---|---|
| 对象 | 下拉（从 `objects.json` 读） |
| 属性 | 下拉（从选中对象的 properties 读） |
| 角色下限 | 下拉（见习/正兵/偏将/human） |
| 遮蔽 | 下拉（`none` / `partial` / `full`） |

**F1.3 fail-closed 提示常驻**

底部固定提示条（文案见 §8.2）——这是本项目的**安全默认值**，必须让用户始终看见。

### F2 Action Type 编辑器（1.5 人日）

**F2.1 表单字段**

| 字段 | 控件 | 危险标记 |
|---|---|---|
| `name` | 文本框，已有项**不可改** | — |
| `title` | 文本框 | — |
| `target_status` | 下拉（从 `states.json` 读） | — |
| `only_from` | **勾选组**（从 states 读） | — |
| `terminal` | 勾选框 | 🔴 **危险字段** |
| `requires_role` | 下拉（角色枚举） | 🔴 **危险字段** |
| `parameters` | 可增删行（名称/类型/必填） | — |
| `side_effects` | 勾选组（现有副作用枚举） | — |

**F2.2 🔴 危险字段门禁**（P2 的红线解法）

修改 `terminal` 或 `requires_role` 时：

1. 必须弹出**危险确认**对话框
2. **理由必填**（不可为空）
3. 弹窗内明确显示「改前值 → 改后值」
4. 审计留痕（复用现有 `reason` 机制）

**F2.3 一致性校验**

| 校验 | 处置 |
|---|---|
| `target_status` 不在 `states.json` 中 | **阻止保存** |
| `only_from` 含不存在的状态 | **阻止保存** |
| 终态动作的 `target_status` 在 states 中非终态 | **警告**（不一致但允许，因 states 可能后改） |

### F3 状态机编辑器（0.5 人日）

**F3.1 展示**

- 状态列表 + 转移关系（文本链 + 简图）
- 终态用 🔒 标出

**F3.2 编辑**

- 新增/删除状态
- 编辑合法转移目标
- 🔴 **终态不得被设为可转移出**（硬阻止，见 §7 R3）

## 七、红线与硬约束（源自核查，非偏好）

| # | 红线 | 依据 | 违反后果 |
|---|---|---|---|
| **R1** | 🔴 `policies.json` 编辑**不得导致 fail-closed 语义退化** | 项目默认「未声明即拒绝」比 Palantir 更严，这是取证场景的正确取舍 | 敏感数据泄露 |
| **R2** | 🔴 修改 `terminal` / `requires_role` **必须危险确认 + 理由必填** | Action 管的是立案/固证等终态动作，改错会让**不具备资格的角色拿到终态权限** | 越权终态操作 |
| **R3** | 终态**不得被设为可转移出**（硬阻止） | 已结案状态可被转出 = 审计链断裂 | 审计失效 |
| **R4** | 🔴 **`llm_policy.json` 永不开放 Web 编辑** | 它是出网前的最后一道闸，不能把闸门钥匙交给被闸门管的人 | 出网内容失控 |
| **R5** | `target_status` / `only_from` 引用不存在的状态 → **阻止保存** | 引用悬空会在运行时炸 | 运行时崩溃 |
| **R6** | 未知字段**原样保留 + UI 提示** | 沿用 S2 R2 | 静默数据丢失 |
| **R7** | 保存反馈**不承诺「自动触发」**，除非确已入队 | 沿用 S0 R3 | 假承诺 |

## 八、文案规则

### 8.1 通用规则

- 危险字段必须**视觉突出 + 文字说明**，不只靠颜色
- 危险确认弹窗必须显示「改前 → 改后」对照
- 所有文案不承诺未执行的行为

### 8.2 fail-closed 常驻提示（F1.3）

> 「⚠️ **fail-closed**：未在此声明的对象/属性一律拒绝访问。这是本系统的安全默认值 —— 漏配的结果是「看不到」，不是「被看到」。」

### 8.3 Action 危险确认文案（F2.2）

以修改 `requires_role` 为例：

> 「🔴 **危险操作：修改角色要求**
>
> 动作：`file`（立案）
> 角色要求：`human` → `偏将`
>
> 此改动将允许**偏将**职级执行「立案」这一**终态动作**。
>
> 请填写变更理由（必填）：
> [________________________]
>
> [取消] [确认修改]」

修改 `terminal`：

> 「🔴 **危险操作：修改终态标记**
>
> 动作：`file`（立案）
> 终态：☑ 是 → ☐ 否
>
> 取消终态后，「已立案」将**可被再次转出**，已结案件的状态可能被更改。
>
> 请填写变更理由（必填）：…」

### 8.4 终态保护提示（F3.2 / R3）

> 「🔒 「已立案」是终态，不可设置转出目标。如需变更，请先取消其终态标记（该操作需危险确认）。」

### 8.5 引用校验失败（R5）

> 「🔴 目标状态「已起诉」不存在于 `states.json`。请先在状态机中创建该状态。保存已被阻止。」

### 8.6 `llm_policy.json` 只读提示（R4）

> 「🔒 `llm_policy.json` 不提供 Web 编辑界面 —— 它是出网前的最后一道闸。」

### 8.7 未知字段提示（R6）

> 「本动作有 1 个界面未覆盖字段（`xxx`），已原样保留。」

## 九、状态机

### 9.1 策略编辑器

```
加载中 → 就绪 / 空 / 错误
就绪 → 编辑单元格 → dirty → 保存中 → 已保存 / 保存失败
```

| 状态 | 说明 |
|---|---|
| `就绪` | 表格渲染 |
| `dirty` | 有未保存变更 |
| `保存中` | 校验 + 临时目录 + `load_pack` |
| `保存失败` | 校验失败 / 装载失败 |

### 9.2 Action 编辑器（含危险态）

```
就绪 → 编辑 → dirty
         ├─ 改了普通字段 → 保存确认（普通）
         └─ 改了危险字段 → 🔴 危险确认（理由必填）→ 保存中
                                    └─ 理由为空 → 阻止，停留在确认弹窗
```

| 状态 | 说明 |
|---|---|
| `编辑中` | 有变更 |
| `待普通确认` | 未触及危险字段 |
| 🔴 `待危险确认` | 触及 `terminal` / `requires_role` |
| `理由校验失败` | 理由为空 → **阻止提交**，弹窗不关闭 |
| `保存中` / `已保存` / `保存失败` | 同通用 |

> **理由为空时弹窗不关闭** —— 关闭等于放弃变更，用户会以为已提交。

### 9.3 状态机编辑器

| 状态 | 说明 |
|---|---|
| `就绪` | 状态与转移渲染 |
| `编辑转移` | 增减转移目标 |
| `终态保护触发` | 试图给终态加转出目标 → **硬阻止** + §8.4 |

## 十、异常与边界处理

| 编号 | 场景 | 处置 | FAIL 判据 |
|---|---|---|---|
| E1-1 | 策略引用了不存在的对象/属性 | **警告不阻止**（本体先改则策略后补，是常见顺序） | 硬失败 |
| E1-2 | 遮蔽值超出枚举（`none`/`partial`/`full`） | **阻止保存** | 保存成功 |
| E1-3 | `policies.json` 含未知字段 | 原样保留 + 提示 | 丢失 |
| E1-4 | 策略被清空（空对象） | 🔴 **警告**：所有对象将不可访问（fail-closed） | 静默接受 |
| E2-1 | 改 `requires_role` 未弹危险确认 | 🔴 违反 R2 | 未弹窗 |
| E2-2 | 危险确认中理由为空点确认 | **阻止**，弹窗保持打开 | 弹窗关闭或提交成功 |
| E2-3 | `target_status` 引用不存在状态 | **阻止保存** + §8.5 | 保存成功 |
| E2-4 | `only_from` 含不存在状态 | **阻止保存** | 保存成功 |
| E2-5 | Action 含未知字段 | 原样保留 + 提示 | 丢失 |
| E2-6 | 删除被 `side_effects` 引用的动作 | **警告 + 列出引用** | 静默删除 |
| E3-1 | 给终态加转出目标 | **硬阻止** + §8.4 | 加成功 |
| E3-2 | 删除被引用的状态 | **阻止** + 列出引用该状态的 Action | 删除成功 |
| E4-1 | 试图 Web 编辑 `llm_policy.json` | 🔴 **不可能**（无入口，无写路由） | 出现编辑界面 |

> **E1-4 值得注意**：策略清空在 fail-closed 下意味着「全部不可访问」而非「全部可访问」——方向是安全的，但仍需告知用户，否则会误以为系统坏了。

## 十一、权限

| 动作 | 要求 |
|---|---|
| 查看治理文件 | 案件可访问 |
| 编辑**案件域** `policies` / `actions` / `states` | rank ≥ 偏将 |
| 编辑**标准域**治理配置 | `is_ontology_admin=1` **且** rank ≥ 偏将 |
| 改 `terminal` / `requires_role` | 上述权限 **+ 危险确认 + 理由必填** |
| 🔴 编辑 `llm_policy.json` | **任何人、任何方式均不可**（R4） |

> **危险字段的权限不额外加严**，但**流程加严**（理由必填 + 留痕）。理由：这类改动低频但高危，加权限会阻塞，加流程能留证据。

| UC-S4-15 | 给终态「已立案」加转出目标 | **硬阻止** + §8.4 | 加成功 |
| UC-S4-16 | 删除被引用的状态 | **阻止** + 列出引用 Action | 删除成功 |
| UC-S4-17 | 查 `llm_policy.json` | 显示 🔒 + §8.6，**无编辑控件** | 有编辑控件 |
| UC-S4-18 | 从原 PolicyMaskingView 入口进入 | **仍可用**，功能不回退 | 不可用 |

> **UC-S4-9 是本 PRD 最重要的用例** —— 「理由留空时弹窗关闭」会让用户以为已提交，是最典型的静默失败。
>
> **UC-S4-8 / UC-S4-10 成对测**：前者验弹窗出现，后者验理由真的进了审计。只测弹窗不测审计，等于门禁形同虚设。
