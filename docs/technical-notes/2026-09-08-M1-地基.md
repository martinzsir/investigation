## 一、需求背景

孙武侦查官内核（core/ + DuckDB + LadybugDB，纯离线 CLI）已就绪，但**无 Web 服务端**：多案件隔离、元数据持久化、任务异步执行、版本化文件、HTTP 认证/信封等基础设施均缺。M1 目标是在**不破坏既有 CLI/MCP/脚本路径**的前提下，搭出 Web 服务端地基，达成端到端最小闭环：登录 → 建案 → 入队 BUILD → Worker 构建新版本 → 原子切换 → 只读可见。

核心约束：**server 外最小影响**——M1 对存量代码仅 2 处追加式改动；服务端开库纪律由 grep 门禁测试强制，不靠改写存量 11 处无参 `Store()` 与 3 处脚本直连 `duckdb.connect`。

### 关键调用链

```
登录 → POST /api/v1/auth/login（PBKDF2 校验 → session 表 → token）
     → 后续请求 Authorization: Bearer <token> → deps.get_principal → AccessContext(network="web")

建案 → POST /api/v1/cases
     → cases.create_case：建 cases/{cid}/ 目录 + 复制 pack 到 ontology_snapshot/
     → snapshot_manifest.json（objects/links/bindings/rules 等 8 文件 sha1 指纹）
     → meta: case 行 + version_pointer 行（v0 待建）

构建 → POST /api/v1/cases/{cid}/tasks（task_type=BUILD，idem_key）
     → worker/pool.claim_task（同案无 RUNNING 才认领）
     → worker/tasks.handle_build
         → 复制 vN → v{N+1}.duckdb（保冷层 parquet 相对路径视图）
         → build_ontology(write_conn, pack="ontology_snapshot", base_dir=cases/{cid})
         → 成功 → meta 单事务 UPDATE version_pointer（原子切换 H1~H4）
         → 失败 → 删半成品，vN 完好
     → SSE /api/v1/tasks/{tid}/events 推送 progress_pct/stage

读 → GET /api/v1/cases/{cid}/...（data_version 随响应）
   → StoreFactory.for_case(mode="read") 开当前版本只读连接
```

## 四、关键实现要点

### 1. Store 抽象与开库门禁（W-001/002/003，D-M1-1/2/3）
`StoreBackend` ABC 五方法（read_conn/write_conn/query/version/case_id）。`CaseStore(mode="read")` 连接为只读（`open(..., read_only=True)`），写操作直接失败；`CaseStore(mode="write")` 开读写连接。`CrossCaseStore` 骨架 write_conn 抛 `UnsupportedOperation`（ATTACH 留 M5）。

**核心设计**：server 全程消费裸 conn 喂内核（`build_ontology(conn, ...)`），不构造 `core.store.Store`。grep 门禁两条硬断言强制纪律：`server/` 树内 `Store()` 命中 0；`server/app/` 除 `store/` 外 `duckdb.connect` 命中 0。破线即红。

### 2. 元数据层 SQLite-WAL（W-004）
`repo_sqlite.py` 515 行：WAL pragma + busy_timeout=5000 保证单写者并发。任务表 `(case_id, task_type, idempotency_key)` UNIQUE 实现幂等。`version_pointer` 强一致读写（单事务 UPDATE 原子切换）。元数据不可用时明确报错（不静默降级）。

### 3. 案件快照锁定（W-005，D-M1-4）
`create_case` 复制 pack 声明到 `cases/{cid}/ontology_snapshot/`，生成 `snapshot_manifest.json` 存 8 个声明文件（objects/links/bindings/rules/functions/actions/views/policies）的 sha1 指纹。`build_ontology(conn, pack="ontology_snapshot", base_dir=cases/{cid})` 装载快照——loader 零改动（`base_dir` 形参透传）。共享本体变更不影响已建案件；快照篡改（指纹不符）装载时报错。

### 4. 版本化文件与原子切换（W-007，D-M1-5）
BUILD 在 `cases/{cid}/` 内生成 `v{N+1}.duckdb`：MVP 策略**复制 vN 后重建语义层**（保冷层 parquet 相对路径视图与附属表）。成功才在 meta 单事务内 UPDATE version_pointer（指针切换原子，无半成品可观测窗口）。失败删半成品，vN 完好。旧版本标记 pending_reclaim 不删除（延迟回收 M2 实现）。

### 5. 任务队列与 Worker（W-006）
两级调度：全局并发 N（默认 2）+ 案件级 FIFO 串行。`claim_task` 原子校验同案无 RUNNING 任务才认领。状态机 PENDING→RUNNING→SUCCEEDED/FAILED/CANCELLED。progress_pct/stage 写入（阶段边界 + 节流）。指数退避内聚于 `pool._fail`（base×2^n），语义错误白名单（缺列/权限/声明非法不重试）。未知任务类型 fail-closed。

### 6. FastAPI 骨架与访问层（S1~S6）
- **S1** `/api/v1` 前缀统一挂载
- **S2** CORS 中间件按 `SUNZI_CORS_ORIGINS` 白名单、默认关闭
- **S5** `GET /api/v1/health` 免认证探针（版本/元数据层状态/Worker 心跳）
- **S4** `DEGRADED_WRITE_REJECTED` 错误码（降级态写/导出拒绝 409）
- **D7** SSE 全程 Bearer 鉴权，不开 Cookie/query-token 旁路
- **D5** 会话构造 `AccessContext(network="web")`，`can_llm_call()` 允许 LLM 调用
- 统一信封 `{ok,data,data_version}` / `{ok,error:{code,message}}`；错误码 401/403/404/409/422/503

## 六、踩坑记录与偏差

1. **core/ 改动 2 处（计划估 1 处）**：除 `access.py NETWORKS += "web"` 外，`ontology.build_ontology` 需增可选 `base_dir` 形参透传 loader（loader 本已支持 base_dir，build_ontology 未转发）。缺省 None 行为完全不变，存量调用零改动——这是案件快照包构建的必要挂钩。
2. **versionswitch 组合并**：计划中的版本切换独立组并入 `taskqueue`（H1~H4 与 Worker 执行同批验证，含真实 build_ontology + 模板库冒烟）。
3. **模块归并**：重试/指数退避未单建 `retry.py`，内聚于 `worker/pool.py`（`_fail` + 内存退避时刻）；认证基元在 `server/app/security.py`（PBKDF2/token/Bearer）+ `routers/auth.py`，未建 `server/app/auth/` 包。
4. **pack 版本凭据**：`snapshot_manifest.json` 存声明文件指纹（objects/links/bindings/rules 等 8 文件 sha1 前 12 位），内容变指纹变，兼作快照完整性基线。
5. **BUILD v1 初始化**：支持 `--template investigation.duckdb` 模板库复制（保 parquet 相对路径视图/附属表）；无模板时写连接自动建空库。
6. **门面化推迟**：原计划 `core/store.py` 门面只读化将波及 101 处调用点，M1 改为 server 全程裸 conn + grep 门禁，最大回归风险由此消除；门面化推迟 M2（处置端点需 store 协议时），`server/app/store/` 结构已预留。

## 七、依赖变更

- 新增 `fastapi`、`uvicorn`、`httpx`（TestClient 用），均为纯 Python 包，WSL venv 国内镜像安装
- 密码哈希用标准库 `hashlib.pbkdf2_hmac`，不引入新依赖
- 不引入 sqlalchemy（SQL 直写 + Repository 封装，与"声明是数据、实现是代码"风格一致）

## 八、遗留与后续（M2+）

- **Store 门面化**：M1 server 消费裸 conn，`core/store.py` 未门面化；M2 处置端点需 `DisposalBoard(store=)` 协议时落地（CaseStore 鸭子适配或补门面）。
- **state.sqlite 审计链迁移**：M1 只有 platform_audit（meta），案件级审计链（state.sqlite）属 M2。
- **版本延迟回收**：M1 旧版本只标记 pending_reclaim 不删除，读者引用计数已登记，完整回收（W-009）属 M2。
- **业务端点**：线索/仪表盘/处置/规则工坊一律 M2/M3。
- **跨案件 ATTACH**：CrossCaseStore 骨架 write 抛 UnsupportedOperation，ATTACH 留 M5。
- **Postgres 实现**：Repository 方言预留，SQLite-WAL 为 M1 实现。
