## 一、需求背景

M1（案件生命周期/任务队列/BUILD）与 M2（治理仪表盘/审计时间线/版本回收/state.sqlite 骨架）交付后，Web 平台尚未具备**研判主流程**的完整闭环：数据只能由人工预置 Parquet、检测只在 CLI `run_all.py` 中跑、线索无 Web 读面、处置只能走 MCP、规则无法在界面编辑。M3 目标是把「数据接入 → 语义构建 → 线索检测 → 线索读面 → 处置 → 审计 → 规则迭代」串成端到端 Web 闭环，同时守住三条禁令（不写业务 SQL、不搬明细进上下文、不下定性结论）。

## 二、方案设计（五个决策点）

| 决策 | 推荐项 | 落地位置 |
|---|---|---|
| D-M3-1 写路径接线 | core 定义 sink 窄协议、server 实现注入 | `core/audit.py` `ActionExecutor` `DisposalBoard` 加可选 `sink` 参数；`server/app/store/state_sink.py` `StateSink` |
| D-M3-2 线索产物 | 落 `cases/{cid}/artifacts/clues_v{N}.json`，随版本不可变 | `server/app/clues_artifact.py` `save_case_clues`；`server/app/worker/detect.py` `run_detection` |
| D-M3-3 处置写 | 仍入队（DISPOSE 快速通道，FIFO，不产版本文件） | `server/app/worker/dispose.py`；`routers/clues.py` `POST .../clues/{clue_id}/actions` 返回 202 |
| D-M3-4 规则写 | 写入案件快照 `rules.json`，调参/启停入队 RESCAN | `routers/rule_workshop.py` `PUT /cases/{cid}/rules/{rid}` |
| D-M3-5 旧审计链 | 时间线双源拼接（state 活链 + 版本文件历史链只读） | `routers/audit.py` `_state_timeline` + `AuditChain.readonly(..., backend="sqlite")` |

核心约束：core/ 仅追加式分派（可选参数注入、缺省即现状）；不引入双写；LLM 端点 M3 只交付守卫层（不接模型 SDK）。

### 关键调用链

```
上传 CSV → POST /sources/upload（嗅探+画像+暂存+注册）
        → POST /sources/{uid}/import（指纹判重+映射校验+入队 IMPORT）
        → worker/ingest.handle_import（写 cold/*.parquet + clean 落 bindings）
        → 链式 enqueue TASK_BUILD
        → worker/tasks.handle_build
            → mount_case_cold（CTAS 挂冷层到版本库）
            → builder（build_ontology 编译语义层 obj_*/lnk_*）
            → worker/detect.run_detection
                → run_rules(stage=None, base_dir=案件快照)
                → skills 适配转 LineageClue → 血缘去重/优先级
                → save_case_clues → artifacts/clues_v{N}.json
            → set_version（H3：检测失败则指针不前进）

处置 → POST /clues/{clue_id}/actions（file 前置校验 human+legal_basis）
     → 入队 DISPOSE → worker/dispose.handle_dispose
     → DisposalBoard(sink=StateSink) → ActionExecutor → state.sqlite

调参 → PUT /rules/{rid}（loader 临时副本强校验后原子落盘）
     → params/enabled 变更入队 RESCAN → handle_rescan → handle_build → v{N+1} 产物
```

## 四、关键实现要点

### 1. D1 写路径接线（D-M3-1）
`StateSink` 实现 core `sink` 协议（`record_action`/`record_audit`/`record_clue_status` 等），底层写 `cases/{cid}/state.sqlite`。`ActionExecutor` 优先写 sink（M3 起处置事件真值源），缺省 `sink=None` 回落 DuckDB 链（CLI/MCP 现状不变）。

### 2. 线索产物随版本不可变（D-M3-2）
`detect.run_detection` 在 `handle_build` 切版本指针**前**执行，检测失败视同 BUILD 失败（版本不前进、下次重试清理残留）。产物路径 `cases/{cid}/artifacts/clues_v{N}.json`，由 `save_case_clues` 原子写（临时文件 + `os.replace`）。线索读面/处置均消费此产物，不触发检测。

### 3. DISPOSE 快速通道（D-M3-3）
五动作（verify/confirm/exclude/file + 回退）经 `DisposalBoard` 状态机校验，写 `state.clue_disposal_status` 全量镜像（未处置行 status=待查）。`file` 动作前置红线：非 human 角色 403、缺 `legal_basis` 400、线索未到「已固证」入队后 Worker 返回 `ACTION_REJECTED`。幂等键缺省 `dispose:{clue_id}:{action}`。

### 4. 规则工坊（D-M3-4）
`PUT /rules/{rid}` 仅可改 `rule_text`/`params`/`enabled`，结构字段（function 等）不可改。写盘前用 `shutil.copytree` + `load_pack` 全量 loader 校验，不合法不落盘；合法则 `os.replace` 原子替换。`params`/`enabled` 变更入队 RESCAN（MVP=全量重跑产新版本），纯 `rule_text` 变更不触发。

### 5. LLM 守卫层（W-025）
`POST /rules/draft`：`llm_enabled=false` → 503 `LLM_DISABLED`；注入正则 `_INJECTION_RE`（中英 ignore previous/忽略以上/你现在是/jailbreak/DROP TABLE 等）→ 400；`model_output` 为 None → 503 `LLM_CHANNEL_UNAVAILABLE`（M3 不接 SDK，接缝测试用）；输出只许 `rule_text` 键（`_DRAFT_ALLOWED_KEYS`），含 function/params/sql/action 等 → 400 `LLM_OUTPUT_REJECTED`；永不写 `rules.json`。

### 6. 数据接入（W-010/012）
五格式（CSV/TSV/TXT、Excel、Parquet、JSON/NDJSON、SQLite）。指纹 = sha256(文件名|内容哈希|行数) 前 24 位。同指纹源已 `queued`/`imported` 即 409（判定在入队前，拒绝不产任务行）。`mount_case_cold` 用 CTAS `CREATE OR REPLACE TABLE "<table>" AS SELECT * FROM read_parquet(...)` 挂到版本库。clean 声明合并进引用该源表的 object binding 的 clean 数组，临时副本过 loader 校验后落盘。

### 7. 审计时间线双源（D-M3-5）
`GET /cases/{cid}/audit` 拼接 state.sqlite 链（M3 起处置真值源）+ 版本文件 DuckDB 历史链（只读追加），按 `occurred_at`/`seq` 归并排序，每条带 `chain_source`(state/version)。`POST /audit/verify` 以 state 活链自检。

## 六、踩坑记录

1. **reclaim 组失败**：`detect.run_detection` 硬调 `load_pack(pack, base_dir=...)`，但 reclaim 测试用 stub builder 不编译 ontology、快照目录不存在 → `FileNotFoundError`。修复：包快照缺失时降级为空产物（stub 场景；生产中 `build_ontology` 成功即包必在）。

2. **auditview 门禁失败**：`ingest_io.py` 最初用 `duckdb.connect()` 读上传的 SQLite 文件，触发「store/ 外不得直连 duckdb」门禁。改 `pandas.read_sql_query` + `sqlite:///` URI（升级 sqlalchemy 2.0.52），文件内无 `duckdb.connect(`/`sqlite3.connect(` 字面量。又因注释中含 `duckdb.connect(` 字面量被 grep 命中，改写注释措辞。

3. **statestore 门禁过期**：M2 门禁要求 `state_store` 仅被 `store/`+`tests/` 引用，M3 把 state 接进 `routers/`（audit/clues/dashboard 读面）和 `worker/`（dispose 写面）后越界。放宽边界为 `store/routers/worker`+`tests`，核心不变量仍是 `core/` 不得依赖 `state_store`（依赖方向 server→core）。

4. **指纹幂等语义**：初版同指纹即 409，导致 staged 重传被误拦。改为仅 `queued`/`imported` 状态拦截（staged 重传由任务幂等键去重），且查询排除当前 upload_id 自身。

5. **file 重试幂等键冲突**：file 因状态机失败占了缺省幂等键 `dispose:{cid}:file`，confirm 后重试 file 命中已失败任务。冒烟测试用显式 `idem_key="file-after-confirm"` 解决（设计预期：失败动作的重试需调用方提供新幂等键）。

## 八、遗留与后续（M4+）

- **增量检测**：RESCAN 当前为全量重跑（MVP），未引入 core 增量机制；后续可按 `rule_ids` 增量重算。
- **真实 LLM 接入**：W-025 当前只交付守卫层（503/注入/输出白名单），未接模型 SDK；`model_output` 为 None 即返回 503 `LLM_CHANNEL_UNAVAILABLE`。
- **线索筛选索引**：列表筛选当前在 `clues_view.assemble_list` 内存做，大数据量下需落索引。
- **MCP 写路径接线**：MCP 处置仍走 DuckDB 链，未切到 `StateSink`（D-M3-1 仅 Web 侧落地）。
