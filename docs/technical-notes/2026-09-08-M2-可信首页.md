> 日期：2026-09-08 ｜ 里程碑：M2 可信首页（REQ-W-008/009/018/023/024 + D1 state.sqlite 骨架）

## 一、需求背景

M1 交付了 Web 服务端地基（多案件隔离、元数据、任务队列、版本化文件、FastAPI 骨架），但**可信首页**所需能力缺失：旧版本只标 pending_reclaim 不删除（无延迟回收）、手工放置的版本文件无孤儿扫描、案件审计链无 Web 读面、平台操作无操作者身份审计、无治理仪表盘。同时 D1 决策要求在 M2 细化 `state.sqlite` 骨架与迁移方案。

M2 目标：补齐版本生命周期（回收+孤儿扫描）、审计双读面（案件链+平台审计）、治理仪表盘、state.sqlite 骨架。核心约束：**server 外最小影响**——core/ 仅追加式只读方法（不改既有函数签名/行为）；state 写路径接线推迟 M3（与处置端点同批）；`core/store.py` 门面化推迟 M3。

## 二、方案设计（三个决策点）

| 决策 | 推荐项 | 落地位置 |
|---|---|---|
| D-M2-1 审计只读 | `core/audit.py` 增 `AuditChain.readonly()` + `timeline()`（DuckDB 只读连接拒绝 CREATE，`AuditChain(conn)` 无法实例化，必须拆两步） | `core/audit.py` |
| D-M2-2 state 写路径 | **推迟 M3**：M2 只交 state.sqlite 骨架 + `import_from_duckdb()` 迁移演练，不接 ActionExecutor/写路径 | `server/app/store/state_store.py` |
| D-M2-3 空链红线 | 只改 API 契约不改 core：CLI 纯查询空链=完整（auditinteg 组）vs 平台案件空链=不完整（W-023 AC-4）是两个合法场景，裁决在 API 包装层 | `routers/audit.py` |

### 关键调用链

```
版本回收（W-008）：
ARCHIVE 任务 → worker/reclaim.handle_reclaim
  → 查 case_reader_lease（读者租约表，TTL 60s 兜底僵尸进程）
  → 单事务二次确认：版本状态=pending_reclaim 且无活跃租约
  → 删除 v{N}.duckdb（Windows 句柄占用失败仅告警，留待下周期幂等）
  → ops_events 记回收日志

孤儿扫描（W-009）：
run_worker 启动 → orphan_scan.scan(case_id)
  → 白名单 = case_version_history 所有版本 + 当前指针
  → cases/{cid}/ 内不在白名单的 v*.duckdb → 移至隔离区（TTL 可人工捞回）
  → --orphan-dry-run 只记 ops_events 不移动

案件审计（W-023，D-M2-1/3）：
GET /cases/{cid}/audit
  → StoreFactory.for_case(read) → AuditChain.readonly(conn, case_id)
  → .timeline(operator=, ...) 只读时间线（空链在 API 层判定"不完整"）
POST /audit/verify
  → chain_integrity() 自检（health=None → NullRunHealth 空操作，无写泄漏）

平台审计（W-024）：
登录/登出/401/403 → platform_audit 表（operator 身份全程绑定）
GET /api/audit/events → 仅管理员可读

治理仪表盘（W-018）：
GET /cases/{cid}/dashboard
  → dashboard.assemble(conn) 单连接单遍：
    health（RunHealth.readonly 健康度）
    diagnostics（诊断类别聚合）
    dual_coverage（资金/通讯双覆盖）
    todo（disposal.status_counts 待办；review 卡片 available=false 降级）
    ops（ops_events 摘要）
```

## 四、关键实现要点

### 1. 版本延迟回收（W-008）
读者租约是回收正确性基础：M1 进程内 `_readers` 跨进程不可见，回收判定一律以 `case_reader_lease` 表为准。租约 TTL 60s 兜底 API 进程崩溃的僵尸租约（僵尸期间旧版本晚删一个周期，安全方向偏保守）。租约校验与删除在 meta 单事务内完成，删文件前二次确认；文件删除失败仅告警不重试，留待下周期（幂等）。ARCHIVE 任务额外做归档压实。

### 2. 孤儿扫描（W-009）
白名单从严：有版本历史记录（任何状态）或等于当前指针的文件永不入隔离区。M1 之前手工放置的版本文件会被判孤儿——部署提示先跑 `--dry-run`。隔离区 TTL 可人工捞回。`run_worker` 启动序列单次执行，周期随回收器间隔（`--reclaim-interval`）。

### 3. 审计只读与空链红线（W-023，D-M2-1/3）
DuckDB 只读连接拒绝一切 CREATE，`AuditChain(conn)` 的 `__init__` 含建表 DDL 无法在只读连接实例化 → 拆 `readonly()` 类方法（跳过 DDL）+ `timeline()` 只读时间线。空链红线只在 API 包装层强制：CLI 纯查询运行空链=完整（auditinteg 组 REQ-G-025），平台案件空链=不完整（W-023 AC-4）——两个合法场景，裁决依据写入 auditview 组测试注释。

### 4. 平台审计与操作者绑定（W-024）
`platform_audit` 只记平台事件（login/logout/login_failure/authz_failure），与案件审计链分离不混表。登录失败三档 reason（missing_token/session_invalid/user_invalid）；403 非管理员访问 `/audit/events` 记 authz_failure。operator 身份全程绑定。

### 5. 治理仪表盘（W-018）
`dashboard.assemble` 单请求单连接单遍取数（各读面 O(诊断行数)），rows 默认 limit 200 可配，分页/筛选在 server 组装层内存过滤（诊断行 ≤ 千级）。任一节失败降级不阻塞整卡。**偏差**：`ReviewQueue.pending()` 是管道运行期内存构造，needs_review 候选无持久化表 → 仪表盘 `todo.review` 输出 `available=false` + 说明，M3 补真实读面。

### 6. state.sqlite 骨架（D1，D-M2-2）
`cases/{cid}/state.sqlite` per-case WAL 库，`audit_chain` 表与 DuckDB 逐列同构、签名算法复用 core。`import_from_duckdb()` 幂等迁移演练 + root_hash 断言。BUILD 任务不触碰 state（M3 接线时同样遵守）。写路径接线（ActionExecutor/DisposalBoard sink）推迟 M3。

## 六、踩坑记录与偏差

1. **core 改动 3 处（计划估 1 处）**：除 `audit.py readonly()+timeline()` 外，实测驱动追加 `RunHealth.readonly()`（建表 DDL 在只读连接失败）和 `disposal.status_counts()`（Web 无内存线索对象）。均为追加式只读，零改既有函数签名/行为。
2. **实体裁决待办卡片降级**（W-018 AC-5 一半）：needs_review 候选无持久化表，仪表盘 `todo.review` 输出 `available=false` + 说明，M3 处置端点接线时补真实读面。
3. **verify 端点 health.record 副作用**：只读路径 `AuditChain.readonly` → health=None → NullRunHealth 空操作（"诊断落 run_diagnostic 与仪表盘联通"在只读连接上不成立；行为安全，无写泄漏）。
4. **SERVICE_VERSION 保持 "M1"**：升版需改 `test_api_base.py` 断言（M2 存量改动清单不含该文件），随 M3 批次一并更新。
5. **W-024 埋点事件命名**：login / login_failure / logout / auth_failure（401 三档 reason）/ authz_failure（403）。
6. **孤儿扫描挂载点**：run_worker 启动单次执行 + `--orphan-dry-run`/`--orphan-ttl-days`；周期随回收器间隔由部署参数合并实现。
7. **grep 门禁扩展**：auditview 组（server/ 无 core Store 实例化；store/ 外无 duckdb.connect；sqlite3.connect 仅 repo_sqlite.py+state_store.py）+ statestore 组（state_store import 仅 store/+tests，无写路径接线硬断言）。
