# M6 前端配套端点实施总结

> 日期：2026-09-08 ｜ 里程碑：M6 前端配套端点补齐（REQ-W-P-001~017）
> Commit：待提交（branch `ontology_v2`）｜ 新增 18 个代码文件 +3548 行（7 组装器 + 6 路由 + 2 Worker + 3 测试组），另有 8 个 core 文件与 10 余个 server 文件增量修改

## 一、需求背景

《前端需求清单 v1.8》附录 F 盘点出**约 20 个后端缺口端点**（W-P-001~017），覆盖前端 09 处置看板、10 知识图谱、11 庙算工作台、07 数据画像、08 接入建议、21/22 质量页、18/19/20 数据治理配置、23b 门户、24 任务中心、25 系统设置共 12 个页面。M1~M5 已交付约 45 个端点，但这些缺口直接阻塞前端批次 2~4 联调。

M6 目标：按优先级分六阶段补齐全量端点（W-P-016 函数目录决策不实施——rules 响应已内嵌函数元数据，编号保留闭合 backlog）。核心约束：

- **routers/worker 不准直读 Parquet、不准直连 DuckDB**（storeback 门禁扫描 `server/app/`），一律经 `ctx.factory.for_case(cid, mode="read")` → `store.read_conn`；
- **写操作唯一入口 ActionExecutor**；业务面短频写（质检/推荐/取消/设置）落 per-case `state.sqlite`（WAL）或 meta 层，**不产 DuckDB 版本文件**；
- **core 改动纪律：仅追加 keyword-only 可选参数，缺省零行为变化**；
- 红线继承：validate 响应无 force/ignore/continue、heuristic 扫描不出 block、零隔离必给 empty_message、内间秩级过滤三处口径一致、llm_enabled 等红线键后端同样拒绝。

## 四、关键实现要点

### 1. core base_dir 透传与只读 gateway 缺陷修复（阶段 A）

web 展示读面（画像/质检/庙算 coverage）需要**以案件快照而非仓库 ontology 目录**求值，因此七文件追加 `base_dir` keyword-only 参数（缺省 None 回落既有解析，零行为变化——121 组存量测试先验证再开工）。过程中暴露 `ontology_version.py` 既有缺陷：`_ensure_meta_table` 无条件 `CREATE TABLE IF NOT EXISTS`，而 **read-only DuckDB 连接拒绝一切 CREATE**（即使表已存在）——修为先查 `information_schema.tables`，存在即 return。这是 core 修复（非 server 层规避），所有只读 gateway 路径受益。

### 2. 质检 severity 红线（W-P-008，D-M6-3）

四扫描结果到 checks 的映射是红线载体：合规扫描的 `by_property` 只有 deterministic 模式可出 `block`；新鲜度 age_days 超限出 `warn`；**敏感词与单位扫描恒 `suggest`**（启发式检测无权阻断），samples 只取 `evidence[].sample_masked`（脱敏值出参）。default 包 person/account 无数据元标签属性时端到端 checks 自然为空，红线行为由映射函数单测覆盖（test_140b）。

### 3. 快照配置写范式（W-P-011/012，D-M6-5）

未复用 `snapshot_config.save_config_json/validate_snapshot`——二者先 load_pack 校验**旧副本**再写新内容，等于没校验新内容（既有 bug；rule_workshop 曾自己内联过正确范式）。`_write_validated()` 统一实现：临时副本写**新内容** → `load_pack` 全量校验（失败 400 不落盘）→ `os.replace` 原子写 → `record_ops` 审计。data-elements 与 etl-pipeline 两个 PUT 共用。

### 4. validate 与红线四（W-P-012，D-M6-4）

映射预检从 `spec.object_bindings` 的 `projections((别名,源列,类型))` 派生 `declared{源表:{属性:源列}}`；对象属性集从 `spec.objects` 按 name 建索引取（object_bindings 键是对象名字符串，不是 ObjectType——踩坑 #5）。响应固定 `paths=[A_split_source_sql, B_degrade_column]`，测试显式断言序列化结果不含 `force/ignore/continue` 任何字样，且不落盘。

### 5. 平台设置的存储与审计（W-P-013/017，D-M6-6/7/9）

`settings_kv`(k PK/value_json/updated_by/updated_at/reason) UPSERT 存储；GET 合并缺省值。四条纪律缺一不可：admin 门禁（复用 audit.py 范式 + `authz_failure` 平台事件）、reason 必填、白名单外键 400、写后 `settings_change` 事件。`storage_root` 只在 GET 透出（部署路径不可经 API 改写）；`policies-thresholds` 响应带 note 明示"平台值仅用于新案默认，生效以案件快照为准"（D-M6-6，避免前端误以为改平台值会影响存量案件）。API 进程不内嵌 Worker 池，`/settings/health` 的 `pool_alive` 如实返回 false 并注明由部署侧监控。

### 6. 门户聚合与归档（W-P-015）

`portal_view.py` 纯函数聚合（state_map/chain_ok 由 routers 层传入——statestore 门禁要求 state_store 仅 store/routers/worker 可 import）。`archive` 端点：`require_analyst` + 状态机校验（IllegalTransition → 409）+ **已封存显式 409**（状态机对同态迁移放行，路由层必须自拦重复归档）+ 入队 TASK_ARCHIVE 版本压实（idem_key=f"archive:{cid}"）。

## 六、踩坑记录

1. **read-only DuckDB 拒绝一切 CREATE**：`CREATE TABLE IF NOT EXISTS` 表已存在仍报错。`ontology_version._ensure_meta_table` 改为先查 `information_schema.tables`。任何"只读连接建元表"模式都要规避。
2. **statestore 门禁**：`test_state_store.py` grep 门禁限定 state_store 仅 store/routers/worker 可 import，`portal_view.py`（server/app 根下）直接 import 即失败。重构：portal_view 只接收 `state_map/chain_ok` 入参，StateStore 开启移到 routers/cases.py。
3. **storeback 门禁**：routers 不得 `duckdb.connect`/读 Parquet。summary 端点取诊断连接必须走 `factory.for_case(cid, mode="read")` → `read_conn`，finally `store.close()`；未 BUILD 捕 `FileNotFoundError` 降级。
4. **snapshot_config.save_config_json 校验旧副本**：先校验再写等于没校验新内容。etl.py 内联 `_write_validated()`（临时副本写新内容后 load_pack）。
5. **object_bindings 键是对象名字符串**：`spec.object_bindings` 为 `dict[str, ObjectBinding]`，键不是 ObjectType；对象属性集需另从 `spec.objects` 按 name 建索引（否则 `'str' object has no attribute 'properties'`）。
6. **状态机对同态迁移放行**：`assert_case_transition` 中 `target == current` 直接 return（幂等语义），"已封存→已封存"不报错。重复归档必须在路由层显式拦截 409。
7. **cases 表主键列名是 `id`**：`list_pack_snapshots` join 写 `ON c.id=s.case_id`（想当然写 c.case_id 会 SQL 报错）。
8. **同文件多处 Edit 并行竞态**：对 main.py/settings.py 的多处编辑并行下发时部分编辑被回退（后写覆盖），导致 settings_router 注册丢失、`_put_scope` 签名半新半旧（TypeError）。教训：同一文件的多处修改必须串行，改完 grep 验证所有调用点一致。
9. **全量回归负载抖动**：首轮全量中 spec 组失败（719s 长跑），单独重跑 32 例全绿——长测试组在全量并发下有计时抖动，失败先单跑复核再定位。
