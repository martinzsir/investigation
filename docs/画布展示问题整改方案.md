## P0-1 泳道列名完全没有渲染（功能性缺陷，非样式问题）

**代码定位** `ResearchCanvas.vue`

- L255-275 `buildLaneNodes()`：head 伪节点写死 `type: 'rect'`，id=`lane:head:<x>`，
  `data: { lane: true, lanePart: 'head', label: lane.label }`。
- L1608-1610：图级别 `node.type = RESEARCH_CARD_NODE`；G6 v5 中**数据级 `type` 优先于图级默认**，
  所以 head 走内置 `rect`，自定义节点不生效。
- L1650-1653：`labelText: (d) => (d.data?.lane ? '' : d.data?.label ?? '')` —— 泳道一律空字符串；
  `subtitleText`（L1647）是 `research-card` 的自定义属性，内置 `rect` 不消费。

结论：head 节点被渲染成一个 `fill:'transparent'` + `stroke:'transparent'` + `lineWidth:0`
的 218×22 矩形（L1626-1638），**列名 100% 不可见**；色带存在但没有列标题，用户只能看到 5 条莫名竖带。

**改法**（保持 head 为内置 `rect`，最小改动）

1. `tokens.ts` 新增高对比泳道标签色（现有 `laneLabel:'#5A7484'` 对 `#051522` 仅 **3.8:1**，不达 4.5:1）：

```ts
// canvasTokens
laneLabel: '#5A7484',          // 保留：色带说明等三级信息
laneLabelStrong: '#9FB8C6',    // 新增：列头文字，≈9:1
```

2. `ResearchCanvas.vue` 节点样式映射放开泳道列头：

```ts
labelText: (d: G6Datum) => {
  if (!d.data?.lane) return d.data?.label ?? ''
  return d.data.lanePart === 'head' ? String(d.data.label ?? '') : ''
},
labelPlacement: (d: G6Datum) => (d.data?.lane ? 'center' : 'left'),
labelFill: (d: G6Datum) =>
  d.data?.lane ? canvasTokens.laneLabelStrong : canvasTokens.title,
labelFontSize: (d: G6Datum) => (d.data?.lane ? 13 : 12),
labelFontWeight: 600,
```

3. head 几何微调（L267-272）：`y: -66 → -96`、`size: [LANE_WIDTH, 22] → [LANE_WIDTH, 26]`，
   给列头留出与首行卡片 70px 的呼吸区，避免和第一张卡片压字。

**验收**：五列顶部出现「规则 / 事实 · 待核实 / 实体 · 研判 / 数据行 / 数据源」，
13px、`#9FB8C6`，缩放 0.6 时仍可辨。

## P0-2 初始视口把卡片压成小点（缩放过小 + 大片空黑区）

**代码定位**

- L1605 `autoFit: 'view'`：G6 按**全部元素 bbox** 缩放，包含 10 个泳道伪节点。
- L257-264 band 高度 `height = maxY + 30`（`maxY = max(n.y + 60)`），head 在 `y = -66`；
  列间距 `RANK_Y_GAP = 104`（`domain/canvas-layout.ts` L25）。
  节点纵向一多，bbox 高度轻松破千；实测卡片尺寸 186×50（`g6-card-node.ts` L35-36），
  bbox 约 1178×1000+，压进 1000×580 容器 → **缩放 ≈ 0.5**，12px 标题被压到 6px，
  就是截图里"节点像小点、文字看不清"的直接原因。
- L1781 `pushGraphData()`：`setData + render` 后只 `applyFocus()`，**不重置视口**；
  展开明细/切换视图后新节点常落在视口外，加剧"大片空黑"。

**改法**

1. 去掉 `autoFit: 'view'`，改由我们按"真实节点 bbox（排除 lane）"计算初始视口。
   在 `domain/` 新增纯函数（可单测，不依赖 G6）：

```ts
// domain/canvas-viewport.ts
export const VIEWPORT_MIN_ZOOM = 0.55   // 低于此值文字不可读
export const VIEWPORT_MAX_ZOOM = 1

export interface Box { minX: number; minY: number; maxX: number; maxY: number }
export function contentBox(nodes: readonly { x: number; y: number }[]): Box | null
export function fitScale(box: Box, viewW: number, viewH: number, pad = 48): number
// scale = clamp(min((viewW-2pad)/w, (viewH-2pad)/h), VIEWPORT_MIN_ZOOM, VIEWPORT_MAX_ZOOM)
```

2. `G6Instance` 接口（L96-110）补 `fitCenter?: () => Promise<unknown>`、
   `translateTo?: (p: [number, number]) => Promise<unknown>`；`mountGraph()` 在
   `await inst.render?.()` 之后调用 `applyInitialViewport()`：

```ts
await inst.render?.()
applyInitialViewport()     // zoomTo(scale) → fitCenter()
applyFocus(selectedNodeId.value)
```

3. `pushGraphData(next, { refit = false } = {})`：结构变更（展开/折叠/层开关）保持当前视口；
   **首次渲染、快照回滚、`compact ↔ full` 切换**传 `refit: true` 重新初始视口。

4. 「适应屏幕」(`onFit` L981) 改为走同一套 `fitScale`（而不是裸 `fitView()` 又把 lane 算进去）。

**验收**：任何线索打开画布，初始缩放 ≥ 0.55（卡片 ≥ 102×27px、标题 ≥ 6.6px→实际 12px×0.55≈7px 仍偏小，
故 `VIEWPORT_MIN_ZOOM` 建议取 **0.7**，必要时横向滚动）；内容整体居中，无单侧大片空白。

## P1-1 画布高度固定 + 缺状态栏

**代码定位** `.canvas-graph { height: 580px; min-height: 380px }`（L2066-2069）；
`ResearchCanvas` 已 `emit('loaded', { version, nodeCount, edgeCount })`（L1569），
但 `ClueDetailView.vue` L489 挂载时**没有监听**，这份计数被浪费。

**改法**

1. 高度自适应：`height: clamp(480px, calc(100vh - 300px), 900px)`。
2. 画布底部新增状态条 `.canvas-status`（`position:absolute; bottom:8px; left:12px; z-index:20`）：

   避免依赖 G6 变换事件名（版本差异风险）。
3. `ClueDetailView.vue`：`<ResearchCanvas ... @loaded="onCanvasLoaded" />`，把
   version/nodeCount/edgeCount 存进 ref，画作 Tab 标题徽标或状态栏用。

## P1-2 选中/焦点态在缩放下等于看不见

**代码定位** L1661-1671：`focus`/`selected` 只改 `stroke` + `lineWidth: 2`，
在 0.5 缩放下只有 1px 差异；`selected` 与 `focus` 样式完全相同，**分不出"焦点链上"和"已选中"**。

**改法**

```ts
state: {
  focus:    { stroke: canvasTokens.strokeSelected, lineWidth: 2, opacity: 1 },
  selected: { stroke: canvasTokens.strokeSelected, lineWidth: 3,
              shadowColor: canvasTokens.strokeSelected, shadowBlur: 12,
              halo: true },
  dim:      { opacity: canvasTokens.dimOpacity },
}
```

并在 `openNode()`（L751）里 `void inst?.focusElement?.(node.id)`（`G6Instance` 补签名），
打开抽屉时把选中节点居中 —— 解决"点了节点但它在视口外"的问题。

## 追加：焦点链路可读性（P0 已实施 / P1+ 待排期）

**现象**：点击假设后，跟踪链路因线过多看不清；链路横向过长既看不到全局、又无法引导层层挖掘。

**代码级根因**

1. `focusChain()`（原 canvas-view.ts）是**固定一跳**，`applyFocus()` 对链外元素只下发
   `dim`（`opacity 0.18`）—— **38 条边一条都没少画**，噪声主体是边不是节点。
2. `RANK_X` 五列铺开 1178px、槽距 104px，追溯链天然横跨整屏，"看全局"只能靠缩小。

**已实施（P0）**

1. `focusChain(doc, nodeId, hops = 1)` 改 BFS，返回 `depthByNode / depthByEdge`；
   `FOCUS_HOPS_MAX = 3`；hops 非法值（0/NaN/∞/超上限）回落 1 或 clamp 到上限。
2. 跳数分级渲染：新增 `hop1/hop2/hop3` 状态——
   节点 2.2/1.6/1.2px 描边、边 2.4/1.6/1.1px（第 3 跳加虚线 `[6,4]`）。
3. **链外边在固化焦点下直接不画**：新增 edge 状态 `hidden`（`opacity: 0`）；
   hover 临时焦点仍用 `dim`（降到 0.06）以保留结构感、避免鼠标移动时整图闪动。
   hover 恒 1 跳，单击固化后才按 `focusHops`（默认 2）展开。
4. 状态栏新增「焦点跳数 − 2 +」游标（仅固化焦点时出现），上限 3；
   节点计数改为 `节点 33 / 43`（当前投影 / doc 全量），消除与 Tab 上 43 的歧义。
5. **P1 传递节点折叠**（`collapseChain()`，纯函数 + 单测）：
   - 折叠条件：链内度=2、非焦点（depth≠0）、系统节点、非钉住、不在 `keep` 集合；
   - 产物：`visibleNodeIds / collapsedNodeIds / syntheticEdges`（含 `via` 顺序与端点跳数），
     合成边 id 前缀 `syn:`，标签「经 N 个中间节点」，常显标签（它是可点入口）；
   - 交互：点合成边 → 段内节点放回（`unfoldedNodeIds`）；工具栏「压缩链路」可整体关掉；
     状态栏提示「折叠 N 个过路节点」；换焦点/清焦点时清空展开记录；
   6. **P1 焦点路径条**（新增 `CanvasPathBar.vue`）：
   - 轨迹是**点击栈**而非列层级——记录用户实际走过的来路（`focusTrail: string[]`），
     重复命中同一节点时截断其后，来回点不会堆积；
   - 形态：`全部 › [规] 规则 · [实] 事实 · [行] 数据行`，每段带类型色点、可点跳转，
     点「全部」= 清焦点回全局；溢出（>4 段）折叠为「… 另有 N 层」只留最近几段；
   - 清空点：画布空白处点击、Esc、快照回滚；跳转时同步清空「手动展开的折叠段」；
   - 位置：画布左上角（图例在右上、状态栏在左下互不遮挡）；连线提示条下移到 46px 让位。

- 口径纪律：`collapsedChain` 与 `applyFocus` **都按 `renderDoc`（当前投影）算**，
     不能用 doc 全量——否则合成边端点可能是被投影隐藏的节点，G6 会因边引用
     不存在的节点而报错；`maxVia = 4` 防止一段吃掉过多上下文。

**实施备注（与方案稿的偏差）**

1. 泳道几何不是写死的 `y:-96`，改为 `laneGeometry(contentBox(nodes))` 贴着内容包围盒生成
   （列头在内容上方 34px、色带上下各外扩 30px），这样泳道不再把 fit bbox 撑大，
   也不用在节点整体下移时改常量。
2. 初始视口不依赖 G6 变换公式：`zoomTo(scale)` → `getViewportByCanvas(center)` →
   `translateBy(视口中心 - 当前位置)`，只用相对平移纠偏，mock/降级环境安全。
3. 图例折叠状态写进既有的 `canvas-view:<caseId>:<clueId>` 偏好对象（新增
   `legendCollapsed` 字段），不另开 localStorage key。
4. `VIEWPORT_MIN_ZOOM = 0.7`：完整视图展开全部数据行时内容仍可能超出视口，
   状态栏会显示"内容超出视口，拖拽浏览或点「适应屏幕」"。
5. **G6 v5 没有 minimap 插件**（v4 有、v5 `lib/plugins/` 下确认没有）：
   挂第二个 Graph 实例不划算（双倍渲染+双份事件），改用纯几何映射。
   `domain/canvas-viewport.ts` 加 `minimapFrame / minimapProject / minimapUnproject`，
   组件 `CanvasMinimap.vue` 只负责画与收点击。视口左上角用 `getCanvasByViewport([0,0])`；
   拿不到时按 `getViewportByCanvas([0,0])` 反推（v = c·zoom + t ⇒ c = −t/zoom）。
6. **聚合视图绕过投影**：它直接吃 `doc` 全量，「全局」本来就不该受简洁视图
   折叠影响。`canvas-overview.ts` 的 `buildOverview()` 只读派生、不回写，
   `currentG6Data()` 在 `overviewMode=true` 时切换；列胶囊沿用 `research-card`
   186×50 卡内布局（写死的，换尺寸会错位）。主干边线宽用 `overviewLinkWidth(weight)`
   开方映射（min=2, max=9），让中等权重也看得见、不被最粗那条吃掉。
7. **反向重边归一化**：`buildOverview` 把同一对列的反向边合成一条（方向信息
   丢失）——否则两条 cubic 曲线完全重叠，没法看。
8. **聚合视图下禁用 focus**：固点节点/hover/跳数游标都不下发（applyFocus 直接 return）；
   进入聚合自动清焦点；点列胶囊退出聚合并顺手打开对应层开关（否则退出后那层还是折叠的）。
9. **泳道下线**（用户反馈「泳道列头跟概览列胶囊冗余」）：
   - 删除 `buildLaneNodes()` + `LANES`/`LANE_WIDTH` 常量；G6 数据不再注入 10 个泳道伪节点；
   - 删 `laneGeometry` / `LANE_HEAD_HEIGHT` 引用；
   - G6 节点 style 函数去除 `d.data?.lane` 分支（size/radius/lineWidth/lineDash/stroke/cursor/
     pointerEvents/fill/chipText/dimDotColor/subtitleText/labelText/labelPlacement/labelFill/
     labelFontSize/badges），仅剩真实节点一条路径；
   - 节点 style 函数去掉函数包裹（radius/cursor/pointerEvents/fill/labelPlacement/labelFontWeight/
     labelMaxWidth/labelWordWrap 改为常量）；
   - `cardBadges()` 去掉 `if (data.lane) return []` 防御分支；
   - 删除 `canvasTokens.laneBand` / `laneLabel` / `laneLabelStrong`（三色都不再被引用）；
   - 列名职责改由「全局概览」列胶囊统一承载（5 个胶囊始终在画布上）；
   - 明细视图靠节点 X 方向对齐识别列（col x 间隔 220px 间距已能看出列分界）；
   - `isLaneId()` 与 `LANE_PREFIX` 仍导出但已无人注入 `lane:` 节点——保留作防御性过滤器
     （onNodeClick/onNodePointerOver/findNode/applyFocus 都留着这些 check，未来若有遗漏
     数据流也能兜住）。
10. **P3 研判视角——证据强度三层**：
   - 新增 `domain/canvas-layout-tier.ts`：纯函数 `tierOf(n)`（已锁死 / 待核实 / 推测 三层分类）
     + `layoutByTier(doc)`（按 tier 重排 y，x 沿用 RANK_X；钉住节点保留原 y；纯函数）
     + `tierCounts(doc)` / `TIER_LABELS` / `TIER_3_OPACITY = 0.55` / `tierStyleHint(n)`；
   - 分类规则：`stale` → 3；`adopted` → 1（覆盖 kind 猜测）；未采纳 `hypothesis`/`note` → 3；
     系统锚点 `rule`/`fact`/`evidence` → 1；其余（实体 / 数据行 / 建议项）→ 2；
   - 流程 vs 证据强度是两条独立正交轴：「流程」问数据从哪儿来，「证据强度」问有多可信——
     切换不改 x，只重排 y（带内 `TIER_Y_GAP=92`、`TIER_BAND_GAP=220` 分带）；
   - `laidOutDoc` 是新中间层：`renderDoc → laidOutDoc → graphDoc`；顺序保证折叠
     仍按 `renderDoc`（旧约定，避免合成边端点指向被重排隐藏的节点——虽然同投影下不该发生）；
   - 工具栏新增「证据强度」按钮（MedalOutline 图标、primary 当开）；切到 tier 模式自动
     `clearFocus()`（路径条跨带位移不连贯）；状态栏显示「视角：证据强度」+ 三带计数胶囊；
   - Tier 3 节点 opacity 0.55（半透后退），仅在 tier 视角下生效；流程视角下仍走 stale 检查；
   - 视角偏好写入既有 `canvas-view:<caseId>:<clueId>`（新增 `perspective` 字段）；
   - 跨 tier 边自然跨越带间隙，可视作「证据链跨越证据强度」——天然引导用户追问
     「这条链下端是不是 Tier 3 推测、能不能换成 Tier 1 证据」。

**注意事项**

- `autoFit` 移除后，节点数极多（完整视图展开全部数据行）时初始缩放会被 clamp 到 0.7，
  此时内容超出视口 —— 需要靠拖拽/滚轮浏览，状态栏要显式提示"内容超出视口，点适应屏幕"。
- 所有色值仍走 `design/tokens.ts`（FE-D-011 纪律），组件内不得硬编码。
