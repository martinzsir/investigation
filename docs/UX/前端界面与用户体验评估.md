# 前端界面与用户体验评估

> 评估对象：`frontend/src`（Vue 3 + Naive UI + TypeScript，34 个页面 / 53 个组件）
> 评估方式：静态代码走查 + 设计系统核对（未运行界面）
> 日期：2026-09-15

---

## 零、结论摘要

**底子很厚，界面很薄。**

项目有一套成熟度远超同类内部系统的设计系统，也有明确的 UX 红线意识，
但这两样东西**没有传导到页面层**。同一个错误在三个地方以不同形态复发。

| 层次 | 评分 | 一句话 |
|---|---|---|
| 设计系统 `design/tokens.ts` | ★★★★★ | 单一事实源、语义色三档独立、色板分区不串台 |
| 通用组件 `components/common/` | ★★★★☆ | EmptyState 三态红线写进注释并开始执行 |
| 页面实现 `views/*.vue`（34 个） | ★★☆☆☆ | 三态各写各的，危险操作确认标准三套 |
| 真伪交互 | ★★☆☆☆ | 全局搜索框是死的，映射页跑演示数据 |
| 信息架构 | ★★★☆☆ | 分组合理，但导航断裂、无面包屑 |
| 无障碍 | ★☆☆☆☆ | 全 `views/` 目录 0 处 `aria-label` |

**最该先修的两条不是视觉问题，是会误导侦查结论的问题**（见 P0-1 / P0-2）。

## 一、做得好，必须保留

### 1.1 设计系统是真材料一

`frontend/src/design/tokens.ts` 注释明写"组件内不得出现硬编码色值，一律经 CSS 变量或 Token 消费"，
实测遵守度良好。几个专业做法：

- **语义色三档独立**（FE-D-008）：`ok/warn/error/info` 各有 `bg`/`border`/`text` 三个值，
  明令"徽章/边框/文字不得共用一个色值"——这正是业余设计系统最容易犯的错（一个色值通吃导致深色底上文字发灰）。
- **色板分区防串台**（FE-D-007）：五间色板"仅用于横条/雷达/热力图，不进状态标签"。
  业务语义色与状态语义色隔离，避免"资金=黄色"和"警告=黄色"混淆。
- **对比度有实测修正**：`canvasTokens.edgeSystem` 注释写明"旧 #4a6b82 在 #051522 上对比度过低"并已调整。
- **受控终态不靠颜色单打**：`FILED_STATUS_META`（已立案金橙）明写"靠锁图标 + 法定依据文字区分"，
  是真正的无障碍思维，不是补票。
- **状态色调声明驱动**：`STATUS_TONE_META` 由 `states.json` 的 `tone` 消费，与后端本体打通。

### 1.2 EmptyState 的三态红线

`EmptyState.vue` 区分 `empty` / `forbidden` / `error`，注释写明：
"无权限态不得伪装成空态（防资源存在性推断）"。

在涉密系统里这条至关重要——如果"无权限查看"和"确实没有"长得一样，
用户就能通过界面差异反推资源是否存在。**这是安全设计，不只是 UX 设计。**

### 1.3 声明驱动与 fail-closed

- `SettingsView.vue:225` 非 admin 直接渲染 `forbidden` 态且**不渲染任何管理数值**，
  fail-closed 而非靠 403 探测。
- `QualityView.vue:100` / `KnowledgeView.vue:155` 的 disabled 按钮自带原因文案
  「🔒 触发检查需偏将及以上」——**解释了为什么不能点**，比灰掉强得多。
- `MiaoSuanView.vue:110` 无权内间线索灰显，只露 id + 原因，不泄露内容。
- `GenericConfigView.vue:321` 发布前强制勾选"已逐条核对影响面"，影响面 failed 时禁止发布。

### 1.4 健康度不做"报喜鸟"

`DashboardView.vue:171` 注释："零记录/降级均为 warn 语义，不显示「一切正常」"。
空态文案还区分"零命中"与"无线索"两种语义。
在侦查场景里，虚假的安全感比明确的警告危险得多。

## 二、P0：会误导侦查结论的两条

### P0-1　质量页加载失败被伪装成"尚未运行质量检查"

`QualityView.vue:37-49` 的 `load()` 失败时只弹 toast，`report` 保持 `null`，
于是 `available === false`，模板落到 107 行的空态：

> 「尚未运行质量检查 / 点击「运行四扫描」……」

**用户看到的是"我还没跑过"，实际是"接口挂了"。**
侦查人员可能据此认为质量检查非必做而继续推进，或反复点击运行。

这正是项目自己在 `EmptyState.vue` 明令禁止的语义混淆——
只是那条红线只管住了"无权限 vs 空"，没管住"加载失败 vs 空"。

**修复**：`load()` 失败时置 `errorMsg`，模板优先渲染 `type="error"` 态 + 重试按钮
（`DashboardView.vue:161-168` 已是正确范本，直接照抄）。

---

### P0-2　权限与遮蔽策略删除零确认

`PolicyMaskingView.vue:341`：

```html
<NButton size="tiny" quaternary type="error" @click="removeLinkPolicy(i)">删除</NButton>
```

点击即删，无二次确认。同页面保存却走 `ConfigConfirmDialog` 要求填变更理由。

权限策略（谁可见哪些对象/属性）是本系统最敏感的配置之一，
**手滑一次就能让一批敏感字段失去遮蔽**。

同类问题：`ActionsView.vue:117`、`StatesView.vue:93` 删除动作/状态同样零确认，
而 `DataElementsView.vue:278` 走确认弹窗并列引用告警。
**同一类"删除"操作，三个页面三套标准。**

**修复**：删除类操作统一走确认；涉及权限/遮蔽的额外要求填理由（与保存同口径）。

## 四、P2：一致性与状态缺失

### 4.1 三态实现五花八门

| 页面 | 空态做法 | 问题 |
|---|---|---|
| `DataElementsView.vue:373` vs `:378` | 同页一处裸 `div.empty-hint`，一处 `EmptyState` | 一页两种空态 |
| `FunctionsView.vue:92` | 自建 `.fn-error` / `.fn-empty` | 丢掉 forbidden 语义 |
| `KnowledgeView.vue:145` | 只有 NSpin，无 error 态；空态用 `<td colspan>` 裸文本 | 失败后看到空表 |
| `GenericConfigView.vue:213` | NAlert 且无重试 | 失败即死页 |

**根因**：`EmptyState` 是可选组件而非强制约定，页面作者各自发挥。

### 4.2 分页是否可分享不一致

`ClueListView.vue:48,68,90` 同步 `?page=` 到 URL（刷新保持、可分享）；
`TaskCenterView.vue:356` 用本地状态（刷新回第一页）。
同为列表页，行为不同。

### 4.3 任务入队的出口不一致

`IngestView.vue:827` 入队后给"前往任务中心"按钮；
`QualityView.vue:59` 只 toast 一句"可在任务中心查看进度"。
一个带出口，一个让用户自己找。

### 4.4 危险确认两套控件

`ConfigConfirmDialog` 被 9 个页面使用（配置类）；
`PortalView` / `OntologyModelerView` / `GenericConfigView` 自建 NModal 确认。

## 五、信息架构

### 5.1 分组本身是对的

6 组 26 项（研判中心 / 数据接入 / 数据治理 / 研判模型 / 治理审计 / 高级工具），
按业务阶段分组。**本体管理器做成独立 App 不入侧栏（R1）的决策正确**——
配置态不该混进办案态导航。

### 5.2 但导航是单向的

- 全 `views/` 无 `NBreadcrumb`
- `GraphView.vue:59` 点节点下钻即 `router.push` 离开图谱，**无返回、无面包屑**，节点上限等参数全部丢失
- `DashboardView:142` / `BoardView:114` / `MiaoSuanView:44` 都跳 `/c/clue/:id`，
  而详情页只回"线索列表"——**从看板点进去，回来筛选条件全丢**
- 仅 `ClueDetailView.vue:385` 有"返回列表"

**典型场景**：侦查员在看板按状态筛选 → 点开线索 → 返回 → 筛选没了，重新筛。一天重复几十次。

**修复**：详情页返回带上来源（`router.back()` 或 query 携带 `from`），图谱下钻用抽屉而非跳页。

### 5.3 Dashboard 指标行列数硬编码

`DashboardView.vue:298` `grid-template-columns: repeat(6, 1fr)`，
但卡片数是动态的（1 固定 + N 个 `states` 声明状态 + 1 严重诊断）。
`states` 数量由本体声明决定，**声明 6 个状态就变成 8 张卡，第六列后换行**。

## 六、无障碍

**全 `views/` 目录 0 处 `aria-label`**（全项目仅 5 个 `components/research/` 文件有）。

主要硬伤：
- 可点击行 `<tr @click>` 无 `tabindex`/`role`/`keydown`（`DataTable.vue:80`、`DashboardView.vue:237`、`ProfileView.vue:281`）
- `IngestView.vue:552` 上传主入口 `<div @click="pickFile">` 键盘不可达
- 图标按钮仅 `title` 无 `aria-label`（`OntologyModelerView.vue:904,1060`、Header 四个图标按钮）
- `EscapeHatchView.vue:143` `<button>` 无 `type`、无 `aria-selected`，同类控件两种写法

> 内网专业系统对无障碍的法定要求通常不高，但**键盘可达性**直接影响高强度办案效率
> （侦查员大量使用键盘），建议至少补齐这一项。

## 九、实施记录（2026-09-15）

按上表优先级逐项落地，改动 17 个文件。以下记录关键决策与未做完的部分。

### 9.1 P0-1 QualityView 失败态

`QualityView.vue`：新增 `errorMsg`，`load()` 失败时置位并清空 `report`，
模板 error 态优先于 empty 态 + 重试按钮。范本取自 `DashboardView.vue:161-168`。

### 9.2 P0-2 删除确认

`PolicyMaskingView`（链接策略 / 属性策略）、`ActionsView`（删除动作）、`StatesView`（删除状态）
四处改用 `NPopconfirm`，文案写明"删除在保存后生效"。

> 实施时更正了评估阶段的一处判断：这四处删除改的是内存中的待保存列表，
> **保存才落盘**，并非"点击即永久丢失"。真正的问题是不可撤销地丢失已配置内容、
> 且保存确认弹窗并不逐条列出删除项。故采用轻量气泡确认而非理由必填。

### 9.3 P1-1 全局搜索框（接真实能力，未摘除）

后端无全局检索接口，但 `cluesApi.list` 的 `subject` 参数
（`server/app/clues_view.py:94`）对「线索标题 + detail 全文」做子串匹配——这是真实能力。

于是把搜索接到它上面而非摘除：

- `ClueListView` 新增关键词输入（`?q=`，URL 可分享），空态文案按是否带关键词分支
  （关键词无匹配 ≠ 零命中，处置不同）
- `GlobalHeader` 回车跳转 `/c/clues?q=`
- placeholder 由「搜索案件、线索、人员或证据」改为「搜索线索标题或详情关键词」——
  **只承诺已建成的能力**

### 9.4 P1-2 MappingView

原 4 行硬编码映射改为：初始为空 + 「载入示例映射」按钮 + 载入后常驻警示条，
明示"示例源列名取自通用银行流水表，与本案本体配置无关"。

### 9.5 P1-3 返回来源（部分）

- `ClueDetailView` 新增 `backTo`：读 `?from=`，**校验必须为站内 `/` 开头、
  排除 `//` 与 `\`**（防开放重定向），否则回落 `/c/clues`
- 仪表盘 / 看板 / 庙算 / 线索列表四处跳转均带上 `from`；
  线索列表传 `route.fullPath`，返回时连 `?page=` 与 `?q=` 一起保留
- **未做**：`GraphView` 点节点下钻跳走无返回。该改动要把下钻从跳页改为抽屉，
  涉及画布状态与参数传递，属独立改造，不宜与其他改动混在一起

### 9.6 P2 三态收敛

新建 `composables/useAsyncState.ts`：统一 loading / error / empty，
**强制 error 优先于 empty**，失败即清空数据（避免"旧数据 + 失败提示"混合）。

本次收敛 4 处：`QualityView` / `KnowledgeView` / `FunctionsView` / `GenericConfigView`。

> `useAsyncState` 目前尚未被页面直接引用——上述四处为控制回归风险，
> 采用了最小侵入的就地修复。它作为**后续页面改造与新页面的默认入口**存在，
> 已在文件头写明红线与用法。

`DataElementsView:373` 的 `.empty-hint` 保留：它是左栏列表的行内提示（非主空态），
换 EmptyState 会因 40px 内边距撑坏列表布局，且语义无歧义。

### 9.7 P2 键盘可达性

`DataTable` 改为**仅当外部监听 `row-click` 时才加 `tabindex`/`role`/回车空格**
（不可点的行进 Tab 序列只会制造噪声）；另修 `DashboardView` 线索行、
`ProfileView` 分组行、`IngestView` 上传区，均补 `:focus-visible` 焦点环。

### 9.8 验证情况

`vue-tsc --noEmit -p tsconfig.app.json` 实测：**本次改动的 17 个文件无新增类型错误**。

仓库存在 46 个既有类型错误，均未由本次改动引入，集中在
`canvas-layout-cross.ts`（10）、`OntologyModelerView`（4）、`RuleWorkshopView`（4）、

## 八、一个根因判断

本项目不缺设计能力，也不缺红线意识——PRD 里写满了红线，组件注释里写满了红线。
缺的是**让页面层必须遵守红线的机制**。

三处失守（失败伪装成空态、死搜索框、删除零确认）都不是因为不知道，
而是因为红线停留在"文档 + 注释"层面，没有：

1. **强制路径**：如"所有列表页必须经 `useAsyncState` 组合式函数，统一产出 loading/error/empty 三态"
2. **检查手段**：如 ESLint 规则禁止裸 `v-if="!items.length"` 空态、禁止 `<tr @click>` 无键盘事件

建议优先建 1，用 2 兜底。这比逐页修补更能防止继续劣化。
